# Eidos の使い方

実践的な手引き。CLI、GUI、Steam の起動オプション、ソースからのビルド、そして
概念実証スクリプト。何かおかしいと思ったときにどうするかは
[troubleshooting.ja.md](troubleshooting.md) を参照してください。

## 使う(CLI)

```sh
eidos games                       # ここに入っている対応ゲーム(MO2 の一覧と同じ)
eidos init skyrimse               # MOD 用インスタンスを作る
# ...各 MOD をフォルダのまま <instance>/mods/ へ置く(グローバルインスタンスは
#    ~/.local/share/eidos/skyrimse にある。`eidos init` が自分の場所を表示する)...
eidos install skyrimse mod.7z     # または、落としてきた書庫をインストールする(Simple / FOMOD)
eidos import skyrimse <mo2-profile>  # 既存の MO2 プロファイルの順序 + プラグイン状態を引き継ぐ
eidos sort skyrimse               # プラグインのロード順を LOOT で並べ替える
eidos play skyrimse               # 何がマウントされるかを表示する
eidos play skyrimse -- <command>  # MOD をゲームに重ねた状態で <command> を実行する
```

`eidos tool`、`eidos prereqs`、`eidos nexus`、`eidos nxm`、`eidos export` が
残りを埋めます。引数なしで `eidos` を実行すれば全一覧が出ます。

### インスタンス: グローバルとポータブル

上のコマンドはどれもインスタンスを指しています。`skyrimse` が指すのは
**グローバル**のほう - `~/.local/share/eidos/skyrimse` に集約して置かれ、
Eidos が管理します。もう一方は**ポータブル**。好きな場所(二台目のドライブ、
ゲーム用のパーティション)に置ける自己完結したフォルダで、移動でき、隔離
されていて、MO2 のポータブルインスタンスとまったく同じです。ゲーム ID を取る
コマンドは、どれもポータブルインスタンスのフォルダを同じように受け取ります:

```sh
eidos init skyrimse /mnt/games/EidosSkyrim   # そこにポータブルインスタンスを作る
eidos install /mnt/games/EidosSkyrim mod.7z  # どのコマンドもフォルダを受け取る
eidos play /mnt/games/EidosSkyrim -- %command%
```

フォルダは自分自身を説明します(`eidos-instance.ini` がゲーム名を持つ)。だから
他には何も要りません - そして環境変数の `EIDOS_INSTANCE=<folder>` はゲーム ID を
そのフォルダへ振り向けます。Steam の起動オプションで重宝します。作ったり開いたり
したポータブルインスタンスは `~/.config/Colony/Eidos/instances.ini` に(最近使った
順で)記憶されます。GUI のようこそ画面はそれらを一覧して一クリックで開けるように
し、Steam からの起動は最後に遊んだものに着地し、`nxm://` ハンドラはそこへ
ダウンロードします。知っておく価値のある注意が二つ。ポータブルフォルダを移動しても
残らないのは、古い場所への絶対パスで登録したツールの項目だけです(それは登録し
直してください)。そして共有ランタイムキャッシュ
(`~/.local/share/Colony/Eidos/runtimes/`)は意図的にマシン全体のままです -
78 MB の .NET ホストはインスタンスごとに持つものではありません。

Eidos は自分のファイルを `Colony/Eidos` の下に置きます。Colony 系のどの
プログラムも使う配置です。あなたが選んだもの(設定、Nexus のセッション、
インスタンス一覧、自分で書いたゲームとアドオンの定義)は
`~/.config/Colony/Eidos/`、セッションログは
`~/.local/state/Colony/Eidos/logs/`、Eidos が落としてきたものは
`~/.local/share/Colony/Eidos/`。古い Eidos はこれらを `~/.config/eidos/` と
`~/.local/state/eidos/` に置いていました。更新後の初回起動がそれらを
**コピー**し、ログにそう書きます。古いディレクトリはそのままの姿で残ります -
何も削除しないので、更新の失敗でサインインを失うことはありません - 納得したら
自分で消してください。

あなたの MOD はそこに含まれません。グローバルインスタンスは今も
`~/.local/share/eidos/<game>/` にあり、ポータブルは置いた場所にあります。
それらのパスはインスタンス一覧に、場合によっては Steam の起動オプションにも
書かれているからです。動かせば、Eidos が両端を持っていないリンクが切れます。

一箇所だけはきっぱり拒否されます。**ゲームのインストールフォルダの中**
(MO2 のベテランがつい取る反射)。あの木は Steam のものです - 更新、
「整合性の確認」、アンインストールがそれを書き換えたり消したりして、あなたの
環境ごと持っていきます - そして Eidos はゲームのルートに重ねてマウントするので、
その中のインスタンスは自分のマウント先の内側に座ることになります。ウィザードも
`eidos init` も `eidos play` も断ります。フォルダはゲームの隣に置いてください
(同じドライブの兄弟なら手軽さは変わりません)。

`play` は、プライベートな名前空間の中で、インスタンスの MOD をゲーム自身の
`Data` ディレクトリに重ねてマウントし(bind-stash 経由なので、デーモンは元の
ファイルをそのまま読めます)、そのビュー越しにコマンドを実行します。書き込み
(セーブ、再生成された設定)はインスタンスの `overwrite/` レイヤーに落ちます。
ゲームのインストール先も MOD の元データも一バイトも変わりません。

### 特権の要る手順はない

Eidos は完全に rootless で動きます。プライベートな user + mount 名前空間の中で
マウントするので、setuid のヘルパーもデーモンも要らず、与える権限もありません。

`sudo setcap cap_sys_admin+ep "$(command -v eidos)"` は**任意**で、開くのは
ただ一つ、カーネルの FUSE パススルーだけです。これはゲームを壊すため既定では
無効です(下記)。この capability があると、Eidos は user 名前空間ではなく素の
mount 名前空間を取ります。MOD の展開はどちらでも同じです。


昔の `setcap` の案内が消えた理由 - そして FUSE パススルーが無効で出荷される
理由 - は
[troubleshooting.ja.md](troubleshooting.md#なぜパススルーは既定で無効なのか)
にあります。

## GUI

```sh
cargo run -p eidos-gui
```

Colony の羊皮紙 / バーガンディの見た目で、MO2 風の初回起動ウィザードが動きます。
ようこそ -> インスタンスの種類(ポータブル / グローバル)-> ゲーム -> 名前と
場所 -> 概要 -> 作成 -> メイン画面。ようこそ画面は既知の既存インスタンス
(グローバルもポータブルも、最後に使った順)も一覧して一クリックで開けるように
します - インスタンスの切り替え役も兼ねます - そしてすでにインスタンスがある
フォルダをウィザードに指すと、上から作り直すのではなくそのまま引き継ぎます
(そのフォルダが別のゲームのものなら、きっぱり断ります)。

二ペインのメインウィンドウもできています。プロファイルの選択(切り替え、または
現在のものを複製して新規作成)、絞り込み・選択・並べ替え・セパレータでの
グループ化・カテゴリでの絞り込み・右クリックからの操作ができる MOD 一覧、
そして Data / Plugins / Conflicts / Overwrite / Saves / Downloads /
Diagnostics のタブと、実行対象を選べる Run ボタン。

並べ替えは先頭 / 末尾へ送るだけではありません。MO2 の狙いを定めた移動もここに
あります - 最初に競合する MOD の上へ、最後の下へ、指定した優先度へ、あるいは
セパレータのグループの中へ。どれも共通の移動ヘルパー一つを通るので、行を消して
から挿し直すときに出る off-by-one は五箇所ではなく一箇所にしかありません。

### 列、並べ替え、グループ化

一覧は最初から四列を描き、八列を用意しています。Category、Content、Version、
Author、Installed、Nexus id、Game、Flags。View メニューでチェックを入れて
ください。既定が八列全部でないのは意図的です - 全部の列を出した一覧には名前の
列の余地が残りません。実際に読んでいるのはその列です。

見出しをクリックすればその列で並べ替わります。もう一度で逆順、三度目で
**ロード順**に戻ります。これは聞こえるより重要です。一覧をドラッグできるのは
ロード順のときだけだからです。挿入の隙間は本物の一覧を指しているのに、
並べ替えられた行はまったく別の場所にあります。並べ替えが効いている間は挿入の帯を
描かず、誰も狙っていない場所に落とすのではなくドラッグを断ります - MO2 と同じ
ことを、同じ理由で。View メニューはそう言い、戻る道も出します。

View メニューは一覧全体を**グループ化**もできます。カテゴリ別か、出所別
(Nexus からか、手で入れたか)。グループの見出しはセパレータではありません。
名前を変えたり色を付けたり動かしたりする実体は後ろにありませんし、折りたためて、
折りたたんでも件数は見出しに残ります。並べ替えやグループ化のもとでは、セパレータは
一覧から退きます - セパレータはロード順で後ろに続く行の頭に立つものであり、
どちらもその行を動かしてしまったからです。

### マウスとキーボード

MOD をダブルクリックで Information、Ctrl+ダブルクリックでそのフォルダ、
Shift+ダブルクリックで Nexus のページ。Ctrl+F でカーソルが絞り込み欄に入ります。
文字を打つとその文字で始まる次の MOD へ飛び、もう一度押せば最初のものに留まらず
残りを順に辿ります。どれも、絞り込みや折りたたんだセパレータ・折りたたんだ
グループが隠している行には着地できません - 見えない選択を動かすことこそ、次の
Space が見てもいない MOD を切り替える原因です。

セパレータのメニューの「Collapse others」は、そのグループ以外を全部
折りたたみます。ドラッグ中に折りたたんだグループの上で止まると開くので、
ドラッグをいったんやめずに中へ落とせます - 止まったときだけで、通り過ぎる
だけでは開きません。

### 一覧が MOD について教えること

助言のフラグが二つ。どちらも字形で、ホバーすると説明が出ます。
**No valid game data** は、MOD の一番上にこのゲームが読み込むものらしきものが
何もない、という意味です。フォルダを一階層上げる必要があるのかもしれませんし、
このゲーム向けの MOD ではないのかもしれません。**Another game** は、MOD 自身の
`meta.ini` が別のゲームを指している、という意味です。どちらも何も止めません -
MOD はそのまま展開されます - 行のメニューの「Mark as valid」がどちらも
黙らせます。MO2 自身の `validated=` キーを通すので、片方のマネージャで太鼓判を
押した MOD はもう片方でも静かに現れます。

配置の判定は意図的に甘くしてあります。`Root/` の木も数え、読めないフォルダも
数え、空のフォルダも数えます。五百行の一覧では、警告が間違っているほうが、
警告が出ないより悪いからです。

### 触る前に MOD を控えておく

「Back up this mod」はそのフォルダを `<name>_backup` として脇にコピーします
(次は `_backup2`、以下同様 - 控えが前の控えを置き換えることはありません)。
コピーは**動きません**。MOD ではなく、チェックボックスは何もせず、統合ビューにも
何も足しません。チェックを入れれば同じ MOD の複製二つを重ねて展開することに
なるからです。「Restore this backup over the mod」は二クリックで元に戻します。
今の中身がまず脇へ退けられ、コピーが成功してから初めて捨てられます。

**Data** は統合ビューの本物の木で、一階層ずつ展開します。ノードを開く費用は、
有効な MOD 全部を再帰的に歩くのではなく、そのノードを持つレイヤーごとに
ディレクトリを一回読むだけです。答えを返すのはマウントが供給するのと同じ
レイヤースタックなので、whiteout や隠しファイルも尊重され、このタブがゲームの
見るものと食い違うことはありません。名前で絞り込み、争っているファイルだけに
絞り、Size と Modified の列で何がどこにあるかを片付け、どの行でもファイル
マネージャで Reveal できます。**Plugins** は ESP/ESM/ESL のロード順です
(切り替え、手での並べ替え、あるいは LOOT での並べ替えと、その後のレポートの
閲覧。レポートの助言のリンクはブラウザで開きます)。**Conflicts** はファイル
ごとの勝ち負けを説明します。**Overwrite** はゲームが書いたものを一手で本物の
MOD に変えます。**Saves** は各セーブのヘッダを解析し - キャラクター、レベル、
場所、プレイ時間 - そこに焼き込まれたプラグイン一覧を今のものと突き合わせ、
必要な MOD を有効にするボタンを添えます。名前を挙げて後はご自由に、では退屈な
ほうの半分だからです。

「Information...」は MOD ごとのダイアログを開きます。general、conflicts、
filetree、INI tweaks、notes。filetree から(そして Data の木から)どのファイルも
**隠せます** - `<name>.mohidden` に改名され、削除せずに仮想ビューから外れるので、
ある MOD の迷子のメッシュ三つを、優先度に触らずに黙らせられます。filetree は
普通のファイル操作もします。新規フォルダ、改名、削除、開く。どれも一つの
リゾルバを通り、その MOD の中の素直なパスでないものはすべて拒否します - `..` も、
絶対パスも、シンボリックリンクである構成要素も。辿ってしまえば削除が MOD
フォルダの外に出てしまうからです。改名は最後の構成要素だけを置き換えるので、
移動になることは決してありませんし、すでに使われている名前は、黙ってその
ファイルを置き換えるのではなく拒否します。削除は二クリック。ここで唯一、
もう一度クリックしても取り消せない操作です。

filetree でも Data の木でも、行の **View** はそのファイルをプレビューします。
画像とテキスト。DDS や NIF は違います - あれにはこの木が持たないブロック
デコーダとレンダラが要ります - が、空の枠を見せる代わりにそう言い、Reveal を
指します。テキストは 64 KB まで読み、どこで止めたかを言います。プレビューは
一瞥であり、Papyrus のログは百メガバイトになりうるからです。**INI Tweaks** は
MOD が `INI Tweaks/` フォルダで配っている断片を一覧します。有効なものは起動時に
優先度順でプロファイルのゲーム INI へ統合され、その回の INI を取り込むときに
外されます - さもないと tweak が黙って設定そのものになり、無効にしても何も
起きなくなります。

ダウンロードは **Downloads の一覧から MOD 一覧の位置へドラッグ**すれば、その
優先度でインストールできます。ファイルマネージャからウィンドウへ落とした書庫や
フォルダもインストールされます(そちらは X11 か XWayland のセッションが要り
ます - winit がファイルのドロップを実装しているのは X11 だけです)。ダウンロード
自体も一時停止と再開ができます。一時停止は転送を止めて途中のファイルを残し、
Resume は新しいリンクを取り直して止まったところから続けます。

Downloads タブは転送の待ち行列ではなく、書庫の**書棚**です。名前で絞り込み
(親しみやすい MOD 名でも通るので、「skyui」で `SkyUI_5_2_SE-12604-5-2SE.7z` が
見つかります)、新しい順・名前・サイズ・状態で並べ替え、用の済んだ書庫は
**隠せます** - ファイルは残して行だけを落とすので、本をしまうことは燃やすこと
ではありません。「Show hidden」で戻り、同じボタンで隠しを解きます。
「Remove N installed」は、すでにインストールした MOD の書庫を二クリックで
削除します。消えるのは**画面に出ているもの**だけ。どれのことかは、絞り込みで
言ったのですから。

### Nexus のコレクション

コレクションのリンクを貼るか、サイト上でクリックすると、Eidos はそのリビジョンの
構成要素を一覧し、それぞれをこのインスタンスと突き合わせます。インストール済み、
ダウンロード済み、未取得。コレクションを**読む**のであって、インストールは
しません。ペインもそう言います。ここでインストーラを、単に難しいというより
不誠実にしてしまうものが四つあります。構成要素はごく普通の Nexus のファイルで、
サイト自身のボタンの外でファイルごとの鍵を作れるのはプレミアム会員だけです。
完全なインストールは構成要素ごとに API 呼び出し三回で、このクライアントが使い
過ぎを拒む予算に当たります。マニフェストのフェーズ、ルール、再生される FOMOD の
回答は、実際に公開された Bethesda 向けのコレクションで検証できませんでした。
そして当て推量は、正しそうに見えて正しくないロード順を生みます。読むだけなら
リクエスト一回で、しかも正確です。

コレクションを読めるのは**そのコレクション自身のゲーム**に対してだけです。
Fallout 4 のインスタンスを開いた状態で Skyrim のコレクションを開くと、間違った
MOD 一覧と突き合わせる代わりに名前を挙げて断ります。そこでの「インストール
済み」も「未取得」も、答えの形をした雑音でしかないからです。

### オフラインモード

**Settings -> Nexus -> Offline** は Eidos が Nexus に接続すること自体をやめさせ
ます。更新確認、サインイン、ダウンロード、コレクションは、接続エラーで失敗する
代わりにそう言います。自分で入れない限り無効です - 古い Eidos が書いた設定
ファイルにはこのキーがなく、無いものを「有効」と読めば、更新した人全員の
ネットワークを切ってしまいます。

**Preferred servers** はダウンロードが好む CDN のノードに順位を付けます。良い
ものから先に。選べる複数のミラーが渡されるのはプレミアム会員だけなので、それ
以外の人には Nexus が選び、この設定は何も変えません。これは並び順であって、
絞り込みではありません。挙げたノードが今日どれも出てこなくても、ダウンロードは
Nexus が最初に出したノードから行われます。

**Categories** は表示するだけでなく編集できます。MOD 一つにも選択全体にも
割り当て、同じダイアログからカタログ自体を編集し、ゲームの公式カテゴリ一覧を
Nexus から取ってこられます。カタログのファイルはどちらも MO2 のもの
(`categories.dat` と `nexuscatmap.dat`)なので、共有したインスタンスは
カタログを一つに保ちます。

**View -> INI editor** はプロファイルのゲーム INI を編集します - 起動のたびに
上書きされる Proton プレフィックスの奥のものではなく、残るほうの写しです。
**View -> Log** はセッションログを読みます。**View -> Extensions** は自分の
アドオンを一覧します。[extensions.ja.md](extensions.md) を参照。

インストールは何でも受け付けます。Simple と FOMOD の経路に加え、Wrye Bash の
**BAIN** パッケージ(サブパッケージにチェックを入れると順に統合されます)、
そしてどの推測も配置を認識できないときに書庫の木を見せてデータのルートを指させる
**手動**の選択画面。断られる書庫はありません。

**Diagnostics** は生きた健全性チェックを走らせます。何より起動できるかどうか、
欠けたマスター(最も当たるクラッシュの予兆)、有効なプラグインがどれも読み込ま
ない書庫、MOD 一覧が今も mods フォルダと一致しているか、そして実行後には -
スクリプトエクステンダ自身のログが各プラグイン DLL について何と言っているか。
「SKSE のプラグインは読み込まれたのか?」が推測から証拠に変わります。

GUI からゲームを起動するには、そのゲームの Steam 起動オプションに実行ファイルの
絶対パスを設定してください(Steam は PATH の `~/.cargo/bin` を見ません):

```
~/.cargo/bin/eidos-gui %command%
```

Eidos はそのゲームのインスタンスで開きます - 最後に使ったものなので、ポータブル
インスタンスもグローバルと同じように見つかります。Run を押せば統合ビュー越しに
起動します。(Steam の外で Run を押すと、この行そのものが、動いている実行
ファイルの実際のパス入りで表示されます。)

Bethesda のタイトルでは、Steam の `%command%` はたいてい `<Game>Launcher.exe` を
指しています。Eidos はそれを実行しません。あのランチャーは `Data` を再走査して
`plugins.txt` を書き直す別の設定アプリで、たった今展開したロード順を台無しに
します。スクリプトエクステンダのローダーが入っていればそれに、なければゲームの
実行ファイルに差し替え、後者へ落ちるときはそう言います - SKSE の MOD が全部
死んだまま起動するゲームは、起動しないゲームより悪いからです。

ここの古い案内は `WINEDLLOVERRIDES="d3dcompiler_47=n"` を強いていました。もう
要りませんし、そもそも正確でもありませんでした。*native* への上書きが効くのは、
本物の `d3dcompiler_47.dll` がすでにプレフィックスにある場合だけです。今の Eidos
は有効な MOD の DLL の import を走査し、本物の Microsoft の DLL 自体を配置し、
そのうえで初めて上書きを設定します。

## 概念実証を試す

ゲームは要りません。user 名前空間の非特権 OverlayFS だけで、union +
copy-on-write + 無改変 + 名前空間ごとのスコープを実証します(Linux >= 5.11):

```sh
./scripts/poc-overlay.sh
```

## ツール

xEdit、BodySlide、DynDOLOD といった面々は、ゲームの Proton プレフィックスの中で
統合ビュー越しに動きます:

```sh
eidos tool skyrimse add BodySlide "<path>/CalienteTools/BodySlide/BodySlide.exe"
eidos tool skyrimse run BodySlide
eidos prereqs skyrimse            # 登録したツールが必要とするものと、その状態
eidos prereqs skyrimse --install  # 足りないものを取ってくる
```

ツールに名前を付ける前に一つ。**その名前が、Eidos がどのランタイム DLL を用意
するかを決めます** - `BodySlide` なら DirectX のライブラリが付き、`BS` には何も
付きません。GUI では Executables のダイアログが、前提条件それぞれの実際の状態を
欄の下に表示し、足りないものはボタンになっています。

一覧表、前提条件の三段階、DynDOLOD が winetricks では入れられない .NET
ランタイムを要る理由、そして MOD として入れたツールが自分のフォルダではなく統合
されたパスから起動される理由は [tools.ja.md](tools.md) にあります。

ソースからのビルドとリポジトリの構成は
[../internals/contributing.md](../../../../internals/contributing.md) にあります。

## 拡張

Eidos は作り直さずに拡張できます。`~/.config/Colony/Eidos/addons/` に置いた
TOML のマニフェストが、Extensions の一覧にツールを、Health タブにチェックを
足します。Eidos の中に何かが読み込まれるわけではありません - 拡張は Eidos が
実行するプログラムです。[extensions.ja.md](extensions.md) を参照。
