# Розширення

Розширення додає до Eidos запис, не будучи частиною Eidos. Це TOML-маніфест, який
називає програму, плюс, щонайбільше, сама ця програма.

Маніфести живуть у `~/.config/Colony/Eidos/addons/`, по одному `.toml` на
розширення. Відкрийте теку через View -> Extensions -> Open folder, потім
натисніть Reload - без перезапуску.

`id`, `kind` і `exec` обов'язкові; `name` за замовчуванням дорівнює id. `exec`
називає програму. Назва без `/` шукається в `PATH`. Коли програми немає, Eidos
пропускає розширення, а його рядок у View -> Extensions пояснює причину
(`<exec> is not on PATH` або `<exec> is not there`). `games` обмежує розширення
вказаними ідентифікаторами ігор; без нього розширення діє для кожної гри, а в
іншій грі його рядок каже «not for this game».

Маніфест, який Eidos відхиляє, показується першим, із причиною: файл, який не
вдалося прочитати, некоректний TOML або бракує обов'язкового поля, порожній `id`
чи `id` із пробілом, порожній `exec`, `id`, який уже зайняв раніший маніфест
(файли читаються в порядку імен), `kind`, якого Eidos не знає, або вид інсталятора,
перегляду чи відомостей про збереження без `protocol = 1` і імені файлу
`extensions`.

## Чому в Eidos нічого не завантажується

Mod Organizer 2 завантажує додатки як спільні бібліотеки, а написані на Python
розміщує через Qt. Ані те, ані інше сюди не переноситься. Rust не має стабільного
ABI, тож спільна бібліотека, зібрана іншим компілятором - чи з іншим прапорцем
оптимізації, чи з іншим набором можливостей спільної залежності - це невизначена
поведінка, і ніщо не повідомляє про неї як про розбіжність версій. До того ж
віджети Eidos є узагальненими на етапі компіляції, тому бібліотека не змогла б
побудувати віджет для повернення, навіть якби ABI був стабільним.

Розширення - це програма, яку Eidos запускає з правами доступу вашого облікового
запису до файлової системи. Установлюйте лише допоміжні програми, яким довіряєте.
Ізоляція процесів і перевірка відповідей не забезпечують пісочниці операційної
системи.

## Інструмент

```toml
id = "wrye-bash"
name = "Wrye Bash"
kind = "tool"
exec = "/opt/wrye/wrye-bash"
args = ["--data", "{data}"]
games = ["skyrimse"]        # опустіть, щоб для всіх ігор
description = "Bashed patch builder."
author = "you"
version = "1.0"
```

Він з'являється у View -> Extensions з кнопкою Run і стартує відокремлено - Eidos
на нього не чекає, а рядок стану показує його pid. Його вивід відкидається. Без
`workdir` він стартує в теці, з якої запущено сам Eidos.

## Перевірка

```toml
id = "esl-count"
name = "ESL budget"
kind = "diagnose"
exec = "/home/me/bin/esl-count.sh"
args = ["{profile_dir}/plugins.txt"]
```

Вона виконується під час кожного оновлення, у корені екземпляра, якщо `workdir` не
каже іншого, і друкує по одному висновку на рядок:

```
level<TAB>title<TAB>detail
```

де `level` - це `problem`, `advice` або `ok`. Деталь необов'язкова; рядок без
title відкидається. Усе, що не починається з відомого рівня, ігнорується, тож
вивід поступу й випадкові попередження не здатні підняти рядок, схожий на власну
перевірку Eidos. Висновки з'являються у вкладці Diagnostics як `<name> - <title>`,
після карток префікса та Nexus і перед іншими Health-картками.

Перевірці дається три секунди. Та, що перевищить час, зупиняється й повідомляється
як проблема проти самої себе - вона виконується на тому самому оновленні, що йде
за кожним клацанням, тож зависла заморозила б вікно. Годинник іде, доки
перевірка не завершиться і її канали виводу не закриються, тож фоновий дочірній
процес, який їх ще тримає, зараховується в ці три секунди. Перевірка, що
завершується з помилкою й нічого не друкує, повідомляється так само, з першим
рядком її виводу помилок, як і та, що друкує понад 1 MiB в одному з потоків. В
обох випадках Eidos не запускає її знову, доки ви не натиснете Reload, а її рядок
каже «It will not be retried until you press Reload.» Перевірка нічого не читає зі
свого стандартного входу.

## Підстановки

І `args`, і `workdir` розгортають такі:

| Підстановка     | Що це                                        |
| --------------- | -------------------------------------------- |
| `{instance}`    | корінь екземпляра                            |
| `{mods}`        | `<instance>/mods`                            |
| `{downloads}`   | `<instance>/downloads`                       |
| `{overwrite}`   | `<instance>/overwrite`                       |
| `{profile}`     | назва активного профілю                      |
| `{profile_dir}` | тека активного профілю                       |
| `{game}`        | ідентифікатор гри, напр. `skyrimse`          |
| `{game_name}`   | відображувана назва гри                      |
| `{install}`     | тека гри, з якої працює екземпляр            |
| `{data}`        | тека `Data` цієї теки                        |

`{install}` - це інсталяція з магазину або копія гри, коли екземпляр працює з
копії (заморожений `Stock Game` чи власна тека гри зі списку; див.
[usage.md](usage.md#файли-гри-встановлення-з-магазину-або-копія)). `{data}` іде за
нею.

Перевірка отримує також `{addon_dir}`, теку, де лежить її маніфест, так само як і
розширення протоколу 1 нижче. Інструмент її не отримує.

Невідома підстановка ніколи не спорожнюється, бо це перетворило б `--out {typo}`
на `--out --next-flag`. Eidos відмовляється запускати інструмент чи перевірку, чиї
підстановки не всі розв'язуються, і каже, яких бракує: у рядку стану для
інструмента, у рядку перевірки у вкладці Diagnostics для перевірки.

## Чого розширення не може

Розширення не може робити зворотні виклики до Eidos, реєструвати себе з архіву чи малювати власні віджети. Структуровані інсталятори протоколу 1 можуть повертати перевірені плани файлів і запитання з вибором; перевірку, підготовку в тимчасовому каталозі та публікацію контролює Eidos. FOMOD і BAIN залишаються нативними інсталяторами. Розширення перегляду та відомостей про збереження використовують той самий хост з обмеженнями на відповіді. Пріоритет зіставлення, записані відповіді CLI, обмеження та перевірки ідентичності під час повторного виконання описано у [специфікації протоколу й виконуваних прикладах](../../../../guide/examples/extensions/README.md).
