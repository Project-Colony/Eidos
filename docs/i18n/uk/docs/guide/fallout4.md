# Fallout 4 крізь Eidos

Fallout 4 не потребує ані особливого параметра запуску, ані перейменованого
виконуваного файлу, ані скрипта-обгортки. Це варто сказати прямо, бо всі інші
посібники з F4SE під Linux стверджують протилежне - і їхні поради ламаються на
наступному оновленні Steam.

## Параметр запуску

```
~/.local/bin/eidos-gui %command%
```

Ціль запуску Steam для Fallout 4 - це `Fallout4Launcher.exe`, ніколи не
`Fallout4.exe`, тож змусити script extender узагалі запуститися - насправді питання
«як змусити Steam стартувати іншу програму». Звичні відповіді переписують
`%command%` на bash:

```
bash -c 'exec "${@/Fallout4Launcher.exe/f4se_loader.exe}"' -- %command%
```

або копіюють `f4se_loader.exe` поверх `Fallout4Launcher.exe`, який Steam тихо
відновлює під час кожного оновлення гри - після чого ви граєте без F4SE, і ніщо про
це не повідомляє.

Eidos виконує підміну сам, спираючись на описувач гри: він замінює лаунчер на
`f4se_loader.exe`, коли той встановлений, відкочується на `Fallout4.exe`, коли його
немає, і **каже вам**, коли довелося відкотитися. Гра, що стартує з усіма модами
F4SE мертвими, гірша за гру, яка не стартує.

Є й друга причина ніколи не запускати лаунчер: він перескановує `Data` і переписує
`plugins.txt`, скасовуючи щойно розгорнутий порядок завантаження. Eidos його ніколи
не виконує.

## Що Eidos бере на себе

| | |
|---|---|
| Знеціннення архівів | До `Fallout4Custom.ini` потрапляють `[Archive]` `bInvalidateOlderFiles=1` та порожній `sResourceDataDirsFinal=` - два ключі, без яких вільні файли поза `Data` взагалі не видно. Пишеться у профіль, а не в теку гри. |
| Порядок завантаження | `plugins.txt` у форматі із зірочками, який використовує Fallout 4 (`*` позначає активний), з урахуванням `Fallout4.ccc` для неявних додатків Creation Club |
| LOOT | Сортування працює так само, як для Skyrim - `eidos sort <instance>` бере masterlist `fallout4` |
| Збереження | Збереження `.fos` та їхні косейви `.f4se` перелічуються, копіюються і зберігаються за профілями; панель подробиць читає власну таблицю додатків збереження, тож збереження, якому потрібен вимкнений вами додаток, скаже про це до завантаження |
| Root-моди | Усе, що мод кладе поруч із виконуваним файлом (сам F4SE, ENB, `dxvk.conf`), потрапляє туди тим самим механізмом `Root/`, що й у Skyrim |

## Питання версій

Fallout 4 більше не та заморожена гра, якою була з 2019 до 2024 року. Станом на
серпень 2026 живих гілок три, і DLL мода, зібрана під одну, не завантажиться в
іншій:

| Гілка | Версія | F4SE |
|---|---|---|
| Класична («old-gen») | 1.10.163 | 0.6.23 |
| Next-gen | 1.10.984 | 0.7.2 |
| Anniversary / Creations | 1.11.137 → 1.11.240 | 0.7.4 → 0.7.9 |

Два наслідки, які варто знати перед складанням списку модів:

- **Перевірте, що у вас насправді.** Теки `Creations/` і `Mods/` у корені гри
  означають лінію 1.11.x. Панель подробиць збереження в Eidos також показує збірку,
  якою його записано - Fallout вписує це у збереження, а Eidos виводить як
  «Game build».
- **Свіжий патч - поганий день для початку.** F4SE зазвичай виходить за день-два
  після оновлення Bethesda, але *Address Library for F4SE Plugins* - через яку
  більшість DLL-модів розв'язують свої зсуви - має власний розклад. Між ними
  DLL-половина екосистеми лежить. Моди без DLL (текстури, меші, додатки) не зачеплені.

Щойно ваша збірка запрацює, вимкніть автоматичні оновлення Steam для Fallout 4
(Властивості → Оновлення → «Оновлювати цю гру лише під час запуску»), інакше
наступний патч зламає кожну встановлену DLL.

## Апаратна заувага: вильоти на уламках зброї в NVIDIA

Ефект уламків зброї у Fallout 4 працює на NVIDIA FleX, похідній PhysX, підтримку
якої NVIDIA припинила після покоління Pascal. На будь-якій карті Turing і новішій -
GTX 16, RTX 20 по RTX 50 - він валить гру. Це вада самої гри, ніяк не пов'язана з
Linux, Proton чи Eidos.

Два виправлення, годиться будь-яке: вимкніть «Weapon Debris» у налаштуваннях гри
або встановіть *Weapon Debris Crash Fix* (Nexus 48078), який вимикає зіткнення
уламків, а не сам ефект.

## Якщо щось виглядає не так

Загальний перелік перевірок - у [troubleshooting.uk.md](troubleshooting.md);
перше суто Fallout-івське питання завжди - *який виконуваний файл насправді
стартував*. Eidos пише повну команду запуску до журналу запусків екземпляра, тож:

```sh
grep '# command:' <instance>/logs/run-*.log | tail -1
```

Якщо там `f4se_loader.exe`, підміна відбулася. Якщо `Fallout4Launcher.exe`, F4SE не
встановлений там, де Eidos може його знайти - його місце поруч із виконуваним
файлом гри, що для збірки під керуванням менеджера модів означає теку `Root/`
якогось мода (або саму теку гри, встановлений вручну).
