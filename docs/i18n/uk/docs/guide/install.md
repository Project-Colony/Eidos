# Встановлення Eidos

Три шляхи. Усі дають `eidos` (командний рядок), `eidos-gui` і допоміжну програму статичного перегляду NIF, а також обробник `nxm://`, завдяки якому кнопка «Mod Manager Download» на Nexus спрямовує завантаження до вашого екземпляра.

## Що потрібно спершу

| | |
|---|---|
| **Linux із FUSE** | `fusermount3` у PATH. Його постачає будь-який сучасний дистрибутив. |
| **Гра під Proton, запущена хоча б раз** | Steam створює Wine-префікс гри лише під час першого запуску, а Eidos працює всередині нього. |
| **`7z`** | Для встановлення архівів модів. У більшості дистрибутивів це `p7zip`. |

Ані root, ані демона, ані редагування `/etc/fuse.conf`, ані додавання до груп.
Eidos монтує у приватному просторі імен, що належить процесові гри.

## Arch

```bash
cd packaging && makepkg -si
```

## Архів випуску

```bash
./install.sh
```

Типово встановлює в `~/.local/bin`. `--system` кладе у `/usr/local/bin`,
`--bindir DIR` - будь-куди. Повторний запуск - передбачений спосіб оновлення.

## З джерельних кодів

```bash
git clone https://github.com/Project-Colony/Eidos && cd Eidos
just build
just install
```

Для збирання з джерельного коду потрібні Rust, `just`, CMake 3.20+, компілятор C++17 і Python 3 для тестів нативної допоміжної програми. Команди без `just` наведено в [інструкціях для нативної допоміжної програми](../../../../../native/eidos-nif-preview/README.md). Зберіть Rust командою `cargo build --release --locked`, скопіюйте допоміжну програму до `target/release`, а потім запустіть `packaging/install.sh --from target/release`.

## Далі: скерувати на нього Steam

Eidos виконується *як* команда запуску вашої гри - саме так він встигає
змонтувати вигляд до її старту. У Steam: правий клац на грі -> Властивості ->
Параметри запуску:

```
~/.local/bin/eidos-gui %command%
```

Натисніть «Грати». Eidos відкриється на екземплярі цієї гри; встановлюйте моди,
сортуйте через LOOT, тисніть Run. Після виходу монтування зникає разом із грою, а
ваша інсталяція лишається точно такою, якою була.

Вказуйте абсолютний шлях - Steam не читає `PATH` вашої оболонки.

### Якщо ви віддаєте перевагу терміналу

```sh
eidos init skyrimse               # створити екземпляр (вкажіть теку, щоб зробити його портативним)
eidos install skyrimse mod.7z     # моди Simple / FOMOD / BAIN / root
eidos sort skyrimse               # відсортувати порядок завантаження через LOOT
eidos play skyrimse -- %command%  # запустити будь-що через об'єднаний вигляд
```

Кожна команда, що приймає ідентифікатор гри, приймає й теку портативного
екземпляра - див. [usage.uk.md](usage.md). Повна екскурсія там само.

## Необов'язково: FUSE passthrough

`sudo setcap cap_sys_admin+ep "$(command -v eidos)"` надає необов’язкову можливість, але не вмикає passthrough.
`EIDOS_FUSE_PASSTHROUGH=1` — окремий перемикач під час запуску. Він **вимкнений типово, і майже напевно так і слід залишити**:
виміряно на Skyrim SE - він заважає грі відкривати власні архіви та додатки, тож
моди мовчки не завантажуються. Перемикач існує, щоб механізм можна було
перевірити знову, а не тому, що він рекомендований.

Подробиці й виміри, що стоять за цим рішенням, у
[troubleshooting.uk.md](troubleshooting.md).
