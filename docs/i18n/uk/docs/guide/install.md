# Встановлення Eidos

Чотири шляхи. Colony встановлює один файл, `eidos-linux`, який і є всією
програмою. Пакет випуску, пакет Arch і збірка з джерельних кодів дають `eidos`
(CLI), `eidos-gui` і статичну допоміжну програму перегляду NIF `eidos-nif-preview`
поруч. Пакет Arch і збірка з джерельних кодів також встановлюють `eidos-fuse` та
`eidos-launch`, два нижчорівневі CLI. Кожен шлях може зареєструвати обробник
`nxm://`, завдяки якому кнопка «Mod Manager Download» на Nexus спрямовує
завантаження до вашого екземпляра.

## Що потрібно спершу

| Вимога | Навіщо |
|---|---|
| Linux із FUSE | `fusermount3` у PATH. Його постачає будь-який сучасний дистрибутив. |
| Гра під Proton, запущена хоча б раз | Steam створює Wine-префікс гри лише під час першого запуску, а Eidos працює всередині нього. Eidos також виявляє копії Skyrim Special Edition з GOG і Epic, копії Fallout 3 і Fallout: New Vegas з Epic та копію Stardew Valley з GOG. Вони запускаються через Heroic або Legendary, де Eidos виступає обгорткою гри: див. [usage.md](usage.md#запуск-гри). |
| Виконуваний файл 7-Zip: `7z`, `7zz` або `7za` | Для встановлення архівів модів. `7zip` в Arch, `p7zip` у більшості інших дистрибутивів. |
| `par2` (необов'язково) | Дані для відновлення PAR2 для резервних копій `eidos pack`. `par2cmdline` в Arch і Fedora, `par2` у Debian і Ubuntu. |

Ані root, ані демона, ані редагування `/etc/fuse.conf`, ані додавання до груп.
Eidos монтує у приватному просторі імен, що належить процесові гри.

Деякі системні налаштування проявляються лише збоями. Вкладка Diagnostics
перевіряє `vm.max_map_count` (1048576 або більше), жорстку межу відкритих файлів
(524288 або більше) і те, чи гра, її префікс або екземпляр лежать на NTFS, exFAT чи
FAT; виправлення для кожного є в
[troubleshooting.md](troubleshooting.md#система).

## Через Colony

Знайдіть **Eidos** у [Colony](https://github.com/Project-Colony/Colony) і
встановіть його; оновлення приходять через лаунчер. Colony тримає один файл,
`~/.local/share/Colony/apps/Eidos/eidos-linux`. Запустіть його, і відкриється
вікно. Викликаний через посилання з назвою `eidos`, той самий файл є командним
рядком. Покладіть таке посилання у свій `PATH` і зареєструйте обробник
завантажень Nexus:

```bash
mkdir -p ~/.local/bin
ln -s ~/.local/share/Colony/apps/Eidos/eidos-linux ~/.local/bin/eidos
eidos nxm --register    # the site's Mod Manager Download button now reaches Eidos
```

Вікну посилання не потрібне: щоразу, коли воно запускає гру чи інструмент, воно
виконує власний файл як CLI. Попередньому перегляду моделей NIF потрібен
`eidos-nif-preview`, який є лише в пакеті випуску, пакеті Arch та збірках із
джерельних кодів; без нього перегляд про це повідомляє, і більше ніщо не зачеплено.
`eidos-linux` не містить і жодного з Microsoft-середовищ виконання, які постачає
пакет ([нижче](#середовища-виконання-microsoft-у-пакеті)): коли інструменту
потрібне одне з них, Eidos завантажує його з Microsoft, щойно ви запустите
встановлення передумов. Скеруйте Steam на сам файл, як описано нижче.

## Пакет випуску

Завантажте `eidos-linux-bundle.tar.gz` і його `.sig`, `.meta` та `.meta.sig`
з [останнього випуску](https://github.com/Project-Colony/Eidos/releases/latest)
і перевірте їх, як показує
[Політика підписування коду](../../README.md#політика-підписування-коду) в README.
У пакеті на верхньому рівні лежать `eidos`, `eidos-gui` і `eidos-nif-preview`, а
також `install.sh`, `README.md`, `LICENSE`, `SECURITY.md`, іконки в
`assets/brand/png`, повідомлення сторонніх компонентів у `licenses/` (nifly, omod,
microsoft-directx, microsoft-runtimes і крейти Rust) та тека `runtimes/`, описана
нижче. `eidos-fuse` і `eidos-launch` у ньому немає. Потім:

```bash
tar xzf eidos-linux-bundle.tar.gz
cd eidos-linux-bundle
./install.sh
```

`install.sh` копіює бінарні файли в `~/.local/bin` або в `$XDG_BIN_HOME`, якщо
його задано. `--system` кладе їх у `/usr/local/bin` через sudo, `--bindir DIR` -
будь-куди, а `--from DIR` бере бінарні файли з іншої теки. Скрипт також:

- реєструє обробник `nxm://`, запускаючи `eidos nxm --register`, тож крок
  реєстрації з розділу про Colony не потрібен;
- пише `~/.local/share/applications/eidos.desktop` та іконки Eidos у
  `~/.local/share/icons/hicolor`;
- копіює ліцензійні повідомлення до `~/.local/share/licenses/eidos`
  (`/usr/local/share/licenses/eidos` з `--system`);
- копіює `runtimes/` до `~/.local/share/Colony/Eidos/runtimes`, так само й з
  `--system`, тож середовища виконання належать користувачеві, який запускає
  скрипт;
- наприкінці друкує параметр запуску Steam з абсолютним шляхом до встановленого
  `eidos-gui`.

`--cap` просить sudo надати `CAP_SYS_ADMIN` встановленому `eidos` (див. FUSE
passthrough нижче). `--no-cap` - типове значення, воно лишає все без root.
Повторний запуск скрипта - передбачений спосіб оновлення. Пакету і `eidos-linux`
потрібен Linux x86_64 з glibc 2.39 або новішою.

### Середовища виконання Microsoft у пакеті

Тека `runtimes/` пакета містить файли Microsoft, які просять інструменти:
`VC_redist.x86.exe` і `VC_redist.x64.exe` (Visual C++ 2015-2022, передумова
`vcrun2022`), `windowsdesktop-runtime-8.0.12-win-x64.exe` (.NET 8 Desktop Runtime,
для `dotnet8` і `dotnetdesktop8`) та `dotnet-runtime-10.0.10-win-x64.zip` (.NET 10
runtime, для `dotnet10`). Eidos сам запускає інсталятори Visual C++ і .NET 8 у
префіксі гри, без winetricks, а zip .NET 10 розпаковує один раз у
`~/.local/share/Colony/Eidos/runtimes`, де ним користуються всі екземпляри (78 МБ
розпакованим). Кожен файл використовується лише тоді, коли його SHA-256 збігається
із зафіксованим в Eidos. .NET 10 SDK, потрібний Synthesis (`dotnetsdk10`, близько
300 МБ), у пакеті відсутній і завжди завантажується.

Розпакований пакет працює і на місці: Eidos шукає `runtimes/` поруч зі своїм
бінарним файлом після згаданої вище теки даних.

## Arch

```bash
cd packaging && makepkg -si
```

PKGBUILD збирає поточний `main` із джерельних кодів. Він встановлює `eidos`,
`eidos-gui`, `eidos-nif-preview`, `eidos-fuse` і `eidos-launch` у `/usr/bin`, із
системним обробником `nxm://`, записом робочого стола та іконками. Він залежить від
`fuse3`, `7zip` і `xdg-utils`. Теки `runtimes/` він не постачає, тож
Microsoft-середовища виконання завантажуються, коли їх потребує інструмент.
`winetricks` необов'язковий: Eidos і далі користується ним для передумов, яких не
встановлює сам, як-от `dotnet48` і `xact`.

## З джерельних кодів

```bash
git clone https://github.com/Project-Colony/Eidos && cd Eidos
just build
just install
```

Для збирання з джерельного коду потрібні Rust 1.92 або новіший, `just`, CMake 3.20+,
компілятор C++17 і Python 3 для тестів нативної допоміжної програми. `just build`
збирає весь workspace, тож `eidos-fuse` і `eidos-launch` теж збираються, а `just
install` запускає `packaging/install.sh` на результаті збирання, який копіює їх
разом з рештою. Команди без `just` наведено в
[інструкціях для нативної допоміжної програми](../../../../../crates/eidos-nif-preview/README.md):
зберіть Rust командою `cargo build --release --locked`, скопіюйте допоміжну
програму до `target/release`, а потім запустіть
`packaging/install.sh --from target/release`. У збірці з джерельних кодів теж немає
теки `runtimes/`, тож Microsoft-середовища виконання завантажуються, коли їх
потребує інструмент.

Профіль release використовує одну кодогенеративну одиницю, fat LTO і вилучені
символи. З rustc 1.99.1 і 3 завданнями збирання холодна збірка `eidos` та
`eidos-gui` тривала 334 с проти 243 с з thin LTO і дала `eidos` на 20,9 МБ та
`eidos-gui` на 49,7 МБ. Кожен бінарний файл вбудовує вісім DLL DirectX, збережених
стиснутими gzip: 7,9 МБ замість 17,9 МБ. `just profile=dev build` збирає без
оптимізації.

## Далі: скерувати на нього Steam

Eidos виконується *як* команда запуску вашої гри - саме так він встигає
змонтувати вигляд до її старту. У Steam: правий клац на грі -> Властивості ->
Параметри запуску, і введіть абсолютний шлях до вікна Eidos, а за ним `%command%`:

```
~/.local/bin/eidos-gui %command%
```

Вказуйте абсолютний шлях - Steam не читає `PATH` вашої оболонки. Шлях залежить від
того, як ви встановили Eidos, а `install.sh` друкує рядок для теки, яку
використав:

| Встановлення | Параметр запуску |
|---|---|
| Пакет випуску або `just install` | `~/.local/bin/eidos-gui %command%` |
| `install.sh --system` | `/usr/local/bin/eidos-gui %command%` |
| Пакет Arch | `/usr/bin/eidos-gui %command%` |
| Colony | `~/.local/share/Colony/apps/Eidos/eidos-linux %command%` |

Натисніть «Грати». Eidos відкриється на екземплярі цієї гри; встановлюйте моди,
сортуйте через LOOT, тисніть Run. Після виходу монтування зникає разом із грою, а
ваша інсталяція лишається точно такою, якою була.

Гра завжди стартує через свій магазин. У вікні, яке ви відкрили самі, Run
виконує `steam -applaunch <appid>`, Steam запускає Eidos через параметр запуску, і
відкривається друге вікно Eidos, де ви натискаєте Run. Доки параметр запуску не
стартує Eidos, Run нічого не запускає, а рядок стану показує рядок, який треба
задати. Якщо ввімкнено Start the game at once when a store opens Eidos
(Preferences, General, Running a game; типово вимкнено), Play у Steam запускає гру
без вікна, коли Health не показує проблем. Heroic і Legendary працюють так само
через налаштування обгортки; подробиці - в
[usage.md](usage.md#запуск-гри).

Вкладка Diagnostics перевіряє цей рядок. Health-картка показує рядок, який треба
задати, коли параметр запуску порожній, не називає бінарного файла Eidos, указує на
неіснуючий файл, не має `%command%` після Eidos або запускає іншу копію Eidos, ніж
та, що працює.

### Якщо ви віддаєте перевагу терміналу

```sh
eidos init skyrimse               # створити екземпляр (вкажіть теку, щоб зробити його портативним)
eidos install skyrimse mod.7z     # моди Simple / FOMOD / BAIN / root
eidos sort skyrimse               # відсортувати порядок завантаження через LOOT
eidos check skyrimse              # Health-перевірки, яким не потрібне вікно
eidos play skyrimse -- %command%  # запустити будь-що через об'єднаний вигляд
eidos shell skyrimse              # оболонка в об'єднаному вигляді, записи потрапляють в Overwrite
```

Кожна команда, що приймає ідентифікатор гри, приймає й теку портативного
екземпляра - див. [usage.md](usage.md#екземпляри-глобальні-та-портативні). Повна
екскурсія в [usage.md](usage.md).

## Оновлення

Colony оновлює `eidos-linux` через свій лаунчер. Для пакета запустіть
`install.sh` нового пакета; для пакета Arch знову виконайте `makepkg -si`; для
збірки з джерельних кодів зробіть pull і запустіть `just install`. Вікно при
старті питає GitHub про останній випуск, щонайбільше раз на добу, і коли виходить
новіший, показує посилання на його нотатки про випуск після Help у рядку меню. Воно
ніколи не завантажує й не замінює себе. Preferences, About, Version вимикає
перевірку, офлайн-режим її пропускає, а копія, встановлена під `/usr` (пакет
Arch), ніколи не питає, бо її оновлює менеджер пакетів.

## Необов'язково: FUSE passthrough

`sudo setcap cap_sys_admin+ep "$(command -v eidos)"` надає необов'язкову
можливість, але не вмикає passthrough. `./install.sh --cap` і `just setcap`
надають її тому `eidos`, який встановлюють або збирають. На монтуванні `nosuid`
ядро ігнорує файлові можливості, тож `install.sh` пропускає надання з
попередженням, а `just setcap` зупиняється з помилкою. Можливість ставиться на
окремий бінарний файл `eidos` з пакета випуску, пакета Arch або зі збірки з
джерельних кодів, ніколи не на `eidos-linux`, який є також і вікном
([SECURITY.md](../../../../../SECURITY.md)). Перезібраний чи перевстановлений
бінарний файл - це новий файл без можливості, тож якщо ви нею користуєтеся, надайте
її знову після кожного оновлення.

`EIDOS_FUSE_PASSTHROUGH=1` - окремий перемикач під час запуску, і типово він
вимкнений. З увімкненим passthrough попередній демон заважав Skyrim SE
завантажувати будь-який вміст модів. Найімовірніша причина в тому, що він
реєстрував новий файл-основу при кожному відкритті, а ядро приймає лише один на
inode. Тепер демон ділить один файл-основу між усіма відкриттями файла через
passthrough, але в грі це ще не виміряно заново. До того вмикайте passthrough лише
для перевірки. Виміри й причина - у [troubleshooting.md](troubleshooting.md).
