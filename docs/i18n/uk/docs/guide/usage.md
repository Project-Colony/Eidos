# Користування Eidos

Як користуватися Eidos: екземпляри та копії гри, командний рядок, тестові
запуски, вікно, колекції й оновлення Nexus, перенесення екземпляра на іншу
машину, інструменти та розширення. Про проблеми - див.
[troubleshooting.md](troubleshooting.md); про збирання з джерельних кодів і
структуру репозиторію - [../internals/contributing.md](../../../../internals/contributing.md).

## Екземпляри: глобальні та портативні

Команди, що приймають екземпляр, приймають ідентифікатор гри або теку портативного
екземпляра. `skyrimse` називає глобальний екземпляр, який Eidos тримає в
`~/.local/share/Colony/Eidos/instances/skyrimse`. Портативний екземпляр - це
самодостатня тека, де забажаєте (другий диск, ігровий розділ), і її можна
переміщувати, як портативні екземпляри MO2:

```sh
eidos init skyrimse /mnt/games/EidosSkyrim   # створити там портативний екземпляр
eidos install /mnt/games/EidosSkyrim mod.7z  # кожна команда приймає теку
eidos play /mnt/games/EidosSkyrim -- %command%
```

`eidos-instance.ini` у теці називає гру, тож більше теці нічого не потрібно.
`EIDOS_INSTANCE=<folder>` у середовищі перенаправляє ідентифікатор гри на цю теку,
наприклад у параметрі запуску Steam. Портативні екземпляри, які ви створили чи
відкрили, запам'ятовуються, найновіші першими, у
`~/.config/Colony/Eidos/instances.ini`: вітальний екран вікна перелічує їх, запуск
зі Steam потрапляє на той, у який ви грали востаннє, а обробник `nxm://`
завантажує в нього.

Ручне переміщення портативної теки зберігає все, окрім записів інструментів, які
ви зареєстрували з абсолютними шляхами у старе розташування. `eidos pack` і
`eidos unpack` ([нижче](#перенесення-екземпляра-на-іншу-машину)) виправляють їх;
звичайний `mv` - ні. Кеш середовищ виконання в
`~/.local/share/Colony/Eidos/runtimes/` спільний для кожного екземпляра на машині,
тож хост .NET на 78 МБ не копіюється в кожен.

Одне місце відхиляється: усередині теки встановлення гри, куди користувачі MO2
часто кладуть свій екземпляр. Цим деревом володіє Steam, і оновлення, «verify
integrity» чи видалення можуть переписати або стерти його разом із вашим
налаштуванням. Eidos також монтує поверх кореня гри, тож екземпляр там опинився б
усередині власної цілі монтування. Майстер, `eidos init`, `eidos play` і
`eidos shell` його відхиляють. Покладіть теку поруч із грою; сусідня тека на тому
самому диску так само зручна.

### Де Eidos зберігає свої файли

Eidos тримає свої файли під `Colony/Eidos`, у розкладці, якою користується кожна
програма сімейства Colony: `~/.config/Colony/Eidos/` - для того, що ви обрали
(налаштування, ваша сесія Nexus, список екземплярів, написані вами визначення ігор
і доповнень), `~/.local/share/Colony/Eidos/` - для глобальних екземплярів
(`instances/`), завантажених середовищ виконання та логів сесій (`logs/`), і
`~/.cache/Colony/Eidos/` - для мастер-списків LOOT, які завантажуються знову,
щойно їх немає.

Коли Eidos знаходить файли в розкладці старішого Eidos (`~/.config/eidos/`,
`~/.local/share/eidos/` і `~/.local/state/`), перший запуск копіює їх і пише про
це в лог. Глобальний екземпляр переноситься жорсткими посиланнями замість
побайтового копіювання, тож його моди не займають додаткового місця, а записи
його інструментів перенаправляються на нову теку. Нічого в старих теках не
змінюється й не видаляється; приберіть їх самі, коли нова розкладка запрацює. Якщо
копію зробити не вдається (повний диск чи диск лише для читання, тека старого
екземпляра на іншому диску, гра, що досі працює з неї), Eidos і далі користується
старим розташуванням і пробує знову під час наступного запуску. Параметр запуску
Steam, що досі називає стару теку екземпляра, відкриває перенесену.

Жорсткі посилання заощаджують місце лише спочатку. Мод або завантаження, які ви
потім видаляєте чи перевстановлюєте, зберігають свою стару копію на диску через
стару теку екземпляра, а видалення `~/.local/share/eidos/<game>/` повертає це
місце.

Портативний екземпляр ніколи не переноситься: він лишається там, де ви його
поклали.

## Командний рядок

```sh
eidos games                                # підтримувані ігри, встановлені тут, як список MO2
eidos init skyrimse [folder]               # створити екземпляр; з текою він портативний
eidos init skyrimse --game-path <folder>   # використати копію, встановлену в <folder>, коли їх встановлено кілька
eidos install skyrimse mod.7z [name]       # встановити архів (Simple, FOMOD, BAIN, OMOD)
eidos install skyrimse mod.7z --replace --backup  # перевстановити поверх мода (--merge встановлює поверх його файлів)
eidos import skyrimse <mo2-profile>        # перейняти порядок модів і стан плагінів профілю MO2
eidos sort skyrimse [--dry-run]            # відсортувати порядок завантаження через LOOT (--update-masterlist спершу оновлює його)
eidos play skyrimse                        # показати, що було б змонтовано
eidos play skyrimse -- <command>           # запустити <command> з модами, змонтованими поверх гри
eidos shell skyrimse                       # оболонка в об'єднаному вигляді; записи потрапляють в Overwrite
eidos check skyrimse [--json]              # Health-перевірки без вікна
eidos sessions skyrimse                    # записані запуски гри та інструментів, спочатку нові
eidos sessions skyrimse diff [<id>]        # що змінилося з останнього запуску, який завершився з кодом 0
eidos stock-game skyrimse                  # які файли гри використовує екземпляр; заморозити копію або перемкнути
eidos tool skyrimse                        # перелічити інструменти (add, rm і run: див. Інструменти нижче)
eidos tool skyrimse run --exe <path>       # запустити exe один раз через об'єднаний вигляд
eidos tool skyrimse import-mo2 [--write]   # виконувані файли з ModOrganizer.ini; --write додає їх
eidos prereqs skyrimse [--install]         # що потрібно інструментам; --install завантажує те, чого бракує
eidos collection skyrimse <link>           # встановити колекцію Nexus (--dry-run, --no-optional)
eidos nexus status                         # перевірити збережений вхід у Nexus
eidos nexus update skyrimse [--apply]      # перевірити оновлення модів; --apply встановлює їх
eidos nxm <link>                           # завантажити посилання Mod Manager Download
eidos nxm --register                       # зробити так, щоб кнопка Mod Manager Download на сайті відкривала Eidos
eidos export skyrimse -o mods.csv --active # формат CSV від MO2; --active перелічує лише увімкнені моди
eidos pack skyrimse backup.eidos           # увесь екземпляр в одному файлі
eidos unpack backup.eidos [folder]         # без теки глобальний екземпляр повертається на своє центральне місце
eidos --version                            # надрукувати версію
```

`eidos` без аргументів друкує список команд. Більшість команд друкують власні
параметри, коли бракує аргумента, а `eidos tool --help` перелічує підкоманди
`tool`. `eidos pack` приймає `--dry-run`, `--level`, `--no-downloads`,
`--no-recovery` і `--force`, а `eidos unpack` - `--info` і `--force`; обидві
описано [нижче](#перенесення-екземпляра-на-іншу-машину). `eidos stock-game`
описано в розділі
[Файли гри](#файли-гри-встановлення-з-магазину-або-копія).

### Запуск гри через об'єднаний вигляд

`eidos play` монтує моди екземпляра поверх власного каталогу `Data` гри всередині
приватного простору імен, а потім виконує команду через цей вигляд. Власні файли
гри спершу ховаються через bind-монтування, тож демон і далі читає їх без змін.
Записи (збереження, перегенеровані конфіги) потрапляють у шар `overwrite/`
екземпляра; інсталяція гри та кожна тека мода лишаються байт у байт такими, якими
були.

Eidos не потребує root. Він монтує в приватному просторі імен користувача й
монтування, без setuid-помічника, системної служби й нічого, що треба надавати.
Необов'язкова можливість на бінарному файлі `eidos` дозволяє FUSE passthrough,
який лишається вимкненим, доки не задано `EIDOS_FUSE_PASSTHROUGH=1`; див.
[install.md](install.md#необовязково-fuse-passthrough). З цією можливістю Eidos
використовує звичайний простір імен монтування замість простору імен
користувача, а моди розгортаються однаково в обох випадках.

### Оболонка в об'єднаному вигляді

`eidos shell <instance>` запускає ваш `$SHELL` (або `/bin/sh`) у теці гри такою,
якою її бачила б гра: кожен увімкнений мод змонтовано поверх `Data`, Root-моди
поверх кореня гри, а все записане там потрапляє в Overwrite.
`eidos shell <instance> -- <command>` виконує натомість одну команду, наприклад
`eidos shell skyrimse -- ls Data/meshes` чи нативний інструмент на кшталт
NifSkope. Запуск тримає блокування екземпляра, як ігрова сесія, тож вікно не може
зберегти зміни, доки ви не вийдете, і він записується в `eidos sessions` під
назвою `shell`, ніколи не як запуск гри. Ctrl+C на команді зупиняє запуск так, як
це робить Stop: Eidos завершує команду, фіксує сесію й демонтує. В інтерактивній
оболонці Ctrl+C належить оболонці, як зазвичай; наберіть `exit`, щоб завершити
запуск.

### Перевірки стану з термінала

`eidos check <instance>` запускає Health-перевірки, яким не потрібне вікно, тож
їх можна виконувати через SSH чи в Game Mode і додавати до звіту про ваду:

- Proton-префікс і його реєстр;
- діагностика плагінів і відсутні майстри;
- script extender і його додатки;
- оновлення гри з останнього чистого запуску;
- параметр запуску Steam;
- налаштування графіки (NVAPI, повноекранний режим, ENB);
- лог збою останнього запуску;
- рядки `sTestFile` в INI профілю;
- `.esp` і blueprint-додатки Starfield;
- `vm.max_map_count` і межа відкритих файлів;
- копія гри, яку запускає екземпляр, і `gamePath` у `ModOrganizer.ini` зі списку,
  що називає іншу теку гри;
- правила порядку колекції, що більше не діють;
- файли гри на NTFS, exFAT чи FAT;
- шляхи даних BodySlide;
- теки `Data`, залишені в `Overwrite/Root`;
- бібліотеки шрифтів, які називає `Interface/fontconfig.txt` і яких не дає жоден
  мод;
- стиснуте аудіо в архівах BA2 модів Fallout 4 і Fallout 4 VR.

Деякі картки обчислює лише вікно, на вкладці Diagnostics: порядок патчів,
скрипти розширювача, які замінює мод, архіви, які ніщо не завантажує, вимоги
Nexus, додатки, які LOOT позначає як брудні, збірка Proton, що запускає гру,
картка Display і вивід інструментів, старіший за його вхідні дані.

Команда друкує ті самі системні рядки, що й **Copy report**, а потім по рядку на
висновок, із вашою домашньою текою як `~` і вашим ім'ям для входу як `<user>`.
Код виходу 0, коли проблем не знайдено (самі лише поради теж дають 0), 1, коли
знайдено хоч одну проблему, і 2, коли Eidos не зміг перевірити: хибні аргументи,
екземпляр, який він не може відкрити, або гра, якої він не виявляє.

`eidos check <instance> --json` друкує натомість один об'єкт JSON. Його поля
верхнього рівня - `eidos` (версія), `game`, `instance`, `system` (`proton`,
`flatpak_steam`, `passthrough`, `session`, `distro`, `kernel`, `dev_fuse`,
`fusermount3`, `max_map_count`, `open_files_hard`) і `findings`.
`max_map_count` та `open_files_hard` - числа або `null`, коли Eidos не зміг їх
прочитати. Кожен висновок - це `code`, `level` (`problem` або `advice`) і його
`args`; вкладка Diagnostics показує речення для кожного коду.

### Що змінилося з останнього вдалого запуску

Кожен запуск через `eidos play`, `eidos shell` чи `eidos tool run`, розпочатий із
вікна, термінала чи Steam, записує запис у `<instance>/logs/sessions/`: профіль,
кожен увімкнений мод з його версією та ідентифікаторами файлів Nexus, порядок
плагінів, контрольну суму кожного INI профілю, версію виконуваного файла гри,
версію Eidos, код виходу та збереження, створені запуском. Зберігається 50
найновіших, а `logs/` не потрапляє в упакований екземпляр.
`eidos sessions <instance> diff` порівнює найновіший запуск гри, що завершився з
кодом 0, із поточним станом; `diff <id>` вибирає інший запис зі списку. Список
позначає [тестовий запуск](#тестові-запуски) як `test`, і тестовий запуск ніколи
не вибирається останнім вдалим. Запуск, який ви зупинили, записує код виходу 143,
тож його теж ніколи не вибирають. Eidos поки не виявляє збоїв тут, а гра, що
впала під Proton, усе одно може завершитися з кодом 0: якщо вибраний запуск був
таким, назвіть раніший через `diff <id>`.

## Список модів

Як в MO2, кожен профіль має власний `modlist.txt` (які моди ввімкнені і з яким
пріоритетом), тоді як теки модів живуть у спільному `mods/` екземпляра. Теку, яку
ви кинули в `mods/` вручну, ще не перелічено: вона з'являється вимкненою з
найвищим пріоритетом, унизу списку у вікні, як в MO2, тож виграє свої конфлікти,
щойно ви її ввімкнете.

Оскільки теки спільні, видалення чи перейменування мода змінює кожен профіль: його
рядок видаляється з `modlist.txt` кожного профілю або перейменовується в ньому, а
кожен профіль зберігає власний стан і порядок решти. Профіль без модів не має
`modlist.txt` взагалі.

Вікно працює зі своєю копією списку модів і порядку завантаження. Якщо інший
процес Eidos записує будь-що з цього, поки вікно відкрите (`eidos install` чи
`eidos sort` у терміналі, колекція, сесія, яку запустив Steam, друге вікно),
наступне редагування у вікні відхиляється замість перезапису тієї роботи. Воно
перечитує з диска і каже *Not saved: another Eidos process changed the mod list.
It has been reloaded - redo the change.* (або те саме для порядку завантаження);
втрачається лише це одне клацання, тож зробіть його знову. Rename, New mod, Add
separator, Remove і перетворення Overwrite на мод перевіряють це перед тим, як
чіпати `mods/`, тож відхилене редагування нічого не змінює на диску. Редактор INI
так само відмовляється зберігати поверх файла, що змінився після його відкриття.

## Збереження належать профілю

Кожен профіль тримає власні збереження в `profiles/<name>/saves/`, і на час
запуску ця тека монтується поверх теки збережень гри в Proton-префіксі. Перший
запуск профілю копіює в нього збереження, що вже є в префіксі, один раз, тож
збереження, яке ви потім видалили з профілю, лишається видаленим. Після кожного
запуску найновіші збереження профілю копіюються назад у префікс для Steam Cloud;
збереження в префіксі, яке Eidos туди не клав, спершу зберігається в профілі як
`orphan-<time>-<name>` і ніколи не перезаписується.

Збереження, що потрапляє в префікс після цього першого копіювання повз Eidos
(завантаження Steam Cloud зі Steam Deck, запуск без Eidos), лишається прихованим,
поки збереження профілю змонтовано. Ніщо його не видаляє: запуск називає його в
журналі запуску (`logs/run-*.log` екземпляра для запуску з вікна, консоль Steam для
запуску зі Steam), один раз щоразу, коли цей набір файлів змінюється, а вкладка
Saves рахує такі збереження в рядку під своїм заголовком. Щоб пограти в одне з них,
натисніть Import на вкладці Saves. Import копіює кожне разом із його косейвом у
профіль і ніколи не замінює збереження профілю: збереження, чиє ім'я профіль уже
використовує, імпортується як `orphan-<time>-<name>`.

## Тестові запуски

Кнопка Test run поруч із Run запускає гру так, як Run, але все, що гра пише,
потрапляє в `<instance>/test-run/`, а не у ваш профіль, Overwrite і префікс: нові
та змінені збереження, зміни INI, `plugins.txt`, файли, записані в Data чи теку
гри, і журнали в `Documents/My Games/<game>`. Можна тестувати з модами профілю,
без жодного мода або лише з вибраними модами, які ввімкнено, плюс моди, чиї
додатки їм потрібні як майстри.

Коли гра завершується, Eidos перелічує ці файли п'ятьма групами (збереження, зміни
INI, стан плагінів, вивід Overwrite, журнали) і просить залишити або викинути
кожну. Apply чекає, доки кожна група, що містить файли, не матиме відповіді. Стан
плагінів не пропонується, коли запуск використовував інший набір модів, ніж
профіль. Збереження ніколи не видаляє збереження з профілю, навіть те, яке гра
видалила під час запуску. Збереження виводу Overwrite також видаляє з Overwrite
файли, які гра видалила, і список спершу їх рахує. Викидання будь-чого потребує
другого натискання. Decide later закриває список і лишає файли в `test-run/`, а
список відкривається знову, коли ви наступного разу відкриєте екземпляр або
натиснете F5. Якщо Eidos чи комп'ютер зупиняється під час тестового запуску, файли
теж лишаються там, і список відкривається так само.

Коли вікно не запустив магазин гри, Test run передає гру цьому магазину (Steam,
Heroic або Legendary), як Run, а запуск, який стартує магазин, і є тестовим
запуском. Якщо магазин не запускає гру, запит чекає: наступний запуск гри цього
профілю, з Run чи з магазину, буде тестовим, а Cancel the waiting test run скидає
його. Тестовий запуск охоплює лише перелічені вище теки: інші записи гри, як-от
реєстр Wine, йдуть туди, куди йшли завжди. Збереження з тестового запуску
потрапляють у Steam Cloud лише після того, як ви їх залишите й зіграєте звичайний
запуск.

### Як знайти мод, що спричиняє проблему

Find the mod behind a problem на вкладці Diagnostics шукає мод, що спричиняє
проблему, яку можна відтворити, як-от збій у певному місці. Кожен крок - це
тестовий запуск з половиною підозрюваних, що лишилися, майстрами, яких вони
потребують, і модами, які ви тримаєте завжди ввімкненими: ввімкнені моди, вибрані
у списку на початку, і мод, що постачає script extender. Після кожного запуску ви
відповідаєте, чи проблема була. Not sure ділить підозрюваних інакше, а Run it
again повторює крок. Відповідь або натискання Run it again викидає файли, які
записав крок, після другого натискання. Щоб залишити деякі з них, спершу натисніть
See the files: він відкриває той самий список, що й після тестового запуску. Коли
гра впала і реєстратор збоїв записав лог або гра завершилася з кодом помилки,
Eidos позначає Yes як імовірну відповідь. 200 підозрюваних потребують близько 8
запусків.

Пошук зберігається в `<instance>/bisect.json`, тож між кроками можна закривати
Eidos, і він належить профілю, у якому почався. Stop the search скидає його після
другого натискання. Результат називає мод або набір модів, що потребують майстрів
одне одного, і зберігається в `<instance>/logs/bisect-<time>.txt`. Згенеровані моди
(вивід Nemesis чи DynDOLOD, Bashed Patch) збудовані під повний список і можуть
збоїти з його половиною: тримайте їх завжди ввімкненими або лишайте вимкненими на
весь пошук.

## Списки Wabbajack

Eidos не має інсталятора Wabbajack. Встановіть список через CLF3 або Jackify, поза
Eidos, а потім виберіть теку встановлення як портативний екземпляр у майстрі.
Eidos читає теку так, як її розкладає MO2: `mods/`, `profiles/<name>/modlist.txt` і
списки плагінів. Він зберігає `ModOrganizer.ini`, який записав інсталятор, і
ніколи його не перезаписує, тож виконувані файли самого списку лишаються
зареєстрованими.

Багато списків додають теку `Stock Game` або `Game Root`, що містить пропатчену
копію гри, і MO2 запускає гру звідти. Коли майстер чи `eidos init` уперше
перейматиме теку списку, а ця тека містить виконуваний файл гри, екземпляр теж
запускає гру з неї. Гра й далі стартує через Steam чи магазин, що нею володіє, тож
нічого переміщувати не треба. Eidos знаходить теку за `gamePath` у
`ModOrganizer.ini` списку або за цими двома назвами. Екземпляр, перейнятий
раннішим Eidos, зберігає інсталяцію з магазину, доки ви її не перемкнете (див.
наступний розділ). Коли цей `gamePath` називає теку гри, яку екземпляр не
запускає, Diagnostics про це каже, бо інструменти в режимі Mod Organizer 2, як-от
PGPatcher, читають гру звідти. CLF3 перебудовує файли BSA і DDS власними
інструментами, тож результат може відрізнятися від встановлення Wabbajack, а
автори списків його не підтримують.

## Файли гри: встановлення з магазину або копія

Типово гра запускається з інсталяції з магазину, теки, у якій її тримають Steam,
Heroic чи Legendary. Екземпляр натомість може працювати з копії цієї теки всередині
екземпляра. Моди лежать поверх копії, а інсталяція з магазину - лише місце, де
Eidos монтує результат. Магазин і далі запускає гру, тож Steam зберігає свій
оверлей, кеш шейдерів і хмарні збереження.

Картка Game files угорі вкладки Diagnostics показує, які файли запускає екземпляр,
з версією гри в копії та в інсталяції з магазину, і перемикає між ними. У
терміналі `eidos stock-game <instance>` друкує ті самі факти, а `use <folder>`,
`store`, `freeze` і `delete --yes` роблять те, що кнопки картки. `freeze` друкує
розмір і вид копії, а `freeze --yes` копіює.

**Freeze this version** копіює інсталяцію з магазину в `<instance>/Stock Game` і
запускає з неї гру, тож оновлення магазину більше не ламає додатки script
extender: оновлення змінює інсталяцію з магазину, а не копію. Перше натискання
показує розмір і те, що з ним робить файлова система, а друге копіює. На файловій
системі, що вміє ділити блоки (reflink), як-от btrfs чи XFS, копія майже не займає
місця, доки магазин не змінить файл. На ext4 або коли гра й екземпляр на різних
файлових системах, це повна копія розміром із теку гри. Eidos відмовляє, поки
Steam повідомляє, що гра зайнята або не повністю встановлена, поки працює гра чи
інструмент екземпляра, коли екземпляр уже тримає копію гри зі списку, заморожену
копію чи незавершену, і коли на файловій системі менше вільного місця, ніж
потребує повна копія. Копії Heroic і Legendary не перевіряються на оновлення, що
триває. Stop, збій або оновлення гри в Steam під час копіювання лишає
`Stock Game.eidos-tmp`, який картка пропонує видалити; його ніколи не
використовують.

Копія ховає кожен файл, який магазин додає, змінює чи видаляє в теці гри після
створення копії: нові файли Creation Club, новий виконуваний файл, нові DLL. Гра,
список додатків, LOOT і Health-перевірки читають копію. Вона не ховає того, що
відбувається поза текою гри: оновлення все ще може встановити середовища
виконання в Proton-префікс під час наступного запуску, а Steam може перемкнути гру
на інший Proton.

**Return to the store version** прибирає копію з наступного запуску після другого
натискання. Копія лишається на диску, а **Delete the copy** її видаляє, знову
після другого натискання. Delete відхиляється, поки екземпляр досі запускає копію.
Eidos ніколи не видаляє власну теку `Stock Game` чи `Game Root` зі списку. Якщо
теки копії немає або в ній більше немає виконуваного файла гри, запуски
відхиляються, а Diagnostics називає теку, тож версія з магазину ніколи не
запускається несподівано.

Morrowind, а також Oblivion з `bUseMyGamesDirectory=0` тримають список додатків у
теці гри, і Eidos поки не запускає їх з копії.

## Встановлення колекції Nexus

```sh
eidos collection skyrimse nxm://skyrimspecialedition/collections/rqhcxy/revisions/latest
eidos collection skyrimse rqhcxy --dry-run      # прочитати її й сказати, що станеться
eidos collection skyrimse rqhcxy --no-optional  # пропустити учасників, яких вона позначає необов'язковими
```

У вікні вставте посилання в **File -> Open a Nexus collection...** або клацніть
одне з них на сайті. Eidos перелічує учасників ревізії, кожного зіставленого з
цим екземпляром: встановлений, завантажений чи відсутній. *Install this
collection* виконує весь рецепт у робочому потоці, зі смугою поступу, яку
використовують завдання pack і unpack, і по завершенні смуга стає звітом. Вікно і
`eidos collection` виконують те саме встановлення.

Без посилання **File -> Open a Nexus collection...** відкривається на вкладці
**Browse**. Вона перелічує колекції, опубліковані для гри відкритого екземпляра,
по 20, відсортовані за кількістю завантажень, недавнім оновленням або новизною, а
поле пошуку звужує список до колекцій, чия назва чи текст збігаються. Кожен рядок
дає автора, останню ревізію, кількість модів, завантаження й дату. **View**
відкриває останню ревізію цієї колекції на вкладці **Link**, так само як вставлення
її посилання. Колекції, позначені як дорослі, пропускаються, якщо ваш обліковий
запис Nexus не показує дорослий вміст, колекції без рейтингу пропускаються завжди,
а рядок під списком рахує обидва випадки. Перегляд потребує облікового запису
Nexus, до якого виконано вхід, як і решта панелі.

Колекція відкривається лише для екземпляра її власної гри. Колекцію Skyrim,
відкриту, коли завантажено екземпляр Fallout 4, відхиляють поіменно, замість
зіставляти її учасників із хибним списком модів.

### Що Eidos читає з колекції

Майже нічого з колекції не видно через API Nexus. Порядок встановлення, відповіді,
які автор дав скриптовому інсталятору кожного мода, який мод виграє конфлікт
файлів, які плагіни завантажуються де та бінарні патчі - усе це лежить у
`collection.json` усередині власного архіву колекції. Завантажити ті самі моди й
встановити їх з типовими параметрами - це отримати іншу гру.

Eidos завантажує архів, читає `collection.json` і застосовує його:

| Колекція каже | Eidos робить |
| --- | --- |
| `phase` | встановлює в цьому порядку, необов'язкові учасники - останніми |
| `choices` | відтворює відповіді автора кожному FOMOD, а коли не може - каже про це |
| `modRules` | переставляє список модів так, щоб кожен файл вигравав потрібний мод |
| `plugins` / `pluginRules` | зливає правила LOOT у ваш userlist і сортує |
| `INI Tweaks/` | встановлює їх окремим модом |
| `tools` | каже, яких інструментів вона очікує; не створює нічого |

Учасників вмикають у міру встановлення, у кінці списку модів у порядку
встановлення, перш ніж `modRules` їх пересуне. Учасник, якого немає у списку модів,
не завантажувався б, а звіт цього не показав би.

Стан записується до `<instance>/collections/<slug>-<revision>.state.json` після
кожного учасника. Він лежить поруч із текою тієї ревізії, ніколи всередині неї, тож
колекція не може привезти власний файл стану, а встановлення, перерване на
учаснику 147 із 200, продовжується зі 147. Він пишеться під тимчасовою назвою й
перейменовується на місце, тож переривання лишає або старий запис, або новий, і
ніколи половину котрогось із них. Якщо його колись не вдасться прочитати, Eidos
зупиняється й каже про це, замість тихо починати цілу колекцію спочатку. Запустіть
ту саму команду ще раз.

Встановлення новішої ревізії колекції, яка у вас уже є, переймає теки попередньої
ревізії: незмінений учасник перевіряється на місці, учасник, чий файл автор
оновив, замінюється всередині своєї старої теки, а учасник, якого нова ревізія
викинула, лишається встановленим і названим у звіті, щоб ви його вимкнули або
видалили. Теку, яку вмикає інший профіль, ніколи не переймають, бо тека модів
спільна і той профіль змінився б непомітно для вас: натомість нова ревізія
встановлює поруч власну копію, а звіт просить вас вимкнути стару в цьому
профілі, але ніколи не видаляти її. Повернення до старішої ревізії так само
забирає її теки назад або встановлює свіжі копії тих, яких забрати не може.
Щоразу, коли учасника замінюють так, а ви змінювали або додавали файли в його
теці, стару теку спершу зберігають поруч як `<name>_backup`, яка ніколи не
завантажується в гру, і звіт її називає.

Залишок від ранішої ревізії, що й далі ввімкнений, не дає зарахувати
встановлення як те, що збудував автор; ця примітка зникає, щойно ви його
вимкнете. Учасника, якого ви пропустили через `--no-optional`, не переймають, і
його названо так само. Якщо не вдається саме перейняття, виконання зупиняється з
*previous revision: its folders could not be taken over* і причиною; виправте це
й запустіть команду ще раз.

### Безкоштовні облікові записи та учасники, яких ви завантажуєте самі

Безкоштовний обліковий запис Nexus не може дістати моди-учасники. Nexus не дає
безкоштовним обліковим записам посилань на завантаження через API: кожному файлу
потрібна власна кнопка сайту «Mod Manager Download». Архів колекції
завантажується на безкоштовному обліковому записі, тож ви можете прочитати весь
рецепт, але про кожного учасника повідомляється з точною URL його сторінки, щоб ви
дістали його самі, і повторна спроба цього не змінює. Дістаньте їх кнопкою сайту й
запустіть команду ще раз: цих учасників шукають у `downloads/` під час кожного
запуску, тож колекція доходить до кінця в міру того, як ви їх надаєте.

У вікні безкоштовний обліковий запис отримує в панелі колекції замість пакетного
завантаження кнопку *Fetch the N missing required files, one by one*. Вона
відкриває на Nexus сторінку першого відсутнього обов'язкового файлу, чекає,
доки цей файл з'явиться в `downloads/`, а потім відкриває наступну. Кнопку
завантаження на сторінці ви й далі натискаєте самі, для кожного файлу. Панель
показує, скільки пройдено (*3 of 12*), і має *Skip* та *Stop*. Якщо замість
потрібного прийшов інший файл того самого мода, панель називає обидва
ідентифікатори файлів і далі чекає на закріплений. Необов'язкові учасники сюди не
входять і зберігають власну кнопку *Open*.

Eidos також застосовує бінарні патчі (кожен перевіряється за записаним CRC),
перевизначення файлів (названі файли ховаються через `.mohidden`, як це робить
MO2) та учасників, чиї файли їдуть усередині архіву колекції (`bundle`).
Учасники, яких колекція очікує від вас дістати вручну (`browse`, `manual`),
проносять власні вказівки автора аж до звіту. Учасник, чия назва вже є назвою
одного з ваших модів, встановлюється поруч із ним під вільною назвою, ніколи
поверх нього, і звіт каже, який саме.

### Звіт

Учасник, для якого вдалося відтворити не всі відповіді інсталятору, отримує власний
рядок, *installed, but not the way the collection asks*, окремо від учасників,
встановлених так, як їх збудував автор, бо його файли на диску відрізняються від
авторських. Звіт також перелічує правила впорядкування, які не назвали в колекції
нічого, моди, спіймані в петлю суперечливих правил, групи LOOT, яких не існує, і
будь-яку частину маніфесту, якої ця версія Eidos не розуміє.

### Збереження порядку колекції

Eidos зберігає правила кожної встановленої колекції після встановлення. Коли ви
пізніше переставляєте два її моди всупереч правилу «до» чи «після», вкладка
Diagnostics показує одну картку для цієї колекції, називає першу таку пару й
рахує правила, що більше не діють. Враховуються лише моди, увімкнені в поточному
профілі, а правила, спіймані в петлю, пропускаються, бо жоден порядок їх не
дотримає. **Restore collection order** переставляє моди колекції назад у порядок,
що дотримується кожного правила, зберігає ваш власний порядок усюди, де правила
дозволяють, і лишає моди, яких немає в колекції, на місці. Ctrl+Z скасовує це.
`eidos check` перелічує той самий висновок як `collection_order_broken`.
Перевірка читає рецепт ревізії в `collections/`, тож колекція, чий кешований рецепт
видалено, не перевіряється.

## Перенесення екземпляра на іншу машину

`eidos pack` записує цілий екземпляр (кожен мод, порядок завантаження, усі
профілі, Overwrite з вашими збереженнями в ньому й архіви, з яких усе було
встановлене) в один файл. `eidos unpack` повертає його на місце:

```sh
eidos pack skyrimse ~/backup.eidos                  # або вкажіть теку: назва з гри та дати
eidos unpack ~/backup.eidos /mnt/games/EidosSkyrim  # на іншій машині
```

`eidos pack --dry-run` перелічує, що саме туди потрапило б, що ні і чому, і
скільки місця для цього потрібно, нічого не записуючи. `eidos unpack --info`
робить те саме для файлу, який у вас уже є.

Якщо 7-Zip чогось не зміг прочитати або під час обходу довелося пропустити щось,
що ви очікували б побачити в резервній копії (символьне посилання, теку, яку не
вдалося прочитати, назву, яку не можна безпечно передати 7-Zip), архів усе одно
записується під обраною вами назвою, але `eidos pack` завершується з кодом 1 і
каже, чого бракує, тож скрипт, що виконує `eidos pack ... && ...`, зупиняється
там.

Файл `.eidos` - це архів 7-Zip під власним розширенням. 7-Zip і так потрібен, щоб
установити мод, тож це не додає залежності, а резервна копія відкривається без
Eidos у будь-якому архіваторі, що читає 7-Zip. Вона стиснута LZMA2 на `-mx1`,
приблизно до 43% оригіналу на насиченому текстурами списку; `-mx9` триває
значно довше й заощаджує ще кілька пунктів. Текстури й меші - це вже стиснуті
формати, тож більший словник майже нічого не знаходить для стискання. `--level`
(0, 1, 3, 5, 7 або 9) вибирає інший рівень, а `--no-downloads` лишає `downloads/`
осторонь.

На рівні 1, типовому, файли потрапляють у суцільні (solid) блоки щонайбільше по
16 МБ. Щоб витягти один файл із резервної копії на 70 ГБ, декодується щонайбільше
блок, у якому він лежить, і ніколи все, що перед ним, а пакування ігрового вмісту
йде у 2-5 разів швидше, ніж коли кожен файл стискається окремо (розпакування - у
2-4 рази). Платити за це доводиться при пошкодженні: один зіпсований байт може
забрати з собою всі файли свого блока, до 16 МБ сусідніх файлів. Цей випадок
покривають дані для відновлення, описані нижче. Усі інші рівні лишаються
несуцільними: кожен файл - окремий потік, і через зіпсований байт втрачається лише
цей файл. Рівень 0 зберігає файли без стискання. Починаючи з рівня 3 LZMA2 і так
працює шматками по 16 МБ і більше, і суцільні блоки там у вимірах виявилися
повільнішими: на рівні 5 пакування мешів тривало в 1,4 раза довше, а розпакування
текстур - у 6,8 раза довше.

Пакування бере блокування екземпляра, тож воно не може виконуватися, поки гра чи
інший Eidos пише в цей екземпляр, і ніщо не змінює екземпляр, поки його читають.
Резервна копія записується під назвою з `.part`, скидається на диск і повністю
перечитується через `7z t`, перш ніж отримати обрану вами назву. Ця перевірка
декодує кожен блок і звіряє кожну контрольну суму - ту саму роботу робить
розпакування на іншій машині. Вона показує, що диск повернув одразу після
запису, а не те, що накопичувач це збереже; для цього й потрібні дані для
відновлення, описані нижче. Якщо перевірка не пройшла, `.part` видаляється,
під вашою назвою нічого не записується, а `eidos pack` наводить рядок, у якому
7-Zip знайшов пошкодження. Перерване чи невдале пакування лишає файл `.part` або
нічого, а не файл `.eidos`, який виглядає повним і таким не є.

Коли встановлено par2cmdline (`sudo pacman -S par2cmdline` в Arch,
`sudo apt install par2` у Debian і Ubuntu, `sudo dnf install par2cmdline` у
Fedora), `eidos pack` також записує поруч з архівом дані для відновлення PAR2:
`backup.eidos.par2` і кілька файлів `backup.eidos.volNN+MM.par2`, 5% архіву плюс
невеликий індекс. Тримайте їх у тій самій теці, що й файл `.eidos`, під тими
назвами, з якими їх записано, і копіюйте разом із ним: резервній копії,
перенесеній без них, нема з чого відновитися, а дані для відновлення
запам'ятовують назву архіву, тож перейменована копія їм уже не відповідає.
`eidos unpack` знаходить їх за назвою й перевіряє ними архів, перш ніж щось
видобути, зокрема копію, кінець якої обрізано так, що 7-Zip не може її відкрити.
Якщо зіпсувалося кілька байтів, par2 спершу лагодить архів і зберігає пошкоджену
копію як `backup.eidos.1`, для чого в його теці потрібно стільки вільного місця,
скільки займає архів; пошкодження більше, ніж покривають ці 5%, зупиняє
розпакування до того, як буде записано бодай один файл. Файли відновлення, що не
відповідають архіву, наприклад файли старішої копії з тією самою назвою, не
використовуються, якщо 7-Zip прочитав архів і знайшов його цілим, і розпакування
про це повідомляє. На машині без par2 розпакування все одно йде, з
попередженням, що дані для відновлення не використано. `--no-recovery` пакує без
них, а `eidos pack --dry-run` повідомляє, чи їх буде записано. `--force` замінює
наявний файл з тією самою назвою.

### Чого в ній немає і чому

| Лишається поза | Чому |
| --- | --- |
| Префікс Proton | Він має форму машини (відображення дисків, вигляд `Z:` на *цю* файлову систему), і Eidos відбудовує його за хвилину командою `eidos prereqs <instance> --install`. Тягти його означало б приблизно подвоїти архів заради того, що інша машина однаково має перегенерувати. |
| Гра | Екземпляр модифікує гру, якої він не містить. Встановіть її зі Steam там. |
| Інструменти поза екземпляром | xEdit, DynDOLOD і подібні - це сторонні виконувані файли з власними інсталяторами. Їх в архіві названо, тож розпакування скаже вам точно, яких із них бракує на новій машині. |
| `logs/`, `.eidos.lock`, `prereqs.done`, `prereqs.log` | Записи про машину, яка зробила резервну копію. Зокрема `prereqs.done` стверджував би, що бібліотеки runtime уже встановлені в префіксі, якого немає. |
| `loot/`, окрім `userlist.yaml` | Кеш майстер-списку, який Eidos перезавантажує на вимогу. Ваші власні правила LOOT у `userlist.yaml` перезавантажити неможливо, тож цей один файл їде разом. |
| `.base/`, `.base-root/` | Порожні точки монтування, куди на час сеансу відкладаються власні файли гри. |
| `test-run/`, `bisect.json` | [Тестовий запуск](#тестові-запуски), що чекає на розгляд, і пошук мода, що спричиняє проблему, між двома кроками. Обидва належать запускам на цій машині. |
| Недописані файли | Завантаження на паузі (`*.unfinished`), атомарний запис у процесі (`*.eidos-tmp*`). |
| Символьні посилання | 7-Zip пішов би за таким і скопіював те, на що воно вказує, а для абсолютного посилання це означає затягти чуже дерево до вашої резервної копії. Натомість про них повідомляється, і резервна копія вважається неповною: тека `mods/` чи `downloads/`, що посилається на інший диск, не пакується. Щоб навмисно зробити резервну копію без `downloads/`, яка є посиланням, передайте `--no-downloads` (або зніміть позначку *Include downloads/* у вікні); навмисно виключене не вважається відсутнім. |

Копія гри в екземплярі (`Stock Game`) пакується як будь-яка інша тека, тож резервна
копія замороженого екземпляра приблизно на розмір гри більша. Незавершена копія
(`Stock Game.eidos-tmp`) не включається.

Кожен із цих пунктів потрапляє до `eidos-backup.ini` у корені архіву разом зі
своєю причиною, тож прочитавши цей файл, видно, чого немає. Той самий файл
фіксує, де екземпляр жив раніше, який профіль був активним, скільки він займе після
розпакування і які інструменти знадобляться новій машині.

Записи про завантаження (`downloads/*.meta`) потрапляють усередину зі спорожненим
рядком `url=`. Ця URL - підписане посилання Nexus: воно перестає працювати за
кілька годин і несе `user_id` облікового запису, який завантажив файл, а
резервну копію можуть передати комусь іншому. Ідентифікатор мода, ідентифікатор
файлу та версія лишаються, тож завантаження можна знайти знову.

### У вікні

Обидва є в меню **File**: *Pack this instance...* і *Unpack a backup...*.
Розпакування є ще й на вітальному екрані, під списком екземплярів, тож машина без
жодного екземпляра може розпакувати один.

Перш ніж щось записати, діалог Pack показує, скільки файлів, якого розміру, скільки
з того припадає на `downloads/`, приблизно яким вийде архів і які інструменти лише
названо, а не взято з собою. Його прапорець *Write recovery data* позначено, коли
par2 встановлено, а коли ні - він сірий і поруч указано пакет для встановлення.
Діалог Unpack читає маніфест резервної копії, щойно ви обираєте файл, тож він може
сказати, яку гру вона містить, коли її зроблено, де вона жила раніше і яких її
інструментів тут бракує, ще до того, як ви вкажете теку.

Обидва виконуються в робочому потоці зі смугою поступу, і по завершенні смуга стає
звітом.

### Що виправляє розпакування

Проста копія теки лишила б кожну кнопку інструмента вказувати на шлях на старій
машині. `eidos unpack` переписує ті значення, які називають старий корінь
екземпляра, і лише їх: `exe`, `workdir` і нумеровані ключі `arg` у `tools.ini`,
а також `installationFile` у `meta.ini` кожного мода. Інструмент, якого ніколи
не було всередині екземпляра (`/opt/xedit/SSEEdit.exe`), лишається точно таким,
яким був, і потрапляє до списку того, що треба перевстановити; Eidos не вгадує,
де цей інструмент на новій машині. Він також виправляє, ким екземпляр себе
називає, централізованим чи портативним, щоб пізніші команди шукали його там,
де він тепер є.

Розпакування відхиляє непорожню теку (передайте `--force`, якщо ви справді
маєте намір перезаписати), диск, замалий для числа з самого маніфесту, архів,
зроблений новішим Eidos, ніж ваш, і будь-який архів із записом, який було б
записано *поза* обраною вами текою. Без теки резервна копія глобального
екземпляра повертається на центральне місце для своєї гри; портативній потрібна
тека.

Далі:

```sh
eidos prereqs /mnt/games/EidosSkyrim --install   # відбудувати префікс Proton
eidos play /mnt/games/EidosSkyrim
```

## Вікно

Запустіть `eidos-gui` або файл `eidos-linux`, який встановлює Colony.

Перший запуск відкриває майстер, як у MO2: вітання, тип екземпляра (портативний чи
глобальний), гра, назва й розташування, підсумок, а потім головне вікно. Вітальний
екран також перелічує кожен відомий екземпляр, глобальний і портативний, спершу
останній використаний, щоб відкрити одним клацанням, тож він править за
перемикач екземплярів. Якщо вказати майстрові теку, що вже містить екземпляр, він
відкриває цей екземпляр як є, замість створювати новий поверх нього, а тека, що
належить іншій грі, відхиляється.

Головне вікно має дві панелі: список модів, а також вкладки Data, Plugins,
Conflicts, Overwrite, Archives, Saves, Downloads і Diagnostics, з кнопкою Run,
кнопкою Test run ([Тестові запуски](#тестові-запуски)) і вибором цілі запуску. Ви
фільтруєте список модів, виділяєте, переставляєте, групуєте роздільниками,
звужуєте за категорією й клацаєте правою кнопкою для дій. Крім send to top і
bottom, меню мода має цільові переміщення MO2: відправити над першим конфліктним
модом, під останнім, на заданий пріоритет або в групу роздільника.

Вибір профілю перемикає профілі. Клацніть профіль правою кнопкою для Rename, Copy
to new..., Desktop shortcut, Import from MO2... і delete, яке потребує двох
клацань і відмовляє для активного чи останнього профілю. Import from MO2...
переймає порядок модів і порядок завантаження профілю MO2. Desktop shortcut пише
запис робочого столу, що виконує `eidos tool <instance> run "<game>" --profile
<name>`: він робить цей профіль активним і просить магазин запустити гру
(подробиці в
[tools.md](tools.md#як-дістатися-інструмента-приховати-закріпити-і-ярлик-на-робочому-столі)).

Меню **File** також запускає winecfg, regedit, файловий менеджер Wine і програму
видалення в префіксі гри, а Prefix drive_c відкриває диск `C:` префікса; див.
[tools.md](tools.md#власні-програми-wine-у-префіксі-гри). *Instances...* перелічує
екземпляри, які знає Eidos; Forget прибирає один зі списку й нічого не чіпає на
диску. *Export the mod list...* записує список у форматі CSV від MO2, як
`eidos export`.

### Preferences

Клацніть **Eidos** угорі ліворуч, щоб відкрити Preferences замість двох панелей, і
клацніть знову (або **Close**), щоб повернутися. Спершу йдуть General, Appearance
і Accessibility, як у кожній програмі Colony, потім Mod list, Nexus і About. Кожна
зміна застосовується й зберігається одразу; кнопки Save немає.

- General: гра, яку відкриває Eidos, розмір вікна, мова інтерфейсу, тека
  інструментів і спосіб запуску гри. Lock the window while a game runs типово
  ввімкнено. Start the game at once when a store opens Eidos і сповіщення
  робочого столу, яке каже, коли довге завдання закінчується, поки вікно у фоні,
  типово вимкнені. Вікно розмовляє англійською та французькою; System
  слідує за `LC_ALL`, `LC_MESSAGES` або `LANG`, і зміна застосовується одразу.
  Командний рядок `eidos` завжди відповідає англійською.
- Appearance: тема (26 родин, 59 палітр, типово пергамент Eidos), акцентний
  колір, розмір тексту, ефекти й живий перегляд.
- Accessibility: високий контраст, шрифт, зручний для людей із дислексією,
  зменшена анімація та розмір тексту для читання, який множиться з розміром з
  Appearance.
- Mod list: швидкість автопрокручування, коли мод перетягують до верхнього чи
  нижнього краю списку.
- Nexus: вхід, тека завантажень, обробник `nxm://` і його кнопка Register,
  бажані сервери, Install downloads when they finish та Offline mode.
- About: де лежать файли, клавіатурні скорочення, версія та перевірка випусків.

Вигляд і мова інтерфейсу живуть у `~/.config/Colony/Eidos/preferences.json`. Інші
налаштування, які читає й командний рядок (типова гра, тека інструментів, сервери
Nexus, Offline mode та решта), живуть у `settings.ini` поруч, а сесія Nexus - у
`nexus.ini`. Тема, яку старіший Eidos тримав у `settings.ini`, переноситься
першого разу.

**About -> Version** містить перевірку випусків, типово ввімкнену. При старті,
щонайбільше раз на добу, Eidos питає GitHub про останній випуск
`Project-Colony/Eidos`. Коли він новіший за запущену копію, рядок меню показує
`Eidos <version> is available: release notes` після Help, і посилання відкриває
сторінку цього випуску з його журналом змін. Eidos ніколи не завантажує й не
замінює себе. Перевірка пропускається в офлайн-режимі. Вона вимкнена для копії,
встановленої під `/usr` менеджером пакетів, який її оновлює; `/usr/local`, куди
`install.sh --system` кладе Eidos, вважається вашим власним встановленням.

### Стовпці, сортування та групування

Список типово показує чотири стовпці (Category, Content, Version і Flags, ті, що
показує MO2) і пропонує вісім: Category, Content, Version, Author, Installed,
Nexus id, Game, Flags. Позначте їх у меню View. Коли ввімкнено всі вісім, у
стовпця назви лишається мало місця.

Клацніть заголовок, щоб сортувати за ним, ще раз - щоб обернути, і втретє -
щоб повернутися до порядку завантаження. Список можна перетягувати лише в порядку
завантаження: позиція скидання адресує справжній список, а під сортуванням місце
рядка на екрані - не його місце в тому списку. Поки сортування ввімкнено, смуги
вставки не малюються, а перетягування відхиляється, як у MO2. Меню View про це
каже й пропонує шлях назад.

Меню View також може групувати весь список за категорією чи за джерелом (з Nexus
або встановлені вручну). Заголовки груп - не роздільники: їх не можна
перейменувати, розфарбувати чи перемістити. Вони згортаються, а згорнутий
заголовок зберігає свій лічильник. Роздільники ховаються, поки ввімкнено
сортування чи групування, бо роздільник очолює рядки, що йдуть за ним у порядку
завантаження, а обидва змінюють цей порядок на екрані.

### Миша й клавіатура

Подвійне клацання на моді - Information, Ctrl+подвійне клацання - його тека,
Shift+подвійне клацання - його сторінка Nexus. Ctrl+F ставить курсор у поле
фільтра. Набір літери переходить до наступного мода, що починається з неї, а
повторне натискання проходить решту замість того, щоб лишатися на першому. Жоден
перехід не потрапляє на рядок, який ховають фільтр, згорнутий роздільник чи
згорнута група, тож наступний Space ніколи не перемикає мод, якого ви не бачите.

«Collapse others» у меню роздільника згортає кожну групу, крім цієї. Під час
перетягування утримання вказівника нерухомо над згорнутою групою відкриває її,
тож мод можна скинути всередину; простий проліт над нею її не відкриває.

Ctrl+Z скасовує останню зміну списку модів чи порядку завантаження: позначку,
переміщення, пакетне вимкнення, сортування LOOT. Ctrl+Shift+Z повторює її. Вікно
тримає 50 кроків і забуває їх при F5, наприкінці запуску гри чи інструмента, при
зміні профілю та коли інший процес Eidos змінює список. Встановлення,
перейменування чи видалення мода змінює теки на диску, тож скасування повз одне
з них відхиляється.

### Фільтрування списку

Кнопка Filters відкриває по одному рядку на критерій: active, conflicted, update
available, no category, endorsed, tracked, has a Nexus id, has hidden files, no
valid game data, for another game, has notes, і по одному рядку на вид вмісту
(плагіни, архіви BSA чи BA2, текстури, меші, скрипти, додатки script extender,
файли інтерфейсу, звук, FaceGen). Клацання проводить рядок через off, only і
except. Рядок угорі перемикає між збігом з усіма ввімкненими критеріями та
збігом з будь-яким із них. Поле назви й список категорій завжди звужують
результат ще більше. Рядок прихованих файлів дивиться лише на увімкнені моди.

### Що список каже про мод

Два пораджувальні прапорці, кожен - гліф із поясненням при наведенні. No valid
game data означає, що нічого на верху мода не схоже на те, що ця гра завантажує;
можливо, його теки треба підняти на рівень, а можливо, це не мод для цієї гри.
Another game означає, що власний `meta.ini` мода називає іншу. Жоден не блокує
нічого: мод усе одно розгортається. «Mark as valid» у меню рядка вмикає мовчання
для обох через власний ключ MO2 `validated=`, тож мод, позначений як валідний в
одному менеджері, не позначається в іншому.

Перевірка розкладки позначає мод лише тоді, коли певна: дерево `Root/`, нечитабельна
тека й порожня тека всі вважаються валідними даними гри.

### Вимкнення мода, яким користуються ваші збереження або інші моди

Перш ніж мод вимкнуть чи видалять, Eidos читає списки плагінів трьох найновіших
збережень профілю. Коли одне з них використовує плагін із цього мода, смуга над
списком називає плагіни й чекає на Disable anyway чи Cancel (Escape теж
скасовує). Remove додає ті самі назви до свого повідомлення «клацніть ще раз».
Читаються лише збереження Skyrim і Fallout 4; для інших ігор моди вимикаються без
запитання.

Information мода, вкладка General, перелічує моди, яких він потребує, і моди, які
потребують його, зчитані з майстрів увімкнених плагінів. Вимкнення мода, якого
потребують інші, показує ту саму смугу з Disable them too, що вимикає також кожен
мод, який його потребує, і моди, які потребують ті, або Keep them enabled. Картка
відсутніх майстрів на вкладці Diagnostics має Enable what provides them: вона
вмикає мод, що містить кожного відсутнього майстра, і позначає плагін-майстер, який
присутній, але не позначений.

### Резервна копія мода, перш ніж його чіпати

«Back up this mod» копіює його теку вбік як `<name>_backup` (потім `_backup2` і так
далі; резервна копія ніколи не замінює попередню). Копія - не мод: її прапорець
нічого не робить, і вона нічого не додає до об'єднаного вигляду, бо її
позначення розгорнуло б дві копії одного мода одну поверх одної. «Restore this
backup over the mod» повертає її, за два клацання; поточний вміст спершу
відсувається вбік і відкидається лише після успішного копіювання.

**Backups** на панелі інструментів зберігає точки відновлення списку модів
профілю, його порядку завантаження (`plugins.txt` і `loadorder.txt` разом) і його
INI гри, по 10 кожного, у `<profile>/backups/`. Back up now додає одну, а Restore
спершу робить резервну копію поточного стану, тож хибний вибір можна скасувати.
Eidos також зберігає точку відновлення INI перед кожним запуском BethINI (див.
[tools.md](tools.md#bethini-pie)).

### Вкладки

**Data** - це дерево об'єднаного вигляду, що розгортається по одному рівню за раз:
відкриття теки читає цю теку в кожному шарі, що її має, ніколи не всі увімкнені
моди одразу. Воно будується з того самого стека шарів, який обслуговує монтування,
тож whiteout-и та приховані файли враховуються, а вкладка показує те, що побачить
гра. Фільтруйте його за назвою, звужуйте до спірних файлів, розбирайтеся, що де,
через стовпці Size і Modified та використовуйте Reveal на будь-якому рядку, щоб
відкрити його у файловому менеджері. Наведення на файл перелічує інші моди, що постачають його.
`meta.ini`, `readme.txt`, `fomod/` і `Root/` верхнього рівня мода не входять до
Data, ні в цій вкладці, ні в монтуванні: перші три призначені менеджерові модів, а
`Root/` натомість іде в теку гри. Файл, який гра чи інструмент пише під однією з
цих назв, потрапляє в Overwrite і лишається видимим.

Рядок `.exe` у Data має Add tool, що відкриває редактор Executables із заповненим
цим файлом (нічого не зберігається, доки ви не натиснете Save), і Run, що запускає
його один раз через об'єднаний вигляд, як зареєстрований інструмент
([Інструменти](#інструменти)). Save tree записує все об'єднане дерево Data у
текстовий файл, по рядку на файл із модом, що його постачає, з вилученими вашою
домашньою текою й іменем користувача, для звіту про ваду.

**Plugins** - це порядок завантаження ESP/ESM/ESL: перемикайте, переставляйте
вручну або сортуйте через LOOT і читайте звіт після сортування, чиї поради-посилання
відкриваються у вашому браузері. Його заголовок рахує увімкнені плагіни в кожному
просторі індексів проти ліміту гри, наприклад `full 231/254, light 512/4096`, і
стає помаранчевим, коли один заповнений. Поле фільтра звужує список за назвою.
Space, Ctrl+A, діапазони Shift та Activate all shown і Deactivate all shown у меню
рядка тоді діють лише на показані рядки, а перетягування відхиляється, доки
фільтр не очищено. Вибір плагіна підсвічує його майстрів у списку плагінів і мод,
що його постачає, у списку модів. Плагіни, які LOOT позначає як брудні, отримують
картку Diagnostics, що може очистити їх через xEdit
([tools.md](tools.md#очищення-плагіна-який-loot-позначає-як-брудний)).

Після сортування LOOT повний плагін, чиї нові записи всі вміщаються в діапазон
light, каже про це при наведенні, а меню його рядка має Flag as light. Eidos
записує копію з прапорцем light у новий мод `<plugin> (light)` унизу списку модів
(найвищий пріоритет) і лишає оригінал, тож вимкнення цього мода скасовує дію. Він
відмовляє, коли одне з трьох найновіших збережень профілю завантажує плагін як
повний. Читаються лише збереження Skyrim і Fallout 4, тож у Starfield жодне
збереження не перевіряється. LOOT перевіряє лише діапазони записів: перш ніж
позначати плагін, що додає cell чи worldspace, подивіться на нього в xEdit.

Наведення на плагін показує, звідки він, його автора, версії його заголовка й
форм, перші 300 символів його опису, його майстрів і, після сортування LOOT,
повідомлення LOOT. У Skyrim, Skyrim SE, Skyrim VR і Enderal SE гра також читає
INI, названий за завантаженим плагіном; стовпець INI позначає ці плагіни, а клацання
відкриває цей файл лише для читання.

**Conflicts** пояснює переможців і переможених для кожного файлу. **Overwrite**
перетворює те, що записала гра, на справжній мод за один крок.

**Archives** перелічує кожен BSA чи BA2, який постачають увімкнені моди, мод, з
якого він походить, і чому він завантажується: активний плагін з тією ж назвою або
його реєструє INI. Той, що його ніщо не завантажує, позначається як мертвий вантаж.
Коли інший мод постачає архів з тією самою назвою, що виграє конфлікт, рядок називає
цей мод. Extract розпаковує архів у новий мод, названий за ним без розширення
(`Foo.ba2` дає `Foo (extracted)`), і лишає архів у його моді; вільні файли
перемагають файли в будь-якому архіві, незалежно від порядку модів.

**Saves** читає заголовок кожного збереження (персонаж, рівень, місце, час гри),
порівнює список плагінів, збережений у ньому, з поточним і має кнопку, що вмикає
моди, яких воно потребує. Збереження, що потрапили в префікс без Eidos, описано в
розділі [Збереження належать профілю](#збереження-належать-профілю).

**Downloads** і **Diagnostics** мають власні розділи нижче.

### Інформація про мод

«Information...» відкриває діалог мода з вкладками General, Conflicts, Filetree,
INI Tweaks, Notes, Nexus files і Nexus page. З filetree (і з дерева Data) будь-який
файл можна сховати: його перейменовують на `<name>.mohidden`, що забирає його з
об'єднаного вигляду без видалення, тож кілька зайвих файлів одного мода можна
притлумити без зміни пріоритетів. Filetree також виконує звичайні операції з
файлами: нова тека, перейменування, видалення, відкриття. Кожна відхиляє шлях, що
не є простим шляхом усередині цього мода: ніяких `..`, ніяких абсолютних шляхів і
ніяких симлінків по дорозі, бо прохід за таким міг би видалити файл поза текою
мода. Rename змінює лише останню частину шляху, тож ніколи не переміщує файл, і
відхиляє вже зайняту назву. Delete потребує двох клацань і його не можна
скасувати.

**View** на будь-якому рядку filetree чи дерева Data показує файл: зображення,
текст, текстури DDS (виберіть mip, шар, грань і канал) і статичні моделі NIF з
їхніми дифузними текстурами. Перегляд NIF потребує `eidos-nif-preview` поруч з
Eidos або в `PATH`; пакет випуску, пакет Arch і збірки з джерельних кодів його
мають, `eidos-linux` - ні. Текст читається до 64 КБ і каже, де зупинився.

**INI Tweaks** перелічує фрагменти, які мод постачає у своїй теці `INI Tweaks/`;
увімкнені зливаються в INI гри профілю під час запуску, у порядку пріоритету, і
прибираються знову, коли INI запуску фіксуються, тож вимкнення твіка прибирає його
налаштування.

Вкладка **Nexus files** перелічує файли мода на Nexus, найновіші першими, і
позначає той, що встановлений тут, і той, що його замінює. Другий рядок має кнопку
**Update**; див. [Оновлення модів](#оновлення-модів).

Вкладка **Nexus page** показує опис мода і, найновіші першими, журнал змін кожної
версії файлу на його сторінці. Eidos читає обидва, коли ви вперше відкриваєте
вкладку, з GraphQL API Nexus, що не враховується в погодинний бюджет запитів. Він
тримає їх, доки Eidos не закриється або ви не натиснете **Refresh**. Вони показані
звичайним текстом: форматування BBCode і HTML вилучено, адреса посилання
записується після його тексту, а зображення й відео опущено. **Endorse** і
**Track** над текстом роблять те, що меню мода за правим клацанням. Сторінка
дорослого мода лишається прихованою, якщо ваш обліковий запис Nexus не показує
дорослий вміст, а сторінка без рейтингу лишається прихованою в усіх випадках.

### Завантаження

Завантаження можна перетягнути зі списку Downloads на позицію в списку модів, щоб
встановити його з цим пріоритетом, а архіви чи теки, скинуті на вікно з файлового
менеджера, теж встановлюються. Скидання файлів потребує сесії X11 або XWayland:
winit реалізує їх лише для X11. Завантаження можна призупиняти й відновлювати:
пауза зупиняє передавання й зберігає частковий файл, а Resume просить у Nexus
свіже посилання й продовжує з того місця, де зупинилося.

Вкладка Downloads тримає архіви, які ви завантажили. Фільтруйте її за назвою (і за
дружньою назвою мода, тож «skyui» знаходить `SkyUI_5_2_SE-12604-5-2SE.7z`),
сортуйте за новизною, назвою, розміром чи станом і ховайте архів, з яким закінчили:
файл лишається, зникає лише рядок. «Show hidden» повертає їх, а та сама кнопка
знову показує. «Remove N installed» видаляє архіви модів, які ви вже встановили, за
два клацання, і лише ті, що показує фільтр.

**Preferences -> Nexus -> Install downloads when they finish** типово вимкнено.
Коли ввімкнено, завантаження Nexus, що завершується, поки вікно відкрите,
встановлюється без візиту на вкладку Downloads. Це звичайне встановлення: FOMOD
відкриває свій інсталятор, а назва, що вже є в списку модів, питає, що робити.
Архіви, що були в `downloads/` до відкриття вікна чи до ввімкнення опції,
лишаються без змін, так само як завантаження, чиє встановлення ви скасували.
Поки колекцію відкрито в панелі колекції, жодне завантаження не встановлюється
саме, і те, що завершується тим часом, пізніше теж не встановиться саме;
колекція встановлює своїх учасників. Файл, якого чекає Update, що очікує,
встановлює Update. Таким способом встановлюються лише завантаження Nexus, а те,
що ховає фільтр Downloads, чекає, доки фільтр не очищено. Поки триває
перетягування або поки гра чи інший Eidos тримає екземпляр, встановлення чекає.

### Оновлення модів

Кнопка оновлення біля правого краю панелі інструментів перевіряє кожен мод, що має
Nexus id. Коли сторінка мода показує встановлену вами версію, більше нічого не
питається. Інакше Eidos читає список файлів мода (ще один запит, який зберігається
до кінця перевірки) і йде за ланцюгом оновлень від ідентифікатора файлу, який
записує `meta.ini` мода: автори позначають нове завантаження наступником старшого,
і MO2 читає той самий ланцюг. Новіший файл у цьому ланцюгу є оновленням. Коли
ланцюг не називає жодного, а встановлений файл усе ще є в списку на сторінці, мод
вважається актуальним, навіть якщо сторінка показує іншу версію. Версія сторінки
вирішує лише тоді, коли ідентифікатор файлу не записано, коли встановлений файл
видалено чи заархівовано або коли Nexus не надіслав список файлів.

Кожен мод використовує домен Nexus тієї гри, яку називає його власний `meta.ini`
(`gameName`), а не гри екземпляра: перевірка оновлень, Endorse, Track і Visit on
Nexus ідуть туди. Enderal SE також приймає моди `skyrimspecialedition`, тож мод
Skyrim SE, встановлений в екземплярі Enderal SE, перевіряється на своїй сторінці
Skyrim SE. Посилання Mod Manager Download іде до екземпляра, яким ви користувалися
востаннє, якщо його гра приймає домен посилання. Інакше воно іде до екземпляра гри,
чий це власний домен, раніше за екземпляр гри, що його лише приймає.
`EIDOS_INSTANCE=<folder>` перевизначає обидва випадки.

Track і Untrack у меню мода за правим клацанням додають мод до ваших відстежуваних
на Nexus або прибирають його, тож сповіщення сайту йдуть за тим, що ви відстежуєте
тут. Endorse і Abstain у тому самому меню схвалюють мод на Nexus або відкликають
схвалення; кнопка endorse поруч із кнопкою оновлення схвалює вибраний мод. Кожна
перевірка оновлень також читає ваші схвалення й відстежувані моди з Nexus (два
запити) і виставляє прапорці Endorsed і Tracked кожного мода відповідно, на
власному домені Nexus цього мода. Коли вони розходяться, Nexus виграє. Якщо жоден
зі списків прочитати не вдається, перевірка каже про це й лишає ті прапорці як
були.

Кнопка **Update** на вкладці Nexus files у «Information...» встановлює новіший
файл. З premium-обліковим записом Eidos завантажує файл сам. З безкоштовним він
відкриває сторінку файла, де Mod Manager Download надсилає файл назад, і
встановлення починається, коли архів з'являється в `downloads/`. Далі це звичайне
встановлення: FOMOD відкривається на відповідях, з якими мод було встановлено, потім
запит пропонує Replace з позначеним «Keep a backup of the existing mod», що б ви
не вибрали в попередньому запиті. Replace зберігає пріоритет і стан ввімкнення
мода.

Перш ніж Replace підмінить теку мода, Eidos порівнює стару теку з новою за назвою
файлу й розміром і читає заголовки плагінів в обох. Це стосується Update,
оновлення колекції та Replace, обраного в запиті встановлення. Рядок стану тоді
рахує файли, додані, видалені й змінені в розмірі, і називає кожного майстра,
якого потребує нова версія, а старій він не був потрібен. Вкладка **General** у
«Information...» закінчується розділом **Last update**, що перелічує версії,
додані чи видалені плагіни, додані чи видалені майстри, плагіни, у яких змінився
прапорець ESM, ESL чи ESH, моди, з якими цей тепер ділить файли або вже не ділить,
і файли. Файл, переписаний з тим самим розміром, не перелічується. Звіт
зберігається в `logs/updates/<mod>.json` в екземплярі, який `eidos pack` лишає
осторонь; свіже встановлення чи Merge у теку його видаляє.
`eidos install --replace` друкує ті самі числа в рядку `changes:`.

Тека, що містить кілька файлів Nexus, як-от основний файл із об'єднаним у нього
необов'язковим, відхиляється: заміна її новим основним файлом відкинула б решту.
Оновлюйте такі вручну.

`eidos nexus update skyrimse --apply` виконує ту саму перевірку, а потім на
premium-обліковому записі завантажує кожен новий файл і встановлює його поверх
його теки через `--replace --backup`. На безкоштовному натомість друкує
`OPEN <url>` для кожної сторінки файла. Теки, що зливають кілька файлів,
пропускаються з причиною. Мод FOMOD без записаних відповідей, як-от встановлений
до того, як Eidos їх почав зберігати, не перевстановлюється з типовими
значеннями інсталятора: таке оновлення завершується невдачею з повідомленням
оновити мод один раз із вікна, що записує відповіді. FOMOD, чий інсталятор нічого
не пропонує вибрати, встановлюється як зазвичай. Команда завершується з кодом 1,
якщо будь-яке оновлення не вдалося.

### Оновлення колекцій

Коли ви запускаєте Check for updates, Eidos також питає Nexus про останню ревізію
кожної колекції, встановленої в цьому екземплярі. Рядок над списком модів називає
кожну колекцію з новішою ревізією й рахує додані (+), оновлені (~) та викинуті (-)
моди; наведіть на нього, щоб побачити їхні назви. Числа відсутні, коли рецепт
встановленої ревізії більше не кешовано. **Update** відкриває новішу ревізію в
панелі колекції, де *Install this collection* її виконує. Список перебудовується
при кожній перевірці й не зберігається.

### Налаштування Nexus

**Preferences -> Nexus -> Offline** зупиняє будь-який контакт Eidos із Nexus і
пропускає щоденну перевірку випусків на GitHub. Перевірки оновлень, вхід,
завантаження й колекції кажуть про це замість збою з помилкою з'єднання. Типово
вимкнено.

**Preferred servers** ранжує вузли CDN, яким віддає перевагу завантаження, кращі
першими. Лише premium-обліковий запис отримує більше одного дзеркала на вибір, тож
для всіх інших вибирає Nexus, і це нічого не змінює. Коли жоден з названих вами
серверів не запропоновано, завантаження все одно відбувається з першого вузла, який
пропонує Nexus.

### Категорії

Категорії можна призначити одному моду чи цілому вибраному набору, каталог можна
редагувати з того самого діалогу, а офіційний список категорій гри можна
витягти з Nexus. Обидва файли каталогу - власні файли MO2 (`categories.dat` і
`nexuscatmap.dat`), тож спільний екземпляр тримає один каталог. Мод, завантажений
з Nexus, категоризується при встановленні, щойно Fetch from Nexus зіставить
каталог.

### INI-редактор, лог і розширення

**View -> INI editor** редагує INI гри профілю, копію, яку тримає Eidos; копія в
Proton-префіксі перезаписується при кожному запуску. Його остання вкладка - це
`launch-env.ini` профілю
([Змінні та обгортки для профілю](#змінні-та-обгортки-для-профілю)).
**View -> Log** читає журнали сесій. **View -> Extensions** перелічує ваші
власні доповнення; див. [extensions.md](extensions.md).

Коли запуск не знаходить головного INI гри (`Skyrim.ini`, `Fallout4.ini`,
`Oblivion.ini`...) ні в профілі, ні в префіксі, Eidos спершу копіює типовий INI з
теки гри (`Skyrim_Default.ini`, `Fallout4_Default.ini`...) у профіль, як MO2.
Коли екземпляр запускає копію гри, типовий береться з копії. Префікс і тека гри не
змінюються.

### Встановлення модів

Інсталятор обробляє прості архіви, FOMOD, пакунки Wrye Bash BAIN (позначайте
підпакунки, які зливаються по порядку) і пакунки OMOD для Oblivion. Скрипт OMOD
виконується, коли використовує команди OBMM, які підтримує Eidos, або є одним із
трьох інсталяторів на C#, які Eidos знає; жодного іншого коду C# чи Visual Basic
Eidos не виконує й каже про це. Коли жодна евристика не розпізнає розкладку,
ручний вибір показує дерево архіву й дає вказати корінь даних.

Перевстановлення чи оновлення мода FOMOD відкриває майстер з позначеними
відповідями його останнього встановлення, на першому кроці, чиї параметри з того часу
змінилися, із переліком змін. **Reinstall with new choices** натомість починає з
типових значень інсталятора. `eidos install --replace` чи `--merge` використовує
збережені відповіді й відмовляє, перелічуючи зміни, коли вони більше не підходять.

### Діагностика

Вкладка Diagnostics виконує живі перевірки стану. Вона повідомляє про відсутні
майстри, плагіни, які LOOT позначає як брудні, архіви, які не завантажить жоден
активний плагін, чи список модів досі відповідає теці модів, чи ввімкнено FUSE
passthrough і, коли його запрошено, чи є можливість запуску, якої він потребує.
Після запуску вона показує, що власний лог script extender каже про кожну DLL його
додатків, тож ви бачите, чи завантажилися ваші додатки SKSE. Вона також повідомляє
про оновлення гри з останнього чистого запуску, відсутній script extender чи такий,
що не відповідає версії гри (зі сторінкою завантаження розширювача й кнопкою
встановлення архіву, який ви завантажите), параметр запуску Steam, що не стартує
Eidos з `%command%`, NVAPI, залишений вимкненим для DLSS, ексклюзивний
повноекранний режим, що зупиняє генерацію кадрів, ENB `enblocal.ini` без
`LinuxVersion=true`, оголошення додатків F4SE і SFSE та лог збою останньої сесії з
модами, які він називає.

Перевірки INI профілю та плагінів шукають рядки `sTestFile` у `[General]` власних
INI Fallout 4, Fallout 4 VR і Starfield, які змушують гру ігнорувати `plugins.txt`
(Fix видаляє їх із копії профілю й зберігає попередній файл як `<ini>.pre-fix`),
увімкнені `.esp` у Starfield і blueprint-додатки, яким бракує прапорця blueprint,
префікса `BlueprintShips-` чи розширення `.esm` або чий основний додаток не
ввімкнено. Системні перевірки позначають `vm.max_map_count` чи жорстку межу
відкритих файлів нижче того, що потрібно Proton, і гру, префікс чи екземпляр на
NTFS, exFAT або FAT. Перевірки модів називають шлях даних BodySlide, коли він не
вказує на `Data` гри, теки `Data`, які інструмент записав у `Overwrite/Root`,
патч, чиї вільні файли програють моду, який він патчить, і мод, що замінює скрипти
Papyrus script extender.

Check for updates також читає вимоги Nexus кожного мода. Diagnostics перелічує
потрібний мод, який відсутній чи вимкнений, з Ignore для вимоги, виконаної іншим
способом.

Вкладка також показує, яка збірка Proton запускає гру, і попереджає, перш ніж
старіший Proton запустить префікс, який підготував новіший; Rebuild відсуває
зламаний префікс убік, щоб Steam створив новий
([troubleshooting.md](troubleshooting.md#який-proton-запускає-гру-і-зламаний-префікс)).
Інші картки позначають префікс, який ніколи не налаштовували чи чий реєстр
застарів, програму, що не є Eidos, яка отримує посилання Mod Manager Download
(Register це виправляє), вивід інструмента, старіший за його вхідні дані (з
кнопкою, що запускає інструмент знову), і очищену чи light-копію плагіна, чий
оригінал відтоді змінився. Кожну картку пояснено в
[troubleshooting.md](troubleshooting.md#health-картки). **Copy report** кладе в
буфер обміну звіт про систему і кожен висновок, із прихованими домашньою текою й
іменем для входу, для звіту про ваду.

Для Skyrim SE, Enderal SE і Fallout 4 Diagnostics також має картку Display. Вона
показує розмір і режим вікна, задані в `SkyrimPrefs.ini` профілю
(`EnderalPrefs.ini`, `Fallout4Prefs.ini`) або в копії префікса, коли профіль ще не
має такої. Коли жоден не задає розміру, її поля починаються з найбільшого
підключеного екрана, переліченого в `/sys/class/drm`, тож Steam Deck читається як
1280x800. Ширина й висота - цілі числа від 320 до 16384. Apply записує `iSize W`,
`iSize H`, `bFull Screen` і `bBorderless` у копію профілю, після перейняття копії
префікса, якщо профіль її не має. Коли вікно задає SSE Display Tweaks, Apply
записує той самий розмір і режим у його копію в Overwrite; власний файл мода не
змінюється.

Картку Game files угорі вкладки описано в розділі
[Файли гри](#файли-гри-встановлення-з-магазину-або-копія), картку порядку колекції
- у [Збереження порядку колекції](#збереження-порядку-колекції), а Find the mod
behind a problem - у [Тестові запуски](#як-знайти-мод-що-спричиняє-проблему).

### Запуск гри

Щоб запустити гру через вікно, задайте в параметрі запуску Steam для гри
абсолютний шлях до програми, бо Steam не читає `PATH` вашої оболонки
([install.md](install.md#далі-скерувати-на-нього-steam)):

```
~/.local/bin/eidos-gui %command%
```

Для Colony шлях - `~/.local/share/Colony/apps/Eidos/eidos-linux`. Eidos
відкривається на екземплярі гри, тому, яким ви користувалися востаннє, тож
портативний екземпляр знаходиться знову так само, як глобальний; клацніть Run, щоб
запустити її через об'єднаний вигляд.

З увімкненим **Start the game at once when a store opens Eidos** (Preferences,
General, Running a game; типово вимкнено) Eidos пропускає це клацання: він
перевіряє Health і запускає гру, не показуючи свого вікна. Вікно відкривається як
зазвичай, коли Health перелічує проблему, коли список модів потребує уваги, коли
інструмент, налаштований запускатися перед грою, має застарілий вивід або, для
Skyrim SE, Enderal SE і Fallout 4, коли профіль ще не має розміру вікна (вікно тоді
відкривається на Diagnostics). Щоб отримати вікно для одного запуску, поставте
`EIDOS_WINDOW=1` перед командою:
`EIDOS_WINDOW=1 ~/.local/bin/eidos-gui %command%`.

У вікні, яке не відкрив жоден магазин, Run сам не запускає гру, а Eidos ніколи не
запускає гру через Proton чи Wine напряму. Run просить запустити її магазин, що
володіє копією, і магазин запускає Eidos:

- Steam виконує `steam -applaunch <appid>`, коли задано наведений вище параметр
  запуску і гра має Proton-префікс, який Steam створює, коли вперше запускає гру.
  Steam стартує першим, якщо закритий.
- Heroic (копія з GOG чи Epic, нативна чи Flatpak) отримує посилання
  `heroic://launch`, коли Eidos є обгорткою в налаштуваннях гри в Heroic, з
  абсолютним шляхом до `eidos-gui` (або `eidos-linux`) як виконуваним файлом і без
  аргументів. Heroic стартує першим, якщо закритий.
- Legendary окремо виконує `legendary launch <app>`, коли
  `~/.config/legendary/config.ini` має `wrapper =` і абсолютний шлях до `eidos-gui`
  (або `eidos-linux`) у секції гри `[<app>]` або в `[default]`.

Завантажувач script extender, лаунчер і виконуваний файл гри у списку Run так само
передаються магазину, як і `eidos tool <instance> run <entry>` для одного з них у
терміналі. Eidos не може передати деякі копії їхньому магазину, як-от копію з GOG
поза Heroic: тоді Run каже запустити гру з цього магазину.

Передача записує цей екземпляр як той, яким ви користувалися востаннє, а магазин
тоді відкриває на ньому друге вікно Eidos. З вимкненим Start the game at once ви
клацаєте Run там; з увімкненим це вікно запускає гру, не показуючись, якщо його не
відкриває один із наведених вище випадків. Перше вікно за цим запуском не
стежить, тож натисніть у ньому F5 після гри, щоб перечитати його списки. Коли
налаштування магазину немає або завантажувача script extender немає поруч із
виконуваним файлом гри, Run нічого не запускає й показує, що задати і де, зі
справжнім шляхом запущеного бінарного файла.

Поки гра чи інструмент працює, Run стає Stop. Два натискання завершують кожну
програму, яку запустив цей запуск, а Eidos тоді фіксує сесію й демонтує, як після
будь-якого виходу; зупинений запуск ніколи не зараховується як чистий
([troubleshooting.md](troubleshooting.md#гра-чи-інструмент-що-не-закривається)).

`%command%` Steam для ігор Bethesda зазвичай указує на `<Game>Launcher.exe`. Eidos
ніколи його не виконує: лаунчер - окремий застосунок налаштувань, що перескановує
`Data` і переписує `plugins.txt`, скасовуючи щойно розгорнутий порядок
завантаження. Натомість Eidos запускає завантажувач script extender, якщо його
встановлено, інакше бінарний файл гри, і каже про це, коли доводиться відкотитися
на бінарний файл гри.

Eidos скануює DLL увімкнених модів на імпорт `d3dcompiler_47.dll`, копіює DLL від
Microsoft у префікс і лише потім ставить `WINEDLLOVERRIDES=d3dcompiler_47=n,b`;
самому її задавати не потрібно.

### Змінні та обгортки для профілю

Профіль може нести власні змінні середовища й команди-обгортки у
`profiles/<name>/launch-env.ini`, по одному запису на рядок:

```ini
env=PROTON_ENABLE_NVAPI=1
env=DXVK_HUD=fps
wrapper=gamemoderun
wrapper=gamescope -W 1280 -H 800 -f -- %command%
```

Вони діють на кожен `eidos play` цього профілю (гра, запущена `%command%` Steam
або Run у вікні, відкритому магазином) і на кожен запуск інструмента. `eidos shell`
отримує змінні, але не обгортки. Перший рядок `wrapper=` - найзовнішній. Рядок
`wrapper=`, що містить `%command%`, отримує команду на цьому місці, як у
параметрах запуску Steam; рядок без нього отримує команду в кінці. Обгортки
виконуються всередині приватного простору імен Eidos, тож бачать моди.

Змінна тут замінює значення, яке Eidos задає для тієї ж назви, а власний рядок
`env=` інструмента в `tools.ini` замінює обидва. `WINEDLLOVERRIDES` натомість
додається після перевизначень, які Eidos задає для ENB, ReShade і вбудованих DLL,
тож DLL, названа в обох, бере налаштування профілю, а решта зберігає свої.

View -> INI editor відкриває файл як свою останню вкладку, для кожної гри. Порожні
рядки й рядки, що починаються з `#` чи `;`, пропускаються. Збереження перелічує
номери рядків, які Eidos ігнорує: рядки, що не є ні `env=NAME=value`, ні
`wrapper=command`, і рядок `wrapper=`, чиє перше слово - `NAME=value`, як
дозволяють параметри запуску Steam; поставте цю змінну на рядок `env=` натомість.
`eidos play <instance>` без команди перелічує змінні, які отримує запуск, і
обгортки. Copy report у Diagnostics називає змінні та програми-обгортки, без їхніх
значень.

## Інструменти

xEdit, BodySlide, DynDOLOD та інші інструменти працюють через об'єднаний вигляд
усередині Wine-префікса гри (Proton-префікса Steam або того, який Heroic створив
для копії з GOG чи Epic):

```sh
eidos tool skyrimse add BodySlide "<path>/CalienteTools/BodySlide/BodySlide.exe"
eidos tool skyrimse run BodySlide
eidos tool skyrimse run --exe "<path>/GenerateFNISforUsers.exe"  # запустити exe один раз, не реєструючи його
eidos prereqs skyrimse            # що потрібно зареєстрованим інструментам і в якому воно стані
eidos prereqs skyrimse --install  # дістати те, чого бракує
```

Pandora, Nemesis, FNIS, BodySlide, DynDOLOD, TexGen, xLODGen і Synthesis
знаходяться без реєстрації. Pandora, Nemesis, FNIS, BodySlide і Synthesis
приходять з уже заданим модом для перехоплення, тож їхній вивід іде в окремий мод
(подробиці в
[tools.md](tools.md#як-спрямувати-вивід-інструмента-у-власний-мод)).

Назва, яку ви даєте інструментові, вирішує, які середовища виконання й DLL Eidos
для нього забезпечить: `BodySlide` отримає свої бібліотеки DirectX, `BS` - нічого.
У вікні діалог Executables показує справжній стан кожної передумови під полем, а
ті, яких бракує, є кнопками.

Пакет випуску містить інсталятори vcrun2022 (x86 і x64), .NET 8 Desktop Runtime
8.0.12 і середовище виконання .NET 10 10.0.10 у `runtimes/`, а `install.sh`
копіює їх до `~/.local/share/Colony/Eidos/runtimes/`, тож
`eidos prereqs <instance> --install` встановлює їх без завантаження. Eidos тихо
запускає інсталятори vcrun2022 і .NET 8 від Microsoft у префіксі гри, без
winetricks. `eidos-linux` і збірки з джерельних кодів не мають теки `runtimes/`,
тож завантажують ті самі зафіксовані файли від Microsoft. .NET 10 SDK, потрібний
Synthesis (близько 300 МБ), завжди завантажується.

Таблиця, три рівні передумов, чому DynDOLOD потребує середовища виконання .NET,
яке winetricks не вміє встановити, і чому інструмент, встановлений як мод,
запускається з об'єднаного шляху, а не з власної теки, - у [tools.md](tools.md).

## Розширення

Eidos можна розширювати без перезбирання: маніфест TOML у
`~/.config/Colony/Eidos/addons/` додає інструмент до списку Extensions або
перевірку на вкладку Diagnostics. Нічого не завантажується в Eidos: розширення -
це програма, яку він запускає. Див. [extensions.md](extensions.md).

## Спробувати доказ концепції

Скрипту гра не потрібна. Він показує об'єднаний вигляд, copy-on-write, теку гри,
яку не зачеплено, і злиття, що існує лише всередині свого простору імен,
використовуючи лише непривілейований OverlayFS у просторі імен користувача (Linux
5.11 або новіший):

```sh
./scripts/poc-overlay.sh
```
