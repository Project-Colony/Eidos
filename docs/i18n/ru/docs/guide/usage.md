# Использование Eidos

Как пользоваться Eidos: инстанции и копии игры, командная строка, тестовые
запуски, окно, коллекции и обновления Nexus, перенос инстанции на другую машину,
инструменты и расширения. О проблемах - в
[troubleshooting.md](troubleshooting.md); о сборке из исходников и структуре
репозитория - в [../internals/contributing.md](../../../../internals/contributing.md).

## Инстанции: глобальные и портативные

Команды, принимающие инстанцию, принимают идентификатор игры или папку
портативной инстанции. `skyrimse` называет глобальную инстанцию, которую Eidos
хранит в `~/.local/share/Colony/Eidos/instances/skyrimse`. Портативная инстанция -
это самодостаточная папка там, где вы захотите (второй диск, раздел для игр), и её
можно переносить, как портативные инстанции MO2:

```sh
eidos init skyrimse /mnt/games/EidosSkyrim   # создать там портативную инстанцию
eidos install /mnt/games/EidosSkyrim mod.7z  # каждая команда принимает папку
eidos play /mnt/games/EidosSkyrim -- %command%
```

Файл `eidos-instance.ini` в папке называет игру, так что больше папке ничего не
нужно. `EIDOS_INSTANCE=<folder>` в окружении перенаправляет идентификатор игры на
эту папку, например в параметре запуска Steam. Портативные инстанции, которые вы
создали или открыли, запоминаются, самые недавние первыми, в
`~/.config/Colony/Eidos/instances.ini`: их перечисляет экран приветствия окна,
запуск из Steam попадает на ту, в которую вы играли последней, а обработчик
`nxm://` скачивает в неё.

Перенос портативной папки вручную сохраняет всё, кроме записей инструментов,
которые вы зарегистрировали с абсолютными путями в старое место. `eidos pack` и
`eidos unpack` ([ниже](#перенос-инстанции-на-другую-машину)) исправляют их; простой
`mv` - нет. Кэш сред выполнения в `~/.local/share/Colony/Eidos/runtimes/` общий для
всех инстанций на машине, так что хост .NET в 78 МБ не копируется в каждую.

Одно место отклоняется: внутри папки установки игры, куда пользователи MO2 часто
кладут свою инстанцию. Это дерево принадлежит Steam, и обновление, «проверка
целостности» или удаление могут переписать или удалить его вместе с вашей
настройкой. Eidos к тому же монтирует поверх корня игры, так что инстанция внутри
оказалась бы внутри собственной цели монтирования. Мастер, `eidos init`,
`eidos play` и `eidos shell` это отклоняют. Положите папку рядом с игрой; соседняя
папка на том же диске так же удобна.

### Где Eidos хранит свои файлы

Eidos хранит свои файлы в `Colony/Eidos`, в структуре, которую используют все
программы семейства Colony: `~/.config/Colony/Eidos/` для того, что вы выбрали
(настройки, ваша сессия Nexus, список инстанций, определения игр и дополнений,
которые вы написали), `~/.local/share/Colony/Eidos/` для глобальных инстанций
(`instances/`), скачанных сред выполнения и журналов сессий (`logs/`), и
`~/.cache/Colony/Eidos/` для masterlist LOOT, которые скачиваются заново, когда их
нет.

Когда Eidos находит файлы в структуре более старого Eidos (`~/.config/eidos/`,
`~/.local/share/eidos/` и `~/.local/state/`), первый запуск копирует их на новое
место и сообщает об этом в журнале. Глобальная инстанция переносится жёсткими
ссылками, а не побайтовой копией, так что её моды не занимают лишнего места, а
записи её инструментов перенаправляются на новую папку. В старых каталогах
ничего не меняется и не удаляется; удалите их сами, когда новая структура
заработает. Если копию сделать нельзя (диск полон или только для чтения, папка
старой инстанции на другом диске, игра всё ещё работает из неё), Eidos продолжает
использовать старое место и пробует снова при следующем запуске. Параметр запуска
Steam, который всё ещё называет старую папку инстанции, открывает перенесённую.

Жёсткие ссылки экономят место только поначалу. Мод или загрузка, которые вы потом
удалите или переустановите, сохраняют свою старую копию на диске через старую папку
инстанции, а удаление `~/.local/share/eidos/<game>/` возвращает это место.

Портативная инстанция никогда не переносится: она остаётся там, где вы её
положили.

## Командная строка

```sh
eidos games                                # поддерживаемые игры, установленные здесь, как список MO2
eidos init skyrimse [folder]               # создать инстанцию; с папкой она портативная
eidos init skyrimse --game-path <folder>   # использовать копию, установленную в <folder>, когда установлено несколько
eidos install skyrimse mod.7z [name]       # установить архив (Simple, FOMOD, BAIN, OMOD)
eidos install skyrimse mod.7z --replace --backup  # переустановить поверх мода (--merge ставит поверх его файлов)
eidos import skyrimse <mo2-profile>        # перенять порядок модов и состояние плагинов профиля MO2
eidos sort skyrimse [--dry-run]            # отсортировать порядок загрузки через LOOT (--update-masterlist сначала обновляет его)
eidos play skyrimse                        # показать, что будет смонтировано
eidos play skyrimse -- <command>           # выполнить <command> с модами, смонтированными поверх игры
eidos shell skyrimse                       # оболочка в объединённом виде; записи попадают в Overwrite
eidos check skyrimse [--json]              # проверки Health без окна
eidos sessions skyrimse                    # записанные запуски игры и инструментов, сначала новые
eidos sessions skyrimse diff [<id>]        # что изменилось с последнего запуска, завершившегося с кодом 0
eidos stock-game skyrimse                  # какие файлы игры использует инстанция; заморозить копию или переключить
eidos tool skyrimse                        # список инструментов (add, rm и run: см. Инструменты ниже)
eidos tool skyrimse run --exe <path>       # запустить exe один раз через объединённый вид
eidos tool skyrimse import-mo2 [--write]   # исполняемые файлы из ModOrganizer.ini; --write добавляет их
eidos prereqs skyrimse [--install]         # что нужно инструментам; --install скачивает недостающее
eidos collection skyrimse <link>           # установить коллекцию Nexus (--dry-run, --no-optional)
eidos nexus status                         # проверить сохранённый вход в Nexus
eidos nexus update skyrimse [--apply]      # проверить обновления модов; --apply устанавливает их
eidos nxm <link>                           # скачать по ссылке Mod Manager Download
eidos nxm --register                       # заставить кнопку Mod Manager Download на сайте открывать Eidos
eidos export skyrimse -o mods.csv --active # формат CSV из MO2; --active перечисляет только включённые моды
eidos pack skyrimse backup.eidos           # вся инстанция одним файлом
eidos unpack backup.eidos [folder]         # без папки глобальная инстанция возвращается на своё центральное место
eidos --version                            # вывести версию
```

`eidos` без аргументов печатает список команд. Большинство команд печатают свои
параметры, когда не хватает аргумента (`eidos init` и `eidos import` вместо этого
печатают полный список), а `eidos tool --help` перечисляет подкоманды инструмента.
`eidos pack` принимает `--dry-run`, `--level`, `--no-downloads`, `--no-recovery` и
`--force`, а `eidos unpack` принимает `--info` и `--force`; обе описаны
[ниже](#перенос-инстанции-на-другую-машину). `eidos stock-game` описана в разделе
[Файлы игры](#файлы-игры-установка-из-магазина-или-копия).

### Запуск игры через объединённый вид

`eidos play` монтирует моды инстанции поверх собственного каталога `Data` игры
внутри приватного пространства имён, затем выполняет команду через этот вид.
Собственные файлы игры сначала откладываются через bind-монтирование, так что демон
по-прежнему читает их без изменений. Записи (сохранения, пересозданные конфиги)
попадают в слой `overwrite/` инстанции; установка игры и каждая папка мода остаются
байт в байт такими, какими были.

Eidos не нужен root. Он монтирует в приватном пространстве имён пользователя и
монтирования, без setuid-помощника, системной службы и чего-либо, что нужно
выдавать. Необязательная возможность (capability) у бинарного файла `eidos`
разрешает FUSE passthrough, который остаётся выключенным, пока не задан
`EIDOS_FUSE_PASSTHROUGH=1`; см.
[install.md](install.md#необязательно-fuse-passthrough). С этой возможностью Eidos
использует обычное пространство имён монтирования вместо пространства имён
пользователя, а моды разворачиваются одинаково в обоих случаях.

### Оболочка в объединённом виде

`eidos shell <instance>` запускает ваш `$SHELL` (или `/bin/sh`) в папке игры так,
как её увидела бы игра: каждый включённый мод смонтирован поверх `Data`, Root-моды
поверх корня игры, а всё записанное там попадает в Overwrite.
`eidos shell <instance> -- <command>` выполняет вместо этого одну команду, например
`eidos shell skyrimse -- ls Data/meshes` или нативный инструмент вроде NifSkope.
Запуск держит блокировку инстанции, как игровая сессия, поэтому окно не может
сохранять изменения, пока вы не выйдете, и он записывается в `eidos sessions` под
именем `shell`, а не как запуск игры. Ctrl+C на команде останавливает запуск так,
как это делает Stop: Eidos завершает команду, захватывает сессию и размонтирует. В
интерактивной оболочке Ctrl+C, как обычно, принадлежит оболочке; наберите `exit`,
чтобы завершить запуск.

### Проверки Health из терминала

`eidos check <instance>` выполняет проверки Health, которым не нужно окно, так что
их можно запускать по SSH или в Game Mode и прикладывать к отчёту об ошибке:

- префикс Proton и его реестр;
- диагностику плагинов и отсутствующие мастера;
- расширитель скриптов и его плагины;
- обновление игры с последнего чистого запуска;
- параметр запуска Steam;
- настройки графики (NVAPI, полноэкранный режим, ENB);
- лог краха последнего запуска;
- строки `sTestFile` в INI профиля;
- плагины Starfield `.esp` и blueprint;
- `vm.max_map_count` и лимит открытых файлов;
- копию игры, с которой работает инстанция, и `gamePath` в `ModOrganizer.ini`
  списка, называющий другую папку игры;
- правила порядка коллекции, которые больше не выполняются;
- файлы игры на NTFS, exFAT или FAT;
- пути данных BodySlide;
- папки `Data`, оставшиеся в `Overwrite/Root`;
- библиотеки шрифтов, которые называет `Interface/fontconfig.txt` и которых нет ни
  в одном моде;
- сжатый звук в архивах BA2 модов Fallout 4 и Fallout 4 VR.

Некоторые карточки считает только окно, во вкладке Diagnostics: порядок патчей,
скрипты расширителя, которые заменяет мод, архивы, которые ничто не загружает,
требования Nexus, плагины, которые LOOT помечает как грязные, сборку Proton,
которая запускает игру, карточку Display и вывод инструмента, более старый, чем
его входные данные.

Команда печатает те же системные строки, что и Copy report, затем по строке на
каждую находку, причём домашняя папка показана как `~`, а имя для входа как
`<user>`. Код выхода равен 0, если проблем не найдено (одни советы всё равно дают
0), 1, если найдена хотя бы одна проблема, и 2, если Eidos не смог выполнить
проверку: неверные аргументы, инстанция, которую он не может открыть, или игра,
которую он не находит.

`eidos check <instance> --json` вместо этого выводит один JSON-объект. Его поля
верхнего уровня: `eidos` (версия), `game`, `instance`, `system` (`proton`,
`flatpak_steam`, `passthrough`, `session`, `distro`, `kernel`, `dev_fuse`,
`fusermount3`, `max_map_count`, `open_files_hard`) и `findings`. `max_map_count` и
`open_files_hard` содержат числа или `null`, если Eidos не смог их прочитать.
Каждая находка состоит из `code`, `level` (`problem` или `advice`) и её `args`;
вкладка Diagnostics показывает фразу для каждого кода.

### Что изменилось с последнего удачного запуска

Каждый запуск через `eidos play`, `eidos shell` или `eidos tool run`, начатый из
окна, терминала или Steam, пишет запись в `<instance>/logs/sessions/`: профиль,
каждый включённый мод с его версией и идентификаторами файлов Nexus, порядок
плагинов, контрольную сумму каждого INI профиля, версию исполняемого файла игры,
версию Eidos, код выхода и сохранения, которые создал запуск. Хранятся 50
новейших, а `logs/` не входит в упакованную инстанцию.
`eidos sessions <instance> diff` сравнивает новейший запуск игры, завершившийся с
кодом 0, с текущим состоянием; `diff <id>` выбирает другую запись из списка.
Список помечает [тестовый запуск](#тестовые-запуски) как `test`, а тестовый запуск
никогда не выбирается как последний удачный. Остановленный вами запуск записывает
код выхода 143, так что он тоже никогда не выбирается. Eidos пока не определяет
здесь крахи, а игра, упавшая под Proton, всё равно может завершиться с кодом 0: если
выбранный запуск был таким, назовите более ранний командой `diff <id>`.

## Список модов

Как в MO2, у каждого профиля свой `modlist.txt` (какие моды включены и в каком
приоритете), а папки модов лежат в общем `mods/` инстанции. Папка, которую вы
бросили в `mods/` вручную, пока не числится в списке: она появляется выключенной с
самым высоким приоритетом, внизу списка окна, как в MO2, так что выигрывает свои
конфликты, как только вы её включите.

Поскольку папки общие, удаление или переименование мода меняет каждый профиль: его
строка убирается из `modlist.txt` каждого профиля или переименовывается в нём, а
остальное каждый профиль хранит в своём состоянии и порядке. Профиль, оставшийся
без модов, не имеет `modlist.txt` вообще.

Окно работает с собственной копией списка модов и порядка загрузки. Если другой
процесс Eidos записывает любой из них, пока окно открыто (`eidos install` или
`eidos sort` в терминале, коллекция, сессия, которую запустил Steam, второе окно),
следующая правка окна отклоняется, а не перезаписывает эту работу. Оно
перечитывает данные с диска и сообщает *Not saved: another Eidos process changed
the mod list. It has been reloaded - redo the change.* (или то же для порядка
загрузки); теряется только этот один щелчок, так что сделайте его снова. Rename,
New mod, Add separator, Remove и превращение Overwrite в мод проверяют это до того,
как трогать `mods/`, так что отклонённая правка ничего не меняет на диске. Редактор
INI так же отказывается сохранять поверх файла, изменившегося после того, как он
его открыл.

## Сохранения принадлежат профилю

Каждый профиль хранит свои сохранения в `profiles/<name>/saves/`, и на время
запуска эта папка монтируется поверх папки сохранений игры в префиксе Proton.
Первый запуск профиля один раз копирует в него сохранения, которые уже есть в
префиксе, так что сохранение, которое вы позже удалите из профиля, остаётся
удалённым. После каждого запуска новейшие сохранения профиля копируются обратно в
префикс для Steam Cloud; сохранение в префиксе, которое Eidos туда не клал, сначала
сохраняется в профиле как `orphan-<time>-<name>` и никогда не перезаписывается.

Сохранение, которое попадает в префикс после этой первой копии, минуя Eidos
(загрузка Steam Cloud с Steam Deck, запуск без Eidos), остаётся скрытым, пока
сохранения профиля смонтированы. Ничто его не удаляет: запуск называет его в
журнале запуска (`logs/run-*.log` инстанции при запуске из окна, консоль Steam при
запуске через Steam), один раз каждый раз, когда этот набор файлов меняется, а
вкладка Saves считает такие сохранения в строке под своим заголовком. Чтобы
сыграть одно из них, нажмите Import во вкладке Saves. Import копирует каждое
вместе с его косейвом в профиль и никогда не заменяет сохранение профиля:
сохранение, чьё имя профиль уже использует, импортируется как
`orphan-<time>-<name>`.

## Тестовые запуски

Кнопка Test run рядом с Run запускает игру так же, как Run, но всё, что игра
пишет, попадает в `<instance>/test-run/`, а не в ваш профиль, Overwrite и префикс:
новые и изменённые сохранения, изменения INI, `plugins.txt`, файлы, записанные в
Data или в папку игры, и журналы в `Documents/My Games/<game>`. Можно тестировать с
модами профиля, без каких-либо модов или только с выбранными модами, которые
включены, плюс модами, чьи плагины нужны им как мастера.

Когда игра завершается, Eidos перечисляет эти файлы в пяти группах (сохранения,
изменения INI, состояние плагинов, вывод в Overwrite, журналы) и просит оставить
или выбросить каждую. Apply ждёт, пока на каждую группу, в которой есть файлы, не
будет дан ответ. Состояние плагинов не предлагается, если в запуске использовался
другой набор модов, чем у профиля. Сохранение сохранений никогда не удаляет
сохранение из профиля, даже то, которое игра удалила во время запуска. Сохранение
вывода в Overwrite также удаляет из Overwrite файлы, которые удалила игра, и список
сначала подсчитывает их. Выбрасывание чего-либо требует второго нажатия. Decide
later закрывает список и оставляет файлы в `test-run/`, и список открывается снова
при следующем открытии инстанции или нажатии F5. Если Eidos или компьютер
остановился во время тестового запуска, файлы тоже остаются там, и список
открывается так же.

Если окно не было запущено магазином игры, Test run передаёт игру этому магазину
(Steam, Heroic или Legendary), как Run, а запуск, который начинает магазин, и есть
тестовый запуск. Если магазин не запускает игру, запрос ждёт: следующий запуск игры
этого профиля, из Run или из магазина, станет тестовым, а Cancel the waiting test
run его отменяет. Тестовый запуск охватывает только перечисленные выше папки:
другие записи игры, например в реестр Wine, идут туда, куда всегда. Сохранения из
тестового запуска попадают в Steam Cloud только после того, как вы их оставите и
сыграете обычный запуск.

### Поиск мода, вызывающего проблему

Find the mod behind a problem во вкладке Diagnostics ищет мод, вызывающий проблему,
которую вы можете воспроизвести, например вылет в определённом месте. Каждый шаг -
это тестовый запуск с половиной оставшихся подозреваемых, нужными им мастерами и
модами, которые у вас всегда включены: включённые моды, выбранные в списке в момент
начала, и мод, который даёт расширитель скриптов. После каждого запуска вы отвечаете,
случилась ли проблема. Not sure делит подозреваемых по-другому, а Run it again
повторяет шаг. Ответ или Run it again выбрасывает файлы, записанные шагом, после
второго нажатия. Чтобы оставить часть из них, нажмите See the files до ответа:
откроется тот же список, что после тестового запуска. Если игра упала и crash logger
записал лог или игра завершилась с кодом ошибки, Eidos отмечает Yes как вероятный
ответ. 200 подозреваемых требуют примерно 8 запусков.

Поиск сохраняется в `<instance>/bisect.json`, так что между шагами Eidos можно
закрыть, и он принадлежит профилю, в котором начался. Stop the search сбрасывает его
после второго нажатия. Результат называет мод или набор модов, которым нужны мастера
друг друга, и сохраняется в `<instance>/logs/bisect-<time>.txt`. Сгенерированные
моды (вывод Nemesis или DynDOLOD, Bashed Patch) собираются под полный список и могут
не работать с его половиной: оставьте их всегда включёнными или держите выключенными
весь поиск.

## Списки Wabbajack

В Eidos нет установщика Wabbajack. Установите список через CLF3 или Jackify, вне
Eidos, затем выберите папку установки как портативную инстанцию в мастере. Eidos
читает папку так, как её раскладывает MO2: `mods/`, `profiles/<name>/modlist.txt` и
списки плагинов. Он сохраняет `ModOrganizer.ini`, который записал установщик, и
никогда не перезаписывает его, так что собственные исполняемые файлы списка остаются
зарегистрированными.

Многие списки добавляют папку `Stock Game` или `Game Root` с пропатченной копией
игры, и MO2 запускает игру оттуда. Когда мастер или `eidos init` впервые принимает
папку списка, а в ней лежит исполняемый файл игры, инстанция тоже запускает игру
из неё. Игра по-прежнему стартует через Steam или магазин, которому принадлежит,
так что ничего переносить не нужно. Eidos находит папку по `gamePath` в
`ModOrganizer.ini` списка или по этим двум именам. Инстанция, принятая более ранним
Eidos, сохраняет установку из магазина, пока вы её не переключите (см. следующий
раздел). Когда этот `gamePath` называет папку игры, с которой инстанция не
работает, Diagnostics сообщает об этом, потому что инструменты в режиме Mod
Organizer 2, такие как PGPatcher, читают игру оттуда. CLF3 пересобирает файлы BSA и
DDS своими инструментами, так что результат может отличаться от установки
Wabbajack, а авторы списков его не поддерживают.

## Файлы игры: установка из магазина или копия

По умолчанию игра запускается из установки из магазина, папки, в которой её хранит
Steam, Heroic или Legendary. Инстанция может вместо этого запускать копию этой
папки внутри инстанции. Моды лежат поверх копии, а установка из магазина - лишь
место, где Eidos монтирует результат. Игру по-прежнему запускает магазин, так что
Steam сохраняет свой оверлей, кэш шейдеров и облачные сохранения.

Карточка Game files вверху вкладки Diagnostics показывает, какие файлы использует
инстанция, с версией игры копии и установки из магазина, и переключает между ними.
В терминале `eidos stock-game <instance>` печатает те же факты, а `use <folder>`,
`store`, `freeze` и `delete --yes` делают то, что делают кнопки карточки. `freeze`
печатает размер и вид копии, а `freeze --yes` копирует.

Freeze this version копирует установку из магазина в `<instance>/Stock Game` и
запускает игру из неё, так что обновление магазина больше не ломает плагины
расширителя скриптов: обновление меняет установку из магазина, а не копию. Первое
нажатие показывает размер и то, что файловая система с ним сделает, второе
копирует. На файловой системе, которая умеет делить блоки (reflink), такой как
btrfs или XFS, копия почти не занимает места, пока магазин не изменит файл. На ext4
или когда игра и инстанция лежат на разных файловых системах, это полная копия
размером с папку игры. Eidos отказывается, пока Steam сообщает, что игра занята или
установлена не полностью, пока работает игра или инструмент инстанции, когда в
инстанции уже есть копия игры от списка, замороженная копия или незаконченная, и
когда на файловой системе меньше свободного места, чем нужно полной копии. Копии
Heroic и Legendary не проверяются на идущее обновление. Stop, сбой или обновление
игры в Steam во время копирования оставляют `Stock Game.eidos-tmp`, который карточка
предлагает удалить; он никогда не используется.

Копия скрывает каждый файл, который магазин добавляет, меняет или удаляет в папке
игры после создания копии: новые файлы Creation Club, новый исполняемый файл,
новые DLL. Игра, список плагинов, LOOT и проверки Health читают копию. Она не
скрывает того, что происходит вне папки игры: обновление всё равно может при
следующем запуске установить среды выполнения в префикс Proton, а Steam может
переключить игру на другой Proton.

Return to the store version после второго нажатия убирает копию из следующего
запуска. Копия остаётся на диске, а Delete the copy удаляет её, тоже после второго
нажатия. Delete отклоняется, пока инстанция всё ещё работает с копией. Eidos
никогда не удаляет собственную папку `Stock Game` или `Game Root` списка. Если
папка копии пропала или в ней больше нет исполняемого файла игры, запуски
отклоняются, а Diagnostics называет папку, так что версия из магазина никогда не
запустится неожиданно.

Morrowind и Oblivion с `bUseMyGamesDirectory=0` хранят список плагинов в папке игры,
и Eidos пока не запускает их из копии.

## Установка коллекции Nexus

```sh
eidos collection skyrimse nxm://skyrimspecialedition/collections/rqhcxy/revisions/latest
eidos collection skyrimse rqhcxy --dry-run      # прочитать и сказать, что произойдёт
eidos collection skyrimse rqhcxy --no-optional  # пропустить участников, которых она помечает необязательными
```

В окне вставьте ссылку в File -> Open a Nexus collection... или щёлкните по одной
на сайте. Eidos перечисляет участников ревизии, каждого сопоставленного с этой
инстанцией: установлен, скачан или отсутствует. Install this collection выполняет
весь рецепт в рабочем потоке, с индикатором хода, который используют задачи pack и
unpack, и по завершении индикатор становится отчётом. Окно и `eidos collection`
выполняют одну и ту же установку.

Без ссылки File -> Open a Nexus collection... открывается на вкладке Browse. Она
перечисляет коллекции, опубликованные для игры открытой инстанции, по 20 за раз,
отсортированные по числу загрузок, недавнему обновлению или новизне, а поле поиска
сужает список до коллекций, чьё имя или текст совпадает. В каждой строке указаны
автор, последняя ревизия, число модов, загрузки и дата. View открывает последнюю
ревизию этой коллекции на вкладке Link, так же, как вставка её ссылки. Коллекции,
помеченные как для взрослых, исключаются, если ваша учётная запись Nexus не
показывает контент для взрослых, коллекции без рейтинга исключаются всегда, а
строка под списком считает и те, и другие. Просмотр требует учётной записи Nexus с
выполненным входом, как и остальная панель.

Коллекция открывается только для инстанции своей игры. Коллекция Skyrim, открытая
при загруженной инстанции Fallout 4, отклоняется с названием причины, а не
сопоставляет своих участников с чужим списком модов.

### Что Eidos читает из коллекции

Почти ничего из коллекции не видно через API Nexus. Порядок установки, ответы
автора на вопросы скриптового установщика каждого мода, какой мод выигрывает
конфликт файлов, какие плагины где загружаются и бинарные патчи - всё это лежит в
`collection.json` внутри собственного архива коллекции. Скачав те же моды и
установив их с параметрами по умолчанию, вы получите другую игру.

Eidos скачивает архив, читает `collection.json` и применяет его:

| Коллекция говорит | Eidos делает |
| --- | --- |
| `phase` | устанавливает в этом порядке, необязательных участников последними |
| `choices` | воспроизводит ответы автора на каждый FOMOD и сообщает, когда не может |
| `modRules` | переупорядочивает список модов, чтобы нужный мод выигрывал каждый файл |
| `plugins` / `pluginRules` | сливает правила LOOT в ваш userlist и сортирует |
| `INI Tweaks/` | устанавливает их как отдельный мод |
| `tools` | говорит, какие инструменты она ожидает; ничего не создаёт |

Участники включаются по мере установки, в конце списка модов в порядке установки,
до того как `modRules` их переместят. Участник, оставленный вне списка модов, не
загрузился бы, а отчёт этого не показал бы.

Состояние записывается в `<instance>/collections/<slug>-<revision>.state.json` после
каждого участника. Оно лежит рядом с папкой этой ревизии, никогда не внутри неё, так
что коллекция не может поставить свой собственный файл состояния, а установка,
прерванная на участнике 147 из 200, продолжается с 147. Оно пишется под временным
именем и переименовывается на место, так что прерывание оставляет старую запись или
новую и никогда не половину ни той, ни другой. Если его когда-нибудь нельзя
прочитать, Eidos останавливается и говорит об этом, а не начинает всю коллекцию
заново. Выполните ту же команду снова.

Установка более новой ревизии уже имеющейся коллекции перенимает папки предыдущей
ревизии: неизменённый участник проверяется на месте, участник, чей файл автор
обновил, заменяется внутри своей старой папки, а участник, которого новая ревизия
отбросила, остаётся установленным и называется в отчёте, чтобы вы отключили или
удалили его. Папка, которую включает другой профиль, никогда не перенимается,
потому что папка модов общая и этот профиль изменился бы у вас на глазах: новая
ревизия вместо этого устанавливает рядом собственную копию, а отчёт просит
отключить старую в этом профиле, но никогда не удалять её. Возврат к более старой
ревизии забирает её папки тем же способом или устанавливает свежие копии тех,
которые не может забрать. Когда участник заменяется таким образом, а вы меняли или
добавляли файлы в его папке, старая папка сначала сохраняется рядом как
`<name>_backup`, которая никогда не загружается в игру, и отчёт её называет.

Остаток от более ранней ревизии, остающийся включённым, не даёт считать установку
той, что собрал автор; замечание исчезает, когда вы его отключите. Участник,
пропущенный через `--no-optional`, не перенимается и называется так же. Если сам
перенос не удался, запуск останавливается с сообщением *previous revision: its
folders could not be taken over* и причиной; исправьте её и выполните команду снова.

### Бесплатные учётные записи и участники, которых вы скачиваете сами

Бесплатная учётная запись Nexus не может скачать моды-участники. Nexus не даёт
бесплатным учётным записям ссылок на скачивание через API: каждому файлу нужна
собственная кнопка сайта «Mod Manager Download». Архив коллекции скачивается и с
бесплатной учётной записью, так что вы можете прочитать весь рецепт, но каждый
участник сообщается с точным URL своей страницы, чтобы вы скачали его сами, и
повтор этого не меняет. Скачайте их кнопкой сайта и выполните команду снова: этих
участников ищут в `downloads/` при каждом запуске, так что коллекция завершается по
мере того, как вы их предоставляете.

В окне бесплатная учётная запись получает в панели коллекции
*Fetch the N missing required files, one by one* вместо пакетной загрузки. Она
открывает на Nexus страницу первого недостающего обязательного файла, ждёт, пока
этот файл появится в `downloads/`, затем открывает следующую. Кнопку скачивания на
странице для каждого файла вы по-прежнему нажимаете сами. Панель показывает, как
далеко она продвинулась (*3 of 12*), с *Skip* и *Stop*. Когда вместо этого появляется
другой файл того же мода, панель называет оба идентификатора файлов и продолжает
ждать закреплённый. Необязательные участники в этом не участвуют и сохраняют свою
кнопку *Open*.

Eidos также применяет бинарные патчи (каждый проверяется по записанной CRC),
переопределения файлов (названные файлы скрываются через `.mohidden`, как в MO2) и
участников, чьи файлы едут внутри архива коллекции (`bundle`). Участники, которых
коллекция ожидает скачать вручную (`browse`, `manual`), несут собственные
инструкции автора в отчёт. Участник, чьё имя уже есть среди ваших модов,
устанавливается рядом под свободным именем, никогда не поверх, и отчёт говорит,
под каким.

### Отчёт

Участник, чьи ответы установщика не удалось воспроизвести полностью, получает
отдельную строку *installed, but not the way the collection asks*, отдельно от
участников, установленных так, как их собрал автор, потому что его файлы на диске
отличаются от авторских. Отчёт также перечисляет правила порядка, которые не
назвали ничего в коллекции, моды, пойманные в петлю противоречивых правил, группы
LOOT, которых не существует, и любую часть манифеста, которую эта версия Eidos не
понимает.

### Сохранение порядка коллекции

Eidos сохраняет правила каждой установленной коллекции после установки. Когда вы
позже перемещаете два её мода против правила «до» или «после», вкладка Diagnostics
показывает одну карточку для этой коллекции, называя первую такую пару и считая
правила, которые больше не выполняются. Учитываются только моды, включённые в
текущем профиле, а правила, пойманные в петлю, пропускаются, потому что никакой
порядок их сохранить не может. Restore collection order возвращает моды коллекции
в порядок, сохраняющий каждое правило, сохраняет ваш собственный порядок везде, где
правила позволяют, и оставляет моды, которых нет в коллекции, там, где они есть.
Ctrl+Z отменяет это. `eidos check` перечисляет ту же находку как
`collection_order_broken`. Проверка читает рецепт ревизии в `collections/`, так что
коллекция, чей кэшированный рецепт удалён, не проверяется.

## Перенос инстанции на другую машину

`eidos pack` записывает инстанцию целиком (каждый мод, порядок загрузки, все
профили, Overwrite с вашими сохранениями в нём и архивы, из которых всё
устанавливалось) в один файл. `eidos unpack` возвращает её на место:

```sh
eidos pack skyrimse ~/backup.eidos                  # или укажите папку: имя составят игра и дата
eidos unpack ~/backup.eidos /mnt/games/EidosSkyrim  # на другой машине
```

`eidos pack --dry-run` перечисляет, что именно войдёт, что не войдёт и почему, и
сколько места нужно, ничего не записывая. `eidos unpack --info` делает то же для
уже имеющегося у вас файла.

Если 7-Zip не смог что-то прочитать или обход пришлось пропустить то, что вы
ожидаете увидеть в резервной копии (символическую ссылку, папку, которую не удалось
прочитать, имя, которое нельзя безопасно передать 7-Zip), архив всё равно
записывается под выбранным вами именем, но `eidos pack` завершается с кодом 1 и
говорит, чего не хватает, так что скрипт, выполняющий `eidos pack ... && ...`,
останавливается на этом.

Файл `.eidos` - это архив 7-Zip с собственным расширением. 7-Zip и так нужен для
установки мода, так что это не добавляет зависимости, а резервная копия открывается
без Eidos в любом архиваторе, который читает 7-Zip. Он сжат LZMA2 с `-mx1` примерно
до 43 % от оригинала на списке с множеством текстур; `-mx9` занимает намного
дольше и экономит ещё несколько процентов. Текстуры и меши - уже сжатые форматы,
так что больший словарь находит, что ещё сжать, очень мало. `--level` (0, 1, 3, 5, 7
или 9) выбирает другой уровень, а `--no-downloads` исключает `downloads/`.

На уровне 1 по умолчанию файлы складываются в сплошные блоки не больше 16 МБ.
Извлечение одного файла из резервной копии в 70 ГБ декодирует самое большее блок, в
котором он лежит, а не всё, что идёт перед ним, а упаковка игрового содержимого
идёт в 2-5 раз быстрее, чем при сжатии каждого файла отдельно (распаковка - в 2-4
раза). Цена проявляется при повреждении: один испорченный байт может утащить с собой
каждый файл своего блока, до 16 МБ соседних файлов. Это покрывают данные
восстановления, описанные ниже. Все остальные уровни остаются несплошными: каждый
файл - свой поток, и испорченный байт стоит одного этого файла. Уровень 0 только
хранит файлы. Начиная с уровня 3 LZMA2 уже работает кусками в 16 МБ и больше, а
сплошные блоки там измерялись медленнее: на уровне 5 упаковка мешей заняла в 1,4
раза больше времени, а распаковка текстур в 6,8 раза больше.

Упаковка берёт блокировку инстанции, так что не может выполняться, пока игра или
другой Eidos пишет в эту инстанцию, и ничто не меняет инстанцию, пока её читают.
Резервная копия пишется под именем `.part`, сбрасывается на диск и целиком
читается обратно через `7z t`, прежде чем получить выбранное вами имя. Эта проверка
декодирует каждый блок и сверяет каждую контрольную сумму, то есть делает ту же
работу, что распаковка на другой машине. Она показывает, что вернул диск сразу
после записи, а не то, что накопитель сохранит это; для этого служат данные
восстановления ниже. Если она не проходит, `.part` удаляется, под вашим именем
ничего не пишется, а `eidos pack` цитирует строку, где 7-Zip нашёл повреждение.
Прерванная или неудачная упаковка оставляет файл `.part` или ничего, но никогда не
файл `.eidos`, который выглядит завершённым и не является им.

Когда установлен par2cmdline (`sudo pacman -S par2cmdline` в Arch,
`sudo apt install par2` в Debian и Ubuntu, `sudo dnf install par2cmdline` в
Fedora), `eidos pack` также пишет данные восстановления PAR2 рядом с архивом:
`backup.eidos.par2` и несколько файлов `backup.eidos.volNN+MM.par2`, 5 % от
архива плюс небольшой индекс. Держите их в той же папке, что и файл `.eidos`, под
теми именами, с которыми они записаны, и копируйте вместе с ним: резервной копии,
перенесённой без них, не из чего восстанавливаться, а данные восстановления
записывают имя архива, так что переименованная копия им больше не соответствует.
`eidos unpack` находит их по имени и проверяет по ним архив до извлечения чего-либо,
в том числе копию, у которой отрезан конец, так что 7-Zip не может её открыть. Если
несколько байтов испорчены, par2 сначала чинит архив и сохраняет повреждённую копию
как `backup.eidos.1`, для чего нужно свободное место размером с архив в его папке;
повреждение сверх того, что покрывают 5 %, останавливает распаковку до записи
единственного файла. Файлы восстановления, не соответствующие архиву, например от
более старой копии с тем же именем, не используются, когда 7-Zip читает архив и
находит его целым, и распаковка сообщает об этом. На машине без par2 распаковка всё
равно выполняется, с предупреждением, что данные восстановления не использованы.
`--no-recovery` упаковывает без них, а `eidos pack --dry-run` говорит, будут ли они
записаны. `--force` заменяет существующий файл с тем же именем.

### Что в неё не входит и почему

| Исключено | Почему |
| --- | --- |
| Префикс Proton | Он привязан к машине (сопоставления дисков, вид `Z:` *этой* файловой системы), а Eidos пересоздаёт его за минуту командой `eidos prereqs <instance> --install`. Перенос префикса почти удвоил бы архив ради того, что другая машина всё равно должна создать заново. |
| Игра | Инстанция модифицирует игру, которой не содержит. Установите её из Steam на той машине. |
| Инструменты вне инстанции | xEdit, DynDOLOD и другие инструменты - сторонние бинарные файлы со своими установщиками. Они названы в архиве, так что распаковка точно говорит, каких не хватает на новой машине. |
| `logs/`, `.eidos.lock`, `prereqs.done`, `prereqs.log` | Записи машины, сделавшей резервную копию. `prereqs.done` в частности утверждал бы, что библиотеки времени выполнения уже установлены в префиксе, которого нет. |
| `loot/`, кроме `userlist.yaml` | Кэш masterlist, который Eidos скачивает снова по запросу. Ваши собственные правила LOOT в `userlist.yaml` скачать снова нельзя, так что этот единственный файл входит. |
| `.base/`, `.base-root/` | Пустые точки монтирования, где во время сессии откладываются собственные файлы игры. |
| `test-run/`, `bisect.json` | [Тестовый запуск](#тестовые-запуски), ожидающий разбора, и поиск мода, вызывающего проблему, между двумя шагами. Оба относятся к запускам на этой машине. |
| Недописанные файлы | Приостановленная загрузка (`*.unfinished`), атомарная запись на полпути (`*.eidos-tmp*`). |
| Символические ссылки | 7-Zip пошёл бы по ссылке и скопировал то, на что она указывает, а для абсолютной ссылки это означает затягивание постороннего дерева в вашу копию. Вместо этого о них сообщается, а резервная копия считается неполной: `mods/` или `downloads/`, привязанные к другому диску, не упаковываются. Чтобы сделать копию без привязанного `downloads/` намеренно, передайте `--no-downloads` (или снимите флажок *Include downloads/* в окне); намеренное исключение не считается отсутствием. |

Копия игры в инстанции (`Stock Game`) упаковывается, как любая другая папка, так что
резервная копия замороженной инстанции больше на размер игры. Незаконченная копия
(`Stock Game.eidos-tmp`) исключается.

Каждое из этих исключений перечислено с причиной в `eidos-backup.ini` в корне
архива, так что чтение этого файла показывает, что оставлено. Тот же файл
записывает, где инстанция находилась раньше, какой профиль был активен, насколько
велика она в распакованном виде и какие инструменты понадобятся новой машине.

Записи загрузок (`downloads/*.meta`) входят с опустошённой строкой `url=`. Этот URL -
подписанная ссылка Nexus, которая перестаёт работать в течение часов и несёт
`user_id` учётной записи, скачавшей файл, а резервную копию могут передать кому-то
другому. Идентификатор мода, идентификатор файла и версия остаются, так что
загрузку можно найти снова.

### В окне

Оба действия в меню File: *Pack this instance...* и *Unpack a backup...*. Распаковка
есть и на экране приветствия, под списком инстанций, так что машина, у которой ещё
нет инстанции, может распаковать одну.

Прежде чем что-либо записывается, диалог Pack показывает, сколько файлов, насколько
велики, какая часть приходится на `downloads/`, примерно во что выльется архив и
какие инструменты названы, но не переносятся. Его флажок *Write recovery data*
отмечен, когда par2 установлен, и неактивен с названием пакета для установки, когда
нет. Диалог Unpack читает манифест резервной копии, как только вы выбрали файл, так
что до выбора папки может сказать, какую игру она содержит, когда была сделана,
где раньше находилась и каких её инструментов здесь не хватает.

Оба работают в рабочем потоке с индикатором хода, а по завершении индикатор
становится отчётом.

### Что исправляет распаковка

Простая копия папки оставила бы каждую кнопку инструмента указывающей на путь на
старой машине. `eidos unpack` переписывает значения, которые называют корень старой
инстанции, и только их: `exe`, `workdir` и нумерованные ключи `arg` в `tools.ini`, а
также `installationFile` в `meta.ini` каждого мода. Инструмент, который никогда не
был внутри инстанции (`/opt/xedit/SSEEdit.exe`), остаётся ровно таким, как был, и
перечисляется как то, что нужно переустановить; Eidos не гадает, где этот
инструмент на новой машине. Он также исправляет, называет ли инстанция себя
центральной или портативной, так что последующие команды ищут её там, где она теперь.

Распаковка отклоняет непустую папку (передайте `--force`, если хотите
перезаписать), диск, слишком маленький для собственной цифры манифеста, архив,
сделанный более новым Eidos, чем ваш, и любой архив с записью, которая была бы
записана *вне* выбранной вами папки. Без папки резервная копия глобальной
инстанции возвращается на центральное место своей игры; для портативной нужна
папка.

После этого:

```sh
eidos prereqs /mnt/games/EidosSkyrim --install   # пересоздать префикс Proton
eidos play /mnt/games/EidosSkyrim
```

## Окно

Запустите `eidos-gui` или файл `eidos-linux`, который устанавливает Colony.

Первый запуск открывает мастер, как в MO2: приветствие, тип инстанции
(портативная или глобальная), игра, имя и расположение, сводка, затем главное окно.
Экран приветствия также перечисляет все известные инстанции, глобальные и
портативные, последняя использованная первой, чтобы открыть одним щелчком, так что
он служит и переключателем инстанций. Если указать мастеру папку, где уже есть
инстанция, он откроет эту инстанцию как есть, а не создаст новую поверх неё, а
папка, принадлежащая другой игре, отклоняется.

В главном окне две панели: список модов и вкладки Data, Plugins, Conflicts,
Overwrite, Archives, Saves, Downloads и Diagnostics, с кнопкой Run, кнопкой Test run
([Тестовые запуски](#тестовые-запуски)) и выбором цели запуска. Вы фильтруете список
модов, выделяете, переупорядочиваете, группируете разделителями, сужаете по
категории и щёлкаете правой кнопкой для действий. Кроме отправки наверх и вниз, в
меню мода есть направленные перемещения MO2: выше первого конфликтующего мода,
ниже последнего, на заданный приоритет или в группу разделителя.

Выбор профиля переключает профили. Щёлкните профиль правой кнопкой: Rename,
Copy to new..., Desktop shortcut, Import from MO2... и удаление, которое требует
двух щелчков и отклоняет активный или последний профиль. Import from MO2...
перенимает порядок модов и порядок загрузки профиля MO2. Desktop shortcut пишет
запись рабочего стола, которая выполняет
`eidos tool <instance> run "<game>" --profile <name>`: она делает этот профиль
активным и просит магазин запустить игру (подробности в
[tools.md](tools.md#как-добраться-до-инструмента-скрыть-закрепить-ярлык-на-рабочем-столе)).

Меню File также запускает winecfg, regedit, файловый проводник Wine и
деинсталлятор в префиксе игры, а Prefix drive_c открывает диск `C:` префикса; см.
[tools.md](tools.md#собственные-программы-wine-в-префиксе-игры). *Instances...*
перечисляет инстанции, которые знает Eidos; Forget убирает одну из этого списка и
ничего не трогает на диске. *Export the mod list...* записывает список в формате
CSV из MO2, как `eidos export`.

### Preferences

Щёлкните Eidos в левом верхнем углу, чтобы открыть Preferences вместо двух панелей,
и щёлкните снова (или Close), чтобы вернуться. Сначала идут General, Appearance и
Accessibility, как в каждой программе Colony, затем Mod list, Nexus и About. Каждое
изменение применяется и сохраняется сразу; кнопки Save нет.

- General: игра, которую открывает Eidos, размер окна, язык интерфейса, папка
  инструментов и способ запуска игры. Lock the window while a game runs включено по
  умолчанию. Start the game at once when a store opens Eidos и уведомление рабочего
  стола о том, что длинная задача закончилась, пока окно в фоне, по умолчанию
  выключены. Окно говорит по-английски и по-французски; System следует за
  `LC_ALL`, `LC_MESSAGES` или `LANG`, и изменение применяется сразу. Командная
  строка `eidos` всегда отвечает по-английски.
- Appearance: тема (26 семейств, 59 палитр, пергамент Eidos по умолчанию), цвет
  акцента, размер текста, эффекты и живой предпросмотр.
- Accessibility: высокий контраст, шрифт, удобный при дислексии, уменьшенное
  движение и размер текста для чтения, который перемножается с размером из
  Appearance.
- Mod list: скорость автопрокрутки, пока мод перетаскивают к верхнему или нижнему
  краю списка.
- Nexus: вход, папка загрузок, обработчик `nxm://` и его кнопка Register,
  предпочитаемые серверы, Install downloads when they finish и Offline mode.
- About: где лежат файлы, сочетания клавиш, версия и проверка релиза.

Внешний вид и язык интерфейса хранятся в `~/.config/Colony/Eidos/preferences.json`.
Остальные настройки, которые читает и командная строка (игра по умолчанию, папка
инструментов, серверы Nexus, Offline mode и прочее), хранятся в `settings.ini`
рядом с ним, а сессия Nexus - в `nexus.ini`. Тема, которую более старый Eidos
хранил в `settings.ini`, переносится при первом запуске.

About -> Version содержит проверку релиза, включённую по умолчанию. При запуске, не
чаще раза в сутки, Eidos спрашивает у GitHub последний релиз
`Project-Colony/Eidos`. Когда он новее запущенной копии, строка меню показывает
`Eidos <version> is available: release notes` после Help, а ссылка открывает
страницу этого релиза с его списком изменений. Eidos никогда не скачивает и не
заменяет себя. Проверка пропускается в автономном режиме. Она выключена для копии,
установленной в `/usr` менеджером пакетов, который её обновляет; `/usr/local`, куда
`install.sh --system` кладёт Eidos, считается вашей собственной установкой.

### Столбцы, сортировка и группировка

По умолчанию список показывает четыре столбца (Category, Content, Version и Flags,
те же, что показывает MO2) и предлагает восемь: Category, Content, Version, Author,
Installed, Nexus id, Game, Flags. Отметьте их в меню View. При всех восьми для
столбца имён остаётся мало места.

Щёлкните заголовок, чтобы отсортировать по нему, ещё раз, чтобы обратить порядок, и
в третий раз, чтобы вернуться к порядку загрузки. Список можно перетаскивать только
в порядке загрузки: позиция сброса адресует настоящий список, а при сортировке место
строки на экране не её место в этом списке. Пока включена сортировка, полосы вставки
не рисуются, а перетаскивание отклоняется, как в MO2. Меню View говорит об этом и
предлагает путь назад.

Меню View может также сгруппировать весь список по категории или по источнику (с
Nexus или установлен вручную). Заголовки групп не являются разделителями: их нельзя
переименовать, раскрасить или переместить. Они сворачиваются, а свёрнутый заголовок
сохраняет счётчик. Разделители скрыты, пока включена сортировка или группировка,
потому что разделитель возглавляет строки, которые идут за ним в порядке загрузки,
а обе операции меняют этот порядок на экране.

### Мышь и клавиатура

Двойной щелчок по моду открывает Information, Ctrl+двойной щелчок - его папку,
Shift+двойной щелчок - его страницу на Nexus. Ctrl+F ставит курсор в поле
фильтра. Набор буквы переходит к следующему моду, начинающемуся с неё, а повторное
нажатие проходит по остальным, а не остаётся на первом. Ни одно из них не попадает
на строку, скрытую фильтром, свёрнутым разделителем или свёрнутой группой, так что
следующий Space никогда не переключает мод, которого вы не видите.

«Collapse others» в меню разделителя сворачивает каждую группу, кроме этой. Во
время перетаскивания удержание указателя неподвижно над свёрнутой группой
раскрывает её, так что мод можно сбросить внутрь; простое прохождение над ней - нет.

Ctrl+Z отменяет последнее изменение списка модов или порядка загрузки: отметку,
перемещение, пакетное отключение, сортировку LOOT. Ctrl+Shift+Z возвращает его. Окно
хранит 50 шагов и забывает их при F5, в конце запуска игры или инструмента, при
смене профиля и когда другой процесс Eidos меняет список. Установка,
переименование или удаление мода меняет папки на диске, поэтому отмена за пределы
любого из них отклоняется.

### Фильтрация списка

Кнопка Filters открывает по строке на каждый критерий: active, conflicted, update
available, no category, endorsed, tracked, has a Nexus id, has hidden files, no
valid game data, for another game, has notes и по строке на каждый вид содержимого
(плагины, архивы BSA или BA2, текстуры, меши, скрипты, плагины расширителя
скриптов, файлы интерфейса, звук, FaceGen). Щелчок переключает строку по кругу: off,
only и except. Строка вверху переключает между совпадением со всеми включёнными
критериями и совпадением с любым из них. Поле имени и список категорий всегда
дополнительно сужают результат. Строка скрытых файлов смотрит только на включённые
моды.

### Что список сообщает о моде

Два информационных флага, оба - значок с пояснением при наведении. No valid game
data означает, что ничто на верхнем уровне мода не похоже на то, что загружает эта
игра; возможно, его папки нужно поднять на уровень выше, а возможно, это не мод для
этой игры. Another game означает, что собственный `meta.ini` мода называет другую.
Ни один из них ничего не блокирует: мод всё равно разворачивается. «Mark as valid»
в меню строки подавляет любой из них через собственный ключ MO2 `validated=`, так
что мод, отмеченный верным в одном менеджере, не помечается в другом.

Проверка структуры помечает мод, только когда уверена: дерево `Root/`, нечитаемая
папка и пустая папка считаются допустимыми игровыми данными.

### Отключение мода, который нужен вашим сохранениям или другим модам

Прежде чем мод отключается или удаляется, Eidos читает списки плагинов трёх
новейших сохранений профиля. Когда одно из них использует плагин из этого мода,
полоса над списком называет плагины и ждёт Disable anyway или Cancel (Escape тоже
отменяет). Remove добавляет те же имена в своё сообщение о повторном щелчке.
Читаются только сохранения Skyrim и Fallout 4; другие игры отключаются без вопроса.

Вкладка General в Information мода перечисляет моды, которые ему нужны, и моды,
которым нужен он, по мастерам включённых плагинов. При отключении мода, который
нужен другим, появляется та же полоса с Disable them too, которая отключает и
каждый мод, которому он нужен, и моды, которым нужны те, или Keep them enabled. У
карточки отсутствующих мастеров во вкладке Diagnostics есть Enable what provides
them: она включает мод, содержащий каждый недостающий мастер, и отмечает
мастер-плагин, который есть, но не отмечен.

### Резервная копия мода перед правкой

«Back up this mod» копирует его папку в сторону как `<name>_backup` (затем
`_backup2` и так далее; резервная копия никогда не заменяет предыдущую). Копия не
является модом: её флажок ничего не делает, и она ничего не добавляет в объединённый
вид, потому что её включение развернуло бы две копии одного мода друг поверх друга.
«Restore this backup over the mod» возвращает её на место за два щелчка; текущее
содержимое сначала откладывается в сторону и отбрасывается только после успешной
копии.

Backups на панели инструментов хранит точки восстановления списка модов профиля,
его порядка загрузки (`plugins.txt` и `loadorder.txt` вместе) и его игровых INI, по
10 каждого вида, в `<profile>/backups/`. Back up now добавляет одну, а Restore
сначала делает копию текущего состояния, так что ошибочный выбор можно отменить.
Eidos также хранит точку восстановления INI перед каждым запуском BethINI (см.
[tools.md](tools.md#bethini-pie)).

### Вкладки

Data - это дерево объединённого вида, раскрываемое по одному уровню: открытие папки
читает эту папку в каждом слое, где она есть, но никогда не каждый включённый мод
сразу. Оно строится из того же стека слоёв, который обслуживает монтирование, так
что whiteout и скрытые файлы учитываются, а вкладка показывает то, что увидит игра.
Фильтруйте её по имени, сужайте до спорных файлов, разбирайтесь, что где лежит, по
столбцам Size и Modified и показывайте любую строку в файловом менеджере (Reveal).
Наведение на файл перечисляет другие моды, которые его поставляют. Верхнеуровневые
`meta.ini`, `readme.txt`, `fomod/` и `Root/` мода в Data исключены, и в этой вкладке,
и в монтировании: первые три предназначены менеджеру модов, а `Root/` вместо этого
идёт в папку игры. Файл, который игра или инструмент пишет под одним из этих имён,
попадает в Overwrite и остаётся видимым.

У строки `.exe` в Data есть Add tool, который открывает редактор Executables с уже
заполненным файлом (ничего не сохраняется, пока вы не нажмёте Save), и Run, который
запускает его один раз через объединённый вид, как зарегистрированный инструмент
([Инструменты](#инструменты)). Save tree записывает всё объединённое дерево Data в
текстовый файл, по строке на файл с указанием мода, который его поставляет, с
удалёнными домашней папкой и именем пользователя, для отчёта об ошибке.

Plugins - это порядок загрузки ESP/ESM/ESL: переключайте, переупорядочивайте
вручную или сортируйте через LOOT и читайте отчёт после сортировки, ссылки с
советами в котором открываются в браузере. Его заголовок считает включённые
плагины в каждом пространстве индексов против лимита игры, например
`full 231/254, light 512/4096`, и становится оранжевым, когда одно заполнено. Поле
фильтра сужает список по имени. Space, Ctrl+A, диапазоны Shift и пункты меню
строки Activate all shown и Deactivate all shown затем действуют только на
показанные строки, а перетаскивание отклоняется, пока фильтр не очищен. Выбор
плагина подсвечивает его мастера в списке плагинов и мод, который его поставляет,
в списке модов. Плагины, которые LOOT помечает как грязные, получают карточку
Diagnostics, способную очистить их через xEdit
([tools.md](tools.md#очистка-плагина-который-loot-помечает-как-грязный)).

После сортировки LOOT полный плагин, все новые записи которого помещаются в
диапазон лёгких, говорит об этом при наведении, а в меню его строки есть Flag as
light. Eidos пишет копию с флагом light в новый мод с именем `<plugin> (light)` в
конце списка модов (наивысший приоритет) и оставляет оригинал нетронутым, так что
отключение этого мода отменяет изменение. Он отказывается, когда одно из трёх
новейших сохранений профиля загружает плагин как полный. Читаются только
сохранения Skyrim и Fallout 4, так что в Starfield ни одно сохранение не
проверяется. LOOT проверяет только диапазоны записей: прежде чем ставить флаг
плагину, добавляющему ячейки или миры, посмотрите его в xEdit.

Наведение на плагин показывает, откуда он взят, его автора, версию заголовка и
форм, первые 300 символов описания, его мастера и, после сортировки LOOT,
сообщения LOOT. В Skyrim, Skyrim SE, Skyrim VR и Enderal SE игра также читает INI,
названный по загруженному плагину; столбец INI отмечает такие плагины, а щелчок
открывает этот файл только для чтения.

Conflicts объясняет победителей и проигравших по файлам. Overwrite превращает то,
что записала игра, в настоящий мод за один шаг.

Archives перечисляет каждый BSA или BA2, который поставляют включённые моды, мод, из
которого он взят, и причину загрузки: активный плагин с тем же именем или его
регистрирует INI. Тот, который ничто не загружает, помечается как мёртвый груз.
Когда другой мод поставляет архив с тем же именем и выигрывает конфликт, строка
называет этот мод. Extract распаковывает архив в новый мод, названный по нему без
расширения (`Foo.ba2` даёт `Foo (extracted)`), и оставляет архив в его моде;
свободные файлы побеждают файлы в любом архиве, каков бы ни был порядок модов.

Saves читает заголовок каждого сохранения (персонаж, уровень, место, время игры),
сравнивает хранящийся в нём список плагинов с текущим и имеет кнопку, которая
включает нужные ему моды. Сохранения, попавшие в префикс без Eidos, описаны в
разделе [Сохранения принадлежат профилю](#сохранения-принадлежат-профилю).

У Downloads и Diagnostics есть собственные разделы ниже.

### Информация о моде

«Information...» открывает диалог мода со вкладками General, Conflicts, Filetree,
INI Tweaks, Notes, Nexus files и Nexus page. Из filetree (и из дерева Data) любой
файл можно скрыть: он переименовывается в `<name>.mohidden`, что убирает его из
объединённого вида без удаления, так что несколько посторонних файлов одного мода
можно подавить, не меняя приоритеты. Filetree также выполняет обычные операции с
файлами: новая папка, переименование, удаление, открытие. Каждая отклоняет путь,
который не является простым путём внутри этого мода: без `..`, без абсолютного пути
и без символической ссылки по дороге, поскольку переход по ней мог бы удалить файл
вне папки мода. Rename меняет только последнюю часть пути, так что файл никогда не
перемещает, и отклоняет уже занятое имя. Delete требует двух щелчков и не может
быть отменён.

View на любой строке в filetree или в дереве Data показывает файл: изображения,
текст, текстуры DDS (выберите mip, слой, грань и канал) и статические модели NIF с
их диффузными текстурами. Для предпросмотра NIF нужен `eidos-nif-preview` рядом с
Eidos или в `PATH`; он есть в наборе релиза, пакете Arch и сборках из исходников, в
`eidos-linux` его нет. Текст читается до 64 КБ и сообщает, где остановился.

INI Tweaks перечисляет фрагменты, которые мод поставляет в папке `INI Tweaks/`;
включённые сливаются в игровой INI профиля при запуске в порядке приоритета и
убираются обратно, когда INI запуска захватываются, так что отключение правки
убирает её настройки.

Вкладка Nexus files перечисляет файлы мода на Nexus, новейшие первыми, и отмечает
файл, установленный здесь, и тот, что его заменяет. У этой второй строки есть
кнопка Update; см. [Обновления модов](#обновления-модов).

Вкладка Nexus page показывает описание мода и, новейшие первыми, список изменений
каждой версии файла на его странице. Eidos читает оба при первом открытии вкладки
из GraphQL API Nexus, который не расходует почасовой бюджет запросов. Он хранит их,
пока Eidos не закроется или вы не нажмёте Refresh. Они показываются как обычный
текст: форматирование BBCode и HTML убирается, адрес ссылки пишется после её текста,
а изображения и видео опускаются. Endorse и Track над текстом делают то же, что меню
мода по правому щелчку. Страница мода для взрослых остаётся скрытой, если ваша
учётная запись Nexus не показывает контент для взрослых, а страница без рейтинга
скрыта в любом случае.

### Загрузки

Загрузку можно перетащить из списка Downloads на позицию в списке модов, чтобы
установить её с этим приоритетом, и архивы или папки, брошенные на окно из файлового
менеджера, тоже устанавливаются. Для перетаскивания файлов нужна сессия X11 или
XWayland: winit реализует их только для X11. Загрузки можно ставить на паузу и
возобновлять: пауза останавливает передачу и сохраняет частичный файл, а Resume
просит у Nexus свежую ссылку и продолжает с места остановки.

Вкладка Downloads хранит скачанные вами архивы. Фильтруйте её по имени (и по
понятному имени мода, так что «skyui» находит `SkyUI_5_2_SE-12604-5-2SE.7z`),
сортируйте по новизне, имени, размеру или состоянию и скрывайте архив, с которым
закончили: файл остаётся, уходит только строка. «Show hidden» возвращает их, и та
же кнопка снова скрывает. «Remove N installed» удаляет архивы уже установленных
модов, за два щелчка, и только те, которые показывает фильтр.

Preferences -> Nexus -> Install downloads when they finish по умолчанию выключено.
Включённое, оно устанавливает загрузку Nexus, завершившуюся, пока окно открыто, без
захода во вкладку Downloads. Это обычная установка: FOMOD открывает свой
установщик, а имя, которое уже есть в списке модов, спрашивает, что делать. Архивы,
лежавшие в `downloads/` до открытия окна или до включения параметра, не
затрагиваются, как и загрузка, установку которой вы отменили. Пока в панели
коллекции открыта коллекция, никакая загрузка не устанавливается сама, а завершившаяся
в это время не установится сама и позже; коллекция устанавливает своих участников.
Файл, которого ждёт ожидающий Update, устанавливает Update. Так устанавливаются
только загрузки Nexus, а та, которую скрывает фильтр Downloads, ждёт, пока фильтр не
очищен. Пока идёт перетаскивание или пока игра или другой Eidos держит инстанцию,
установка ждёт.

### Обновления модов

Кнопка обновления у правого края панели инструментов проверяет каждый мод, у
которого есть идентификатор Nexus. Когда страница мода показывает установленную у
вас версию, ничего больше не спрашивается. Иначе Eidos читает список файлов мода
(ещё один запрос, сохраняемый до конца проверки) и идёт по цепочке обновлений от
идентификатора файла, записанного в `meta.ini` мода: авторы помечают новую загрузку
как преемника более старой, и MO2 читает ту же цепочку. Более новый файл в этой
цепочке и есть обновление. Когда цепочка никого не называет, а установленный файл
всё ещё указан на странице, мод считается актуальным, даже если страница показывает
другую версию. Версия страницы решает только тогда, когда идентификатор файла не
записан, когда установленный файл удалён или заархивирован или когда Nexus не
прислал список файлов.

Каждый мод использует домен Nexus той игры, которую называет его собственный
`meta.ini` (`gameName`), а не игры инстанции: проверка обновлений, Endorse, Track и
Visit on Nexus идут туда. Enderal SE также принимает моды `skyrimspecialedition`, так
что мод Skyrim SE, установленный в инстанции Enderal SE, проверяется на своей
странице Skyrim SE. Ссылка Mod Manager Download идёт в инстанцию, которой вы
пользовались последней, если её игра принимает домен ссылки. Иначе она идёт в
инстанцию игры, чей собственный это домен, прежде чем в инстанцию игры, которая его
лишь принимает. `EIDOS_INSTANCE=<folder>` переопределяет оба правила.

Track и Untrack в меню мода по правому щелчку добавляют мод в ваши отслеживаемые на
Nexus или убирают его, так что уведомления сайта следуют за тем, что вы отслеживаете
здесь. Endorse и Abstain в том же меню одобряют мод на Nexus или отзывают одобрение;
кнопка одобрения рядом с кнопкой обновления одобряет выбранный мод. Каждая проверка
обновлений также читает ваши одобрения и отслеживаемые моды с Nexus (два запроса) и
приводит флаги Endorsed и Tracked каждого мода в соответствие, на собственном домене
Nexus мода. Когда они расходятся, побеждает Nexus. Если какой-то из списков прочитать
нельзя, проверка говорит об этом и оставляет эти флаги как были.

Кнопка Update на вкладке Nexus files в «Information...» устанавливает более новый
файл. С премиум-аккаунтом Eidos скачивает файл сам. С бесплатным он открывает
страницу файла, где Mod Manager Download отправляет файл обратно, и установка
начинается, когда архив появляется в `downloads/`. Дальше это обычная установка:
FOMOD открывается с ответами, с которыми был установлен мод, затем запрос
предлагает Replace с отмеченным «Keep a backup of the existing mod», что бы вы ни
выбрали в прошлом запросе. Replace сохраняет приоритет и состояние включённости
мода.

Прежде чем Replace подменит папку мода, Eidos сравнивает старую папку с новой по
имени и размеру файла и читает заголовки плагинов в обеих. Это касается Update,
обновления коллекции и Replace, выбранного в запросе установки. Строка состояния
затем считает файлы, добавленные, удалённые и изменённые в размере, и называет
каждого мастера, который нужен новой версии и не был нужен старой. Вкладка General
в «Information...» заканчивается разделом Last update, перечисляющим версии,
добавленные или удалённые плагины, добавленных или удалённых мастеров, плагины, у
которых изменился флаг ESM, ESL или ESH, моды, с которыми этот теперь делит файлы
или больше не делит, и файлы. Файл, переписанный с тем же размером, не
перечисляется. Отчёт хранится в `logs/updates/<mod>.json` в инстанции, который
`eidos pack` исключает; новая установка или Merge в папку его удаляет.
`eidos install --replace` печатает те же счётчики в строке `changes:`.

Папка, содержащая несколько файлов Nexus, например основной файл с влитым в него
необязательным, отклоняется: замена её новым основным файлом потеряла бы остальные.
Обновляйте такие вручную.

`eidos nexus update skyrimse --apply` выполняет ту же проверку, затем на премиум-
аккаунте скачивает каждый новый файл и устанавливает его поверх его папки с
`--replace --backup`. На бесплатном аккаунте вместо этого печатает `OPEN <url>` для
страницы каждого файла. Папки, сливающие несколько файлов, пропускаются с указанием
причины. Мод FOMOD без записанных ответов, например установленный до того, как
Eidos стал их хранить, не переустанавливается с настройками установщика по
умолчанию: это обновление завершается неудачей с сообщением обновить мод один раз
из окна, что записывает ответы. FOMOD, в установщике которого нечего выбирать,
устанавливается как обычно. Команда завершается с кодом 1, если какое-либо
обновление не удалось.

### Обновления коллекций

Когда вы запускаете Check for updates, Eidos также спрашивает у Nexus последнюю
ревизию каждой коллекции, установленной в этой инстанции. Строка над списком модов
называет каждую коллекцию с более новой ревизией и считает добавленные (+),
обновлённые (~) и убранные (-) моды; наведите на неё, чтобы увидеть их имена. Счётчики
отсутствуют, когда рецепт установленной ревизии больше не в кэше. Update открывает
более новую ревизию в панели коллекции, где Install this collection выполняет её.
Список перестраивается при каждой проверке и не сохраняется.

### Настройки Nexus

Preferences -> Nexus -> Offline вообще останавливает обращения Eidos к Nexus и
пропускает ежедневную проверку релиза на GitHub. Проверки обновлений, вход,
загрузки и коллекции сообщают об этом вместо сбоя с ошибкой соединения. По
умолчанию выключено.

Preferred servers ранжирует узлы CDN, которым загрузка отдаёт предпочтение, лучшие
первыми. Больше одного зеркала на выбор выдаётся только премиум-аккаунту, так что
для всех остальных выбирает Nexus, и это ничего не меняет. Когда ни один из
названных вами серверов не предлагается, загрузка всё равно происходит, с первого
узла, который предлагает Nexus.

### Категории

Категории можно назначить одному моду или всему выделению, каталог можно править из
того же диалога, а официальный список категорий игры можно получить с Nexus. Оба
файла каталога - собственные файлы MO2 (`categories.dat` и `nexuscatmap.dat`), так
что общая инстанция хранит один каталог. Мод, скачанный с Nexus, получает категорию
при установке, как только Fetch from Nexus сопоставил каталог.

### Редактор INI, журнал и расширения

View -> INI editor правит игровые INI профиля, ту копию, которую хранит Eidos;
копия в префиксе Proton перезаписывается при каждом запуске. Его последняя вкладка -
`launch-env.ini` профиля
([Переменные и обёртки по профилям](#переменные-и-обёртки-по-профилям)).
View -> Log читает журналы сессий. View -> Extensions перечисляет ваши собственные
дополнения; см. [extensions.md](extensions.md).

Когда запуск не находит главный INI игры (`Skyrim.ini`, `Fallout4.ini`,
`Oblivion.ini`...) ни в профиле, ни в префиксе, Eidos сначала копирует в профиль
значение по умолчанию из папки игры (`Skyrim_Default.ini`, `Fallout4_Default.ini`...),
как MO2. Когда инстанция работает с копией игры, значение по умолчанию берётся из
копии. Префикс и папка игры не меняются.

### Установка модов

Установщик обрабатывает простые архивы, FOMOD, пакеты Wrye Bash BAIN (отметьте
подпакеты, которые сливаются по порядку) и пакеты OMOD для Oblivion. Скрипт OMOD
выполняется, если он использует поддерживаемые Eidos команды OBMM или является
одним из трёх известных Eidos установщиков на C#; никакой другой код C# или Visual
Basic Eidos не выполняет и говорит об этом. Когда ни одна эвристика не узнаёт
структуру, ручной выбор показывает дерево архива и позволяет указать корень данных.

Переустановка или обновление мода FOMOD открывает мастер с отмеченными ответами
его последней установки, на первом шаге, чьи параметры изменились с тех пор, с
перечнем изменений. Reinstall with new choices вместо этого начинает с настроек
установщика по умолчанию. `eidos install --replace` или `--merge` использует
сохранённые ответы и отказывается, перечисляя изменения, когда они больше не
подходят.

### Диагностика

Вкладка Diagnostics выполняет живые проверки состояния. Она сообщает об
отсутствующих мастерах, плагинах, которые LOOT помечает как грязные, архивах,
которые не загрузит ни один активный плагин, о том, соответствует ли список модов
папке модов, включён ли FUSE passthrough и, когда он запрошен, есть ли нужная для
запуска возможность. После запуска она показывает, что собственный журнал
расширителя скриптов говорит о каждой DLL его плагинов, так что видно, загрузились
ли ваши плагины SKSE. Она также сообщает об обновлении игры с последнего чистого
запуска, отсутствующем расширителе скриптов или таком, который не соответствует
версии игры (со страницей загрузки расширителя и кнопкой установки скачанного
архива), параметре запуска Steam, который не запускает Eidos через `%command%`,
оставленном выключенным NVAPI для DLSS, эксклюзивном полноэкранном режиме, который
останавливает генерацию кадров, `enblocal.ini` ENB без `LinuxVersion=true`,
объявлениях плагинов F4SE и SFSE и логе краха последней сессии с названными в нём
модами.

Проверки INI профиля и плагинов ищут строки `sTestFile` в `[General]` пользовательских
INI Fallout 4, Fallout 4 VR и Starfield, из-за которых игра игнорирует `plugins.txt`
(Fix удаляет их из копии профиля и сохраняет прежний файл как `<ini>.pre-fix`),
включённые плагины `.esp` в
Starfield и плагины blueprint, у которых нет флага blueprint, префикса
`BlueprintShips-` или расширения `.esm`, либо чей главный плагин не включён.
Системные проверки помечают `vm.max_map_count` или жёсткий лимит открытых файлов
ниже того, что нужно Proton, а также игру, префикс или инстанцию на NTFS, exFAT или
FAT. Проверки модов называют путь данных BodySlide, когда он не указывает на `Data`
игры, папки `Data`, которые инструмент записал в `Overwrite/Root`, патч, чьи
свободные файлы проигрывают моду, который он патчит, и мод, заменяющий скрипты
Papyrus расширителя скриптов.

Check for updates также читает требования Nexus каждого мода. Diagnostics перечисляет
требуемый мод, который отсутствует или отключён, с Ignore для требования,
выполненного иначе.

Вкладка также показывает, какая сборка Proton запускает игру, и предупреждает, прежде
чем более старый Proton запустит префикс, подготовленный более новым; Rebuild
отодвигает сломанный префикс в сторону, чтобы Steam создал новый
([troubleshooting.md](troubleshooting.md#какой-proton-запускает-игру-и-сломанный-префикс)).
Другие карточки помечают префикс, который так и не был настроен или чей реестр
устарел, программу, отличную от Eidos, получающую ссылки Mod Manager Download
(Register это исправляет), вывод инструмента, более старый, чем его входные данные (с
кнопкой, которая запускает инструмент снова), и очищенную или лёгкую копию плагина,
чей оригинал с тех пор изменился. Каждая карточка объяснена в
[troubleshooting.md](troubleshooting.md#карточки-health). Copy report помещает в
буфер обмена отчёт о системе и каждой находке, со скрытыми домашней папкой и именем
для входа, для отчёта об ошибке.

Для Skyrim SE, Enderal SE и Fallout 4 в Diagnostics есть также карточка Display. Она
показывает размер и режим окна, заданные в `SkyrimPrefs.ini` профиля
(`EnderalPrefs.ini`, `Fallout4Prefs.ini`) или в копии префикса, если у профиля пока
нет своей. Когда размер не задан нигде, её поля начинают с самого большого
подключённого экрана из `/sys/class/drm`, так что Steam Deck читается как 1280x800.
Ширина и высота - целые числа от 320 до 16384. Apply записывает `iSize W`,
`iSize H`, `bFull Screen` и `bBorderless` в копию профиля, сначала приняв копию
префикса, если у профиля её нет. Когда окно задаёт SSE Display Tweaks, Apply
записывает тот же размер и режим в его копию в Overwrite; собственный файл мода не
меняется.

Карточка Game files вверху вкладки описана в разделе
[Файлы игры](#файлы-игры-установка-из-магазина-или-копия), карточка порядка
коллекции - в разделе [Сохранение порядка коллекции](#сохранение-порядка-коллекции),
а Find the mod behind a problem - в разделе
[Поиск мода, вызывающего проблему](#поиск-мода-вызывающего-проблему).

### Запуск игры

Чтобы запускать игру через окно, задайте в параметре запуска Steam для игры
абсолютный путь к программе, потому что Steam не читает `PATH` вашей оболочки
([install.md](install.md#затем-указать-на-него-steam)):

```
~/.local/bin/eidos-gui %command%
```

Из Colony путь - `~/.local/share/Colony/apps/Eidos/eidos-linux`. Eidos открывается
на инстанции игры, той, которой вы пользовались последней, так что портативная
инстанция находится снова, как и глобальная; нажмите Run, чтобы запустить через
объединённый вид.

При включённом Start the game at once when a store opens Eidos (Preferences,
General, Running a game; по умолчанию выключено) Eidos пропускает этот щелчок:
проверяет Health и запускает игру, не показывая окна. Окно открывается как обычно,
когда Health показывает проблему, когда список модов требует внимания, когда у
инструмента, настроенного на запуск перед игрой, устарел вывод или, для Skyrim SE,
Enderal SE и Fallout 4, когда у профиля ещё нет размера окна (тогда окно открывается
на Diagnostics). Чтобы получить окно для одного запуска, поставьте `EIDOS_WINDOW=1`
перед командой: `EIDOS_WINDOW=1 ~/.local/bin/eidos-gui %command%`.

В окне, которое не открывал магазин, Run не запускает игру сам, и Eidos никогда не
запускает игру через Proton или Wine напрямую. Run просит магазин, которому
принадлежит копия, запустить её, а магазин запускает Eidos:

- Steam выполняет `steam -applaunch <appid>`, когда задан параметр запуска выше и у
  игры есть префикс Proton, который Steam создаёт при первом запуске игры. Steam
  запускается первым, если он закрыт.
- Heroic (копия из GOG или Epic, нативный или Flatpak) получает ссылку
  `heroic://launch`, когда Eidos задан обёрткой в настройках игры в Heroic, с
  абсолютным путём к `eidos-gui` (или `eidos-linux`) в качестве исполняемого файла и
  без аргументов. Heroic запускается первым, если он закрыт.
- Legendary сам по себе выполняет `legendary launch <app>`, когда в
  `~/.config/legendary/config.ini` есть `wrapper =` с абсолютным путём к
  `eidos-gui` (или `eidos-linux`) в секции игры `[<app>]` или в `[default]`.

Загрузчик расширителя скриптов, лаунчер и исполняемый файл игры в списке Run
передаются магазину таким способом, как и `eidos tool <instance> run <entry>` для
одного из них в терминале. Некоторые копии Eidos не может передать их магазину,
например копию из GOG вне Heroic: тогда Run говорит запустить игру из этого
магазина.

Передача записывает эту инстанцию как последнюю использованную, а магазин затем
открывает на ней второе окно Eidos. При выключенном Start the game at once вы
нажимаете Run там; при включённом это окно запускает игру, не показывая себя, если
только один из случаев выше не открывает его. Первое окно этот запуск не
отслеживает, так что нажмите в нём F5 после игры, чтобы перезагрузить его списки.
Когда настройки магазина нет или загрузчика расширителя скриптов нет рядом с
исполняемым файлом игры, Run ничего не запускает и показывает, что и где нужно
задать, с настоящим путём запущенного бинарного файла.

Пока игра или инструмент работает, Run становится Stop. Два нажатия завершают все
программы, запущенные этим запуском, а Eidos затем захватывает сессию и
размонтирует, как после любого выхода; остановленный запуск никогда не считается
чистым запуском
([troubleshooting.md](troubleshooting.md#игра-или-инструмент-которые-не-закрываются)).

`%command%` Steam для игр Bethesda обычно указывает на `<Game>Launcher.exe`. Eidos
никогда его не запускает: лаунчер - это отдельное приложение настроек, которое
пересканирует `Data` и переписывает `plugins.txt`, отменяя только что развёрнутый
порядок загрузки. Вместо него Eidos запускает загрузчик расширителя скриптов, если
он установлен, а иначе бинарный файл игры, и сообщает об этом, когда приходится
откатываться на бинарный файл игры.

Eidos сканирует DLL включённых модов на импорт `d3dcompiler_47.dll`, копирует DLL
Microsoft в префикс и только затем задаёт `WINEDLLOVERRIDES=d3dcompiler_47=n,b`;
задавать её самому не нужно.

### Переменные и обёртки по профилям

Профиль может нести собственные переменные окружения и команды-обёртки в
`profiles/<name>/launch-env.ini`, по одной записи на строку:

```ini
env=PROTON_ENABLE_NVAPI=1
env=DXVK_HUD=fps
wrapper=gamemoderun
wrapper=gamescope -W 1280 -H 800 -f -- %command%
```

Они применяются к каждому `eidos play` этого профиля (игра, запущенная `%command%`
Steam, или Run в окне, которое открыл магазин) и к каждому запуску инструмента.
`eidos shell` получает переменные, но не обёртки. Первая строка `wrapper=` -
самая внешняя. Строка `wrapper=`, содержащая `%command%`, получает команду на этом
месте, как в параметрах запуска Steam; строка без неё получает команду в конце.
Обёртки работают внутри приватного пространства имён Eidos, так что видят моды.

Переменная здесь заменяет значение, которое Eidos задаёт для того же имени, а
собственная строка `env=` инструмента в `tools.ini` заменяет оба.
`WINEDLLOVERRIDES` вместо этого добавляется после переопределений, которые Eidos
задаёт для ENB, ReShade и встроенных DLL, так что DLL, названная в обоих, получает
настройку профиля, а остальные сохраняют свои.

View -> INI editor открывает файл последней вкладкой, для каждой игры. Пустые строки
и строки, начинающиеся с `#` или `;`, пропускаются. Сохранение перечисляет номера
строк, которые Eidos игнорирует: строки, не являющиеся ни `env=NAME=value`, ни
`wrapper=command`, и строка `wrapper=`, чьё первое слово - `NAME=value`, как
допускают параметры запуска Steam; поместите эту переменную в строку `env=`.
`eidos play <instance>` без команды перечисляет переменные, которые получает запуск,
и обёртки. Copy report в Diagnostics называет переменные и программы-обёртки без их
значений.

## Инструменты

xEdit, BodySlide, DynDOLOD и другие инструменты запускаются через объединённый вид
внутри Wine-префикса игры (Proton-префикса Steam или префикса, который настроил
Heroic для копии из GOG или Epic):

```sh
eidos tool skyrimse add BodySlide "<path>/CalienteTools/BodySlide/BodySlide.exe"
eidos tool skyrimse run BodySlide
eidos tool skyrimse run --exe "<path>/GenerateFNISforUsers.exe"  # запустить exe один раз, не регистрируя его
eidos prereqs skyrimse            # что нужно зарегистрированным инструментам и их состояние
eidos prereqs skyrimse --install  # скачать всё недостающее
```

Pandora, Nemesis, FNIS, BodySlide, DynDOLOD, TexGen, xLODGen и Synthesis находятся без
регистрации. Pandora, Nemesis, FNIS, BodySlide и Synthesis приходят с уже заданным
модом для перехвата, так что их вывод попадает в собственный мод (подробности в
[tools.md](tools.md#вывод-инструмента-в-его-собственный-мод)).

Название, которое вы даёте инструменту, определяет, какие среды выполнения и DLL
Eidos для него подготавливает: `BodySlide` получает свои библиотеки DirectX, `BS` не
получает ничего. В окне диалог Executables показывает настоящее состояние каждого
prerequisite под полем, а отсутствующие - это кнопки.

Набор релиза несёт установщики vcrun2022 (x86 и x64), .NET 8 Desktop Runtime 8.0.12
и среду .NET 10 10.0.10 в `runtimes/`, а `install.sh` копирует их в
`~/.local/share/Colony/Eidos/runtimes/`, так что `eidos prereqs <instance> --install`
устанавливает их без скачивания. Eidos запускает установщики vcrun2022 и .NET 8 от
Microsoft тихо в префиксе игры, без winetricks. В `eidos-linux` и сборках из
исходников папки `runtimes/` нет, поэтому они скачивают те же зафиксированные файлы
с сайта Microsoft. .NET 10 SDK, нужный Synthesis (около 300 МБ), всегда
скачивается.

Таблица, три вида prerequisites, почему DynDOLOD нужна среда .NET, которую не может
установить winetricks, и почему инструмент, установленный как мод, запускается по
объединённому пути, а не из своей папки, описаны в [tools.md](tools.md).

## Расширения

Eidos можно расширять без пересборки: манифест TOML в
`~/.config/Colony/Eidos/addons/` добавляет инструмент в список Extensions или
проверку во вкладку Diagnostics. В Eidos ничего не загружается: расширение - это
программа, которую он запускает. См. [extensions.md](extensions.md).
