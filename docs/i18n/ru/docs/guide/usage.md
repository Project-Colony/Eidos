# Использование Eidos

Практическое руководство: командная строка, GUI, параметр запуска Steam, сборка
из исходников и скрипт proof of concept. Что делать, когда что-то выглядит не
так, - в [troubleshooting.md](troubleshooting.md).

## Как пользоваться (CLI)

```sh
eidos games                       # поддерживаемые игры, установленные здесь (как список MO2)
eidos init skyrimse               # создать инстанцию для модов
# ...кладите каждый мод папкой в <instance>/mods/ (глобальная инстанция лежит
#    в ~/.local/share/Colony/Eidos/instances/skyrimse; `eidos init` печатает вашу)...
eidos install skyrimse mod.7z     # или установить скачанный архив (Simple / FOMOD)
eidos import skyrimse <mo2-profile>  # перенять порядок и состояние плагинов существующего профиля MO2
eidos sort skyrimse               # отсортировать порядок загрузки плагинов через LOOT
eidos play skyrimse               # показать, что будет смонтировано
eidos play skyrimse -- <command>  # запустить <command> с модами, смонтированными поверх игры
eidos shell skyrimse              # оболочка в объединённом представлении, записи попадают в Overwrite
eidos check skyrimse              # проверки здоровья без окна (--json для скриптов)
eidos sessions skyrimse           # записанные запуски игры и инструментов, сначала новые
eidos sessions skyrimse diff      # что изменилось с последнего запуска, завершившегося с кодом 0
eidos collection skyrimse <link>  # установить коллекцию Nexus так, как её собрал автор
eidos nexus update skyrimse --apply  # установить файлы Nexus, которые заменили ваши
eidos pack skyrimse backup.eidos  # вся инстанция одним файлом, чтобы перенести её в другое место
eidos unpack backup.eidos <folder>   # вернуть её обратно на другой машине
```

`eidos tool`, `eidos prereqs`, `eidos nexus`, `eidos nxm` и `eidos export`
дополняют набор; запустите `eidos` без аргументов, чтобы увидеть полный список.

### Проверки здоровья из терминала

`eidos check <instance>` выполняет проверки префикса, плагинов, отсутствующих мастер-файлов и расширителя скриптов из вкладки **Diagnostics**, не открывая окна, так что их можно запускать по SSH или в Game Mode и прикладывать к отчёту об ошибке. Команда выводит те же системные строки, что и **Copy report**, затем по строке на каждую находку; домашняя папка при этом показана как `~`, а имя пользователя как `<user>`. Код выхода равен 0, если проблем не найдено (одни советы всё равно дают 0), 1, если найдена хотя бы одна проблема, и 2, если Eidos не смог выполнить проверку: неверные аргументы, инстанция, которую он не может открыть, или игра, которую он не находит.

`eidos check <instance> --json` вместо этого выводит один JSON-объект. Его поля верхнего уровня: `eidos` (версия), `game`, `instance`, `system` (`proton`, `flatpak_steam`, `passthrough`, `session`, `distro`, `kernel`, `dev_fuse`, `fusermount3`, `max_map_count`, `open_files_hard`) и `findings`. `max_map_count` и `open_files_hard` содержат числа или `null`, если Eidos не смог их прочитать. Каждая находка состоит из `code`, `level` (`problem` или `advice`) и её `args`; вкладка Diagnostics показывает фразу для каждого кода.

### Оболочка в объединённом представлении

`eidos shell <instance>` запускает ваш `$SHELL` (или `/bin/sh`) в папке игры в том виде, в каком её увидела бы игра: каждый включённый мод смонтирован поверх `Data`, моды Root - поверх корня игры, а всё, что туда записывается, попадает в Overwrite. `eidos shell <instance> -- <command>` вместо этого выполняет одну команду, например `eidos shell skyrimse -- ls Data/meshes` или нативный инструмент вроде NifSkope. Запуск держит блокировку инстанции, как игровая сессия, поэтому окно не сможет сохранять изменения, пока вы не выйдете, а в `eidos sessions` он записан под именем `shell`, никогда как запуск игры. Ctrl+C во время команды останавливает запуск так же, как Stop: Eidos завершает команду, фиксирует сессию и размонтирует представление. В интерактивной оболочке Ctrl+C, как обычно, принадлежит оболочке; чтобы завершить запуск, введите `exit`.

### Инстанции: глобальные и портативные

Каждая команда выше обращается к инстанции. `skyrimse` называет **глобальную** -
она хранится централизованно в `~/.local/share/Colony/Eidos/instances/skyrimse` и управляется
Eidos. Второй вид - **портативная**: самодостаточная папка где угодно (второй
диск, раздел с играми), переносимая и изолированная, ровно как портативные
инстанции MO2. Везде, где команда принимает идентификатор игры, она принимает и
папку портативной инстанции:

```sh
eidos init skyrimse /mnt/games/EidosSkyrim   # создать там портативную инстанцию
eidos install /mnt/games/EidosSkyrim mod.7z  # любая команда принимает папку
eidos play /mnt/games/EidosSkyrim -- %command%
```

Папка описывает себя сама (её `eidos-instance.ini` называет игру), так что
больше ничего не нужно - а `EIDOS_INSTANCE=<folder>` в окружении перенаправляет
идентификатор игры на эту папку, что удобно в параметрах запуска Steam.
Портативные инстанции, которые вы создали или открывали, запоминаются (последняя
использованная первой) в `~/.config/Colony/Eidos/instances.ini`; экран
приветствия GUI показывает их для открытия в один клик, запуск из Steam попадает
на ту, в которую вы играли последней, а обработчик `nxm://` качает в неё. Две
оговорки, о которых стоит знать: при переносе портативной папки вручную
сохраняется всё, кроме записей об инструментах, зарегистрированных абсолютными
путями в старое место (`eidos pack` / `eidos unpack`, ниже, чинят их за вас;
простой `mv` - нет), а общий кэш рантаймов
(`~/.local/share/Colony/Eidos/runtimes/`) намеренно остаётся общемашинным -
хост .NET на 78 МБ не бывает по одному на инстанцию.

Свои файлы Eidos держит под `Colony/Eidos` - в раскладке, которой пользуется
каждая программа семейства Colony: `~/.config/Colony/Eidos/` для того, что вы
выбрали (настройки, ваша сессия Nexus, список инстанций, написанные вами
определения игр и дополнений), `~/.local/share/Colony/Eidos/` для глобальных
инстанций (`instances/`), скачанных сред выполнения и логов сессий (`logs/`) и
`~/.cache/Colony/Eidos/` для мастер-списков LOOT, которые скачиваются заново,
как только их нет.

Старый Eidos держал это в `~/.config/eidos/`, `~/.local/share/eidos/` и
`~/.local/state/`. Первый запуск после обновления **копирует** их и сообщает об
этом в логе. Глобальная инстанция переносится жёсткими ссылками, а не побайтовой
копией, поэтому десятки гигабайт модов переезжают мгновенно и не занимают
лишнего места, а её записи инструментов перенаправляются на новую папку. Старые
каталоги остаются ровно такими, какими были - ничего не удаляется, поэтому
неудачное обновление не может стоить вам ни входа в аккаунт, ни сохранения, - и
вы можете убрать их сами, когда убедитесь, что всё в порядке. Если копию сделать
не удаётся (диск заполнен или доступен только для чтения, старая папка инстанции
лежит на другом диске, из неё всё ещё запущена игра), Eidos продолжает
пользоваться старым местом и пробует снова при следующем запуске. Параметр
запуска Steam, который всё ещё указывает на старую папку инстанции, открывает
перенесённую.
Лишнего места перенос не занимает только поначалу: мод или загрузка, которые вы
потом удалите или переустановите, сохраняют старую копию на диске через старую
папку инстанции, так что вернуть это место можно, только удалив
`~/.local/share/eidos/<game>/`.

Портативная инстанция никогда не переносится: она остаётся там, куда вы её
положили.

Одно место запрещено наотрез: **внутри папки установки игры** (рефлекс ветерана
MO2). Этим деревом владеет Steam - обновление, «проверка целостности» или
удаление могут переписать или стереть его вместе со всей вашей сборкой, - а Eidos
монтирует поверх корня игры, так что инстанция внутри оказалась бы внутри
собственной точки монтирования. Мастер, `eidos init` и `eidos play` все говорят
нет; кладите папку РЯДОМ с игрой (сосед на том же диске даёт то же удобство).

`play` монтирует моды инстанции поверх собственного каталога `Data` игры (через
bind-stash, так что демон по-прежнему читает нетронутые файлы) внутри приватного
пространства имён, а затем запускает команду через этот вид. Записи (сохранения,
перегенерированные конфиги) попадают в слой `overwrite/` инстанции; установка
игры и все исходники модов остаются нетронутыми байт в байт.

### Списки Wabbajack

В Eidos нет установщика Wabbajack. Установите список с помощью CLF3 или Jackify вне Eidos, затем выберите папку установки в мастере как переносимый экземпляр. Eidos читает папку в структуре MO2: `mods/`, `profiles/<имя>/modlist.txt` и списки плагинов. Файл `ModOrganizer.ini`, записанный установщиком, сохраняется и никогда не перезаписывается, поэтому собственные программы списка остаются зарегистрированными.

Многие списки добавляют папку `Stock Game` или `Game Root` с изменённой копией игры, и MO2 запускает игру оттуда. Eidos запускает установку из Steam и не имеет настройки для другой папки игры. Если мастер находит такую папку, он сообщает об этом на экране итогов и больше ничего не делает: файлы, которые список туда положил, перенесите сами в папку `Root/` какого-нибудь мода. CLF3 пересобирает файлы BSA и DDS своими инструментами, поэтому результат может отличаться от установки Wabbajack, а авторы списков его не поддерживают.

### Список модов

Как и в MO2, у каждого профиля свой `modlist.txt` (какие моды включены и с каким
приоритетом), а папки модов лежат в общей для инстанции `mods/`. Папка, которую
вы положили в `mods/` вручную, ещё не внесена в список: она появляется
**выключенной с наивысшим приоритетом** - внизу списка в окне, куда её ставит и
MO2, - так что, как только вы её включите, она выигрывает свои конфликты. Старые
версии ставили её наверх, где её перекрывал любой другой мод.

Поскольку папки общие, удаление или переименование мода меняет все профили: его
строка удаляется из `modlist.txt` каждого профиля или переименовывается в нём, а
во всём остальном каждый профиль сохраняет собственное состояние и порядок. У
профиля, в котором не осталось модов, `modlist.txt` нет вовсе, а не лежит
пустым: пустой читался как повреждённый файл и блокировал следующую установку.

Окно работает с собственной копией списка модов и порядка загрузки. Если другой
процесс Eidos записывает любой из них, пока окно открыто, - `eidos install` или
`eidos sort` в терминале, коллекция, сессия, запущенная Steam, второе окно, -
следующая правка в окне отклоняется, вместо того чтобы перезаписать эту работу.
Окно перечитывает данные с диска и сообщает *Not saved: another Eidos process
changed the mod list. It has been reloaded - redo the change.* (или то же самое
про порядок загрузки); теряется только этот один клик, так что сделайте его ещё
раз. Rename, New mod, Add separator, Remove и превращение Overwrite в мод
выполняют проверку до того, как тронуть `mods/`, так что отклонённая правка
ничего не меняет на диске. Редактор INI точно так же отказывается сохранять
поверх файла, который изменился с тех пор, как он его открыл.

### Сохранения принадлежат профилю

Каждый профиль хранит собственные сохранения в `profiles/<name>/saves/`, и на
время запуска эта папка монтируется поверх папки сохранений игры в
Proton-префиксе. Первый запуск профиля один раз копирует в неё сохранения, которые
уже лежат в префиксе, так что сохранение, которое вы потом удалите из профиля,
остаётся удалённым. После каждого запуска самые новые сохранения профиля
копируются обратно в префикс для Steam Cloud; сохранение в префиксе, которое
положил туда не Eidos, сначала сберегается в профиле как `orphan-<time>-<name>`
и никогда не перезаписывается.

Сохранение, которое попало в префикс после этого первого копирования в обход
Eidos, - загрузка из Steam Cloud со Steam Deck, запуск без Eidos, - остаётся
скрытым, пока смонтированы сохранения профиля. Ничто его не удаляет: запуск
называет его в логе этого запуска (`logs/run-*.log` инстанции при запуске из
окна, консоль Steam при запуске из Steam), по одному разу при каждом изменении
этого набора файлов. Чтобы продолжить игру с него, нажмите Import на вкладке
Saves. Import копирует его вместе с его co-save в профиль и никогда не заменяет
сохранение профиля.

### Что изменилось с последнего удачного запуска

Каждый запуск через `eidos play` или `eidos tool run`, из окна, терминала или Steam, пишет запись в `<instance>/logs/sessions/`: профиль, каждый включённый мод с версией и id файлов Nexus, порядок плагинов, контрольную сумму каждого INI профиля, версию исполняемого файла игры, версию Eidos, код выхода и сохранения, созданные за запуск. Хранятся 50 последних, а `logs/` не попадает в упакованный экземпляр. `eidos sessions <instance> diff` сравнивает последний запуск игры с кодом выхода 0 с текущим состоянием; `diff <id>` выбирает другую запись из списка. Eidos пока не определяет здесь сбои, а игра, упавшая под Proton, всё равно может завершиться с кодом 0: если выбранный запуск из таких, укажите более ранний через `diff <id>`.

### Привилегированный шаг не нужен

Eidos работает полностью без root. Он монтирует в приватном пространстве имён
пользователя и монтирования, поэтому не нужен ни setuid-помощник, ни демон, и
выдавать нечего.

`sudo setcap cap_sys_admin+ep "$(command -v eidos)"` **необязателен** и включает
ровно одно: passthrough FUSE на уровне ядра, который выключен по умолчанию,
потому что прежняя версия демона ломала с ним игру, а изменение, которое обходит
наиболее вероятную причину, ещё не измерено заново в игре (см. ниже). С этой
capability Eidos берёт обычное пространство имён монтирования вместо
пользовательского; моды разворачиваются одинаково в обоих случаях.


Почему старый совет про `setcap` исчез - и почему passthrough FUSE поставляется
выключенным - объяснено в
[troubleshooting.md](troubleshooting.md#почему-passthrough-выключен-по-умолчанию).

## Установка коллекции Nexus

```sh
eidos collection skyrimse nxm://skyrimspecialedition/collections/rqhcxy/revisions/latest
eidos collection skyrimse rqhcxy --dry-run     # прочитать её и сказать, что произойдёт
```

В окне: вставьте ссылку в **File -> Open a Nexus collection...** и нажмите
*Install this collection*.

### Почему это не «скачайте вот эти моды»

Коллекция - это РЕЦЕПТ, а не список покупок, и почти ничего из этого рецепта не
видно через API Nexus. Порядок установки, ответы, которые автор дал
установщику-скрипту каждого мода, какой мод выигрывает конфликт файлов, какие
плагины грузятся где, бинарные патчи - всё это лежит в `collection.json` внутри
собственного архива коллекции. Если скачать те же моды и поставить их с
параметрами по умолчанию, получится другая игра.

Поэтому Eidos скачивает архив, читает рецепт и применяет его:

| Коллекция говорит | Eidos делает |
| --- | --- |
| `phase` | ставит в этом порядке, необязательных участников последними |
| `choices` | воспроизводит ответы автора для каждого FOMOD и сообщает, когда не может |
| `modRules` | переставляет список модов так, чтобы нужный мод выиграл каждый файл |
| `plugins` / `pluginRules` | вливает правила LOOT в ваш userlist и сортирует |
| `INI Tweaks/` | ставит их отдельным модом |
| `tools` | сообщает, какие инструменты она ожидает; не создаёт ничего |

Участники **включаются** по мере установки, в конце списка модов в порядке
установки, до того как их подвинет `modRules`: мод, который ничто не
перечисляет, - это мод, который ничто не грузит, а коллекция, лежащая на диске
мёртвым грузом, - тот единственный провал, которого отчёт увидеть не мог.

Состояние пишется в `<instance>/collections/<slug>-<revision>.state.json` после
**каждого** участника - рядом с папкой этой ревизии, никогда внутри неё, чтобы
коллекция не могла привезти с собой собственную бухгалтерию, - и установка,
прерванная на участнике 147 из 200, продолжится со 147-го. Файл пишется под
временным именем и переименовывается на место, так что прерывание оставляет
либо старую запись, либо новую и никогда половину той или другой; а если его
когда-нибудь не удастся прочитать, Eidos останавливается и говорит об этом,
вместо того чтобы тихо начать всю коллекцию заново. Запустите ту же команду ещё
раз.

Установка более новой ревизии уже имеющейся у вас коллекции перенимает папки
предыдущей ревизии: неизменившийся участник проверяется на месте, участник, файл
которого автор обновил, заменяется внутри своей старой папки, а участник,
которого новая ревизия убрала, остаётся установленным и называется в отчёте,
чтобы вы отключили или удалили его. Папка, которую включает другой профиль,
никогда не перенимается, потому что папка модов общая и тот профиль изменился бы
у вас за спиной: вместо этого новая ревизия ставит рядом собственную копию, а
отчёт просит отключить старую в этом профиле, но никогда не удалять её. Возврат
к более старой ревизии точно так же забирает её папки обратно или ставит свежие
копии тех, которые забрать не может.
Каждый раз, когда участник заменяется так, а вы меняли или добавляли файлы в
его папке, старая папка сначала сохраняется рядом как `<name>_backup`, которая
никогда не загружается в игру, и отчёт её называет.

Оставшийся от более ранней ревизии мод, который по-прежнему включён, не даёт
засчитать установку как ту, что собрал автор; пометка исчезает, как только вы
его отключите. Участник, пропущенный через `--no-optional`, не перенимается и
называется точно так же. Если не удаётся само перенятие, запуск останавливается
с сообщением *previous revision: its folders could not be taken over* и
причиной; устраните её и запустите команду ещё раз.

### Чего он не станет изображать

**Бесплатный аккаунт Nexus не может забрать моды-участники.** Nexus не выпускает
ссылки на скачивание для бесплатных аккаунтов через API; каждому файлу нужна
собственная кнопка сайта «Mod Manager Download». АРХИВ коллекции на бесплатном
аккаунте скачивается прекрасно - так что весь рецепт вы прочитать можете, - но
по каждому участнику сообщается точный URL его страницы, чтобы вы забрали файл
сами. Это бизнес-правило Nexus, и никакое количество повторных попыток его не
обходит. Заберите их через кнопку сайта и запустите команду ещё раз: этих
участников ищут в `downloads/` при каждом запуске, так что коллекция
достраивается по мере того, как вы её пополняете.

В окне бесплатный аккаунт получает в панели коллекции вместо пакетной загрузки
кнопку *Fetch the N missing required files, one by one*. Она открывает на Nexus
страницу первого недостающего обязательного файла, ждёт, пока этот файл
появится в `downloads/`, и затем открывает следующую. Кнопку загрузки на
странице вы по-прежнему нажимаете сами, для каждого файла. Панель показывает,
сколько пройдено (*3 of 12*), и даёт *Skip* и *Stop*. Если вместо нужного
пришёл другой файл того же мода, панель называет оба идентификатора файлов и
продолжает ждать тот, что указан в коллекции. Необязательные участники сюда не
входят и сохраняют свою кнопку *Open*.

Применяются так, как описывает коллекция: **бинарные патчи** (каждый проверяется по записанному CRC), **перекрытия файлов** (названные файлы скрываются через `.mohidden`, как это делает MO2) и участники, чьи файлы едут внутри архива коллекции (`bundle`). Участники, которых коллекция ожидает от вас вручную
(`browse`, `manual`), доносят до отчёта собственные инструкции автора. Участник,
имя которого уже занято вашим модом, ставится рядом с ним под свободным именем,
а никогда не поверх него, и отчёт говорит, какой именно.

### Отчёт

Смысл отчёта в том, чтобы слову «установлено» можно было верить. Участник,
ответы установщика которого удалось воспроизвести не полностью, - это
**установлено, но не так, как просит коллекция**: у него своя строка, отдельно
от успехов, на которые он внешне похож, потому что файлы на диске отличаются от
авторских. Правила порядка, не назвавшие в коллекции ничего, моды, попавшие в
петлю противоречащих друг другу правил, несуществующие группы LOOT и любая часть
манифеста, которую эта версия Eidos не понимает, перечисляются тоже.

Альтернатива - записать такое в лог и объявить установку завершённой - это то,
как коллекция начинает играть неправильно по причинам, которых никто не может
найти.

## Перенос инстанции на другую машину

`eidos pack` записывает целую инстанцию - все моды, порядок загрузки, все
профили, Overwrite с вашими сохранениями и архивы, из которых всё это
ставилось, - в один файл. `eidos unpack` кладёт её обратно:

```sh
eidos pack skyrimse ~/backup.eidos                  # или укажите папку: имя по игре и дате
eidos unpack ~/backup.eidos /mnt/games/EidosSkyrim  # на другой машине
```

`eidos pack --dry-run` перечисляет ровно то, что войдёт внутрь, что не войдёт и
почему, и сколько нужно места, ничего при этом не записывая. `eidos unpack
--info` делает то же самое для файла, который у вас уже есть.

Если 7-Zip чего-то не смог прочитать или обходу пришлось пропустить то, что вы
ожидали бы увидеть в резервной копии (символическую ссылку, папку, которую не
удалось прочитать, имя, которое нельзя безопасно передать 7-Zip), архив всё
равно записывается и получает имя - его стоит иметь, - но `eidos pack`
завершается с кодом **1** и сообщает, чего не хватает. Неполная резервная копия
это не успех, а такую команду люди ставят перед `&&`.

Файл `.eidos` - это архив 7-Zip под собственным именем, и это выбор, а не
маскировка: 7-Zip и так нужен, чтобы вообще установить мод, поэтому зависимостей
не прибавляется, а если вы когда-нибудь лишитесь Eidos, ваша резервная копия всё
равно откроется в любом архиваторе. Сжат он LZMA2 на уровне `-mx1` - около 43%
от исходного размера на сборке с обилием текстур, за долю того времени, которое
`-mx9` тратит ради выигрыша в несколько пунктов. Текстуры и меши - уже сжатые
форматы; словарю побольше там почти нечего найти. `--level` (0, 1, 3, 5, 7, 9)
это переопределяет, если на своём содержимом вы не согласны, а `--no-downloads`
оставляет `downloads/` за бортом.

На уровне 1, который стоит по умолчанию, файлы ложатся в
**сплошные (solid) блоки не больше 16 МБ**. Чтобы вытащить один файл из
резервной копии на 70 ГБ, декодируется самое большее блок, в котором он лежит, и
никогда всё, что перед ним, а упаковка игрового содержимого идёт в 2-5 раз
быстрее, чем когда каждый файл сжимается отдельно (распаковка - в 2-4 раза).
Платить за это приходится при повреждении: один испорченный байт может унести с
собой все файлы своего блока, до 16 МБ соседних файлов. Этот случай покрывают
данные для восстановления, описанные ниже. Все остальные уровни остаются
несплошными: каждый файл - отдельный поток, и из-за испорченного байта теряется
только этот файл. Уровень 0 хранит файлы без сжатия. Начиная с уровня 3 LZMA2 и
так работает кусками по 16 МБ и больше, и сплошные блоки там в замерах оказались
медленнее: на уровне 5 упаковка мешей шла в 1,4 раза дольше, а распаковка
текстур - в 6,8 раза дольше.

Упаковка берёт блокировку инстанции, поэтому не может идти, пока игра или другой
Eidos пишет в эту инстанцию, - резервная копия это снимок, а не смазанный кадр.
Она пишется под именем с `.part`, сбрасывается на диск и целиком перечитывается
через `7z t`, прежде чем получить выбранное вами имя. Эта проверка декодирует
каждый блок и сверяет каждую контрольную сумму - ту же работу делает распаковка
на другой машине. Она показывает, что диск вернул сразу после записи, а не то,
что накопитель это сохранит; для этого и нужны данные для восстановления,
описанные ниже. Если проверка не прошла, файл `.part` удаляется, под вашим
именем ничего не записывается, а `eidos pack` приводит строку, в которой 7-Zip
нашёл повреждение. Прерванная или неудавшаяся упаковка оставляет что-то явно
незавершённое или ничего, а не файл `.eidos`, который выглядит целым и таковым
не является.

Когда установлен par2cmdline (`sudo pacman -S par2cmdline` в Arch,
`sudo apt install par2` в Debian и Ubuntu, `sudo dnf install par2cmdline` в
Fedora), `eidos pack` также записывает рядом с архивом данные для восстановления
PAR2: `backup.eidos.par2` и несколько файлов `backup.eidos.volNN+MM.par2`, всего
5% от архива плюс небольшой индекс. Держите их в той же папке, что и файл
`.eidos`, под теми именами, с которыми они были записаны, и копируйте вместе с
ним: резервной копии, перенесённой без них, не из чего восстанавливаться, а
данные для восстановления запоминают имя архива, так что переименованная копия
им уже не соответствует. `eidos unpack` находит их по имени и проверяет по ним
архив, прежде чем что-либо извлечь, в том числе копию, конец которой обрезан
так, что 7-Zip не может её открыть. Если испортилось несколько байтов, par2
сначала чинит архив и сохраняет повреждённую копию как `backup.eidos.1`, для
чего в его папке нужно столько свободного места, сколько занимает архив;
повреждение больше, чем покрывают эти 5%, останавливает распаковку до того, как
будет записан хоть один файл. Файлы восстановления, которые не соответствуют
архиву, например файлы более старой копии с тем же именем, не используются, если
7-Zip прочитал архив и нашёл его целым, и распаковка об этом сообщает. На машине
без par2 распаковка всё равно идёт, с предупреждением, что данные для
восстановления не использовались. `--no-recovery` упаковывает без них, а
`eidos pack --dry-run` сообщает, будут ли они записаны.

### Чего в ней нет и почему

| Не входит | Почему |
| --- | --- |
| Proton-префикс | Он привязан к машине (сопоставления дисков, вид `Z:` на *эту* файловую систему), и Eidos пересобирает его за минуту командой `eidos prereqs <instance> --install`. Тащить его значило бы примерно удвоить архив ради того, что другая машина всё равно должна создать заново. |
| Игра | Инстанция модифицирует игру, которую сама не содержит. Установите её там из Steam. |
| Инструменты вне инстанции | xEdit, DynDOLOD и прочие - сторонние программы со своими установщиками. В архиве они **названы**, поэтому распаковка сообщает, каких именно не хватает на новой машине. |
| `logs/`, `.eidos.lock`, `prereqs.done`, `prereqs.log` | Записи о машине, сделавшей копию. `prereqs.done` в частности утверждал бы, что рантайм-библиотеки уже установлены в префикс, которого нет. |
| `loot/`, кроме `userlist.yaml` | Кэш masterlist, который Eidos подтягивает заново по требованию. Ваши собственные правила LOOT это не кэш - их никто не подтягивает заново, - поэтому этот один файл едет вместе со всем. |
| `.base/`, `.base-root/` | Пустые точки монтирования, куда во время сессии убираются собственные файлы игры. |
| Недописанные файлы | Приостановленная загрузка (`*.unfinished`), атомарная запись на лету (`*.eidos-tmp*`). |
| Символические ссылки | 7-Zip пошёл бы по ссылке и скопировал то, на что она указывает, а для абсолютной ссылки это значит затянуть в вашу копию чужое дерево. Вместо этого о них сообщается, и резервная копия считается неполной: `mods/` или `downloads/`, ведущие ссылкой на другой диск, НЕ упаковываются. Чтобы намеренно сделать копию без папки `downloads/`, являющейся ссылкой, передайте `--no-downloads` (или снимите галочку *Include downloads/* в окне); намеренное исключение не считается недостающим. |

Каждый из этих пунктов попадает в `eidos-backup.ini` в корне архива вместе со
своей причиной - так что ответ на вопрос «чего здесь нет» это `cat`, а не
догадка. Тот же файл записывает, где инстанция жила раньше, какой профиль был
активен, во сколько она распакуется и какие инструменты понадобятся новой
машине.

Записи о загрузках (`downloads/*.meta`) входят с **опустошённой** строкой
`url=`. Этот URL - подписанная ссылка Nexus: она перестаёт работать за
считанные часы и несёт в себе `user_id` аккаунта, который скачал файл. Резервная
копия делается для того, чтобы её можно было отдать кому-то другому, поэтому
этого она не несёт. Всё, что позволяет найти загрузку снова, - id мода, id
файла, версия - остаётся.

### В окне

Обе команды лежат в меню **File**: *Pack this instance...* и *Unpack a
backup...*. Распаковка есть ещё и на экране приветствия, под списком инстанций,
потому что машина, которой она нужнее всего, - это та, где инстанций пока нет.

Диалог упаковки показывает расчёт до того, как что-то сделает: сколько файлов,
какого объёма, сколько из этого приходится на `downloads/`, примерно во сколько
выйдет архив и какие инструменты названы, но не унесены. Его флажок *Write
recovery data* отмечен, когда par2 установлен, а когда нет - он серый и рядом
указан пакет для установки. Диалог распаковки читает манифест резервной копии в
тот момент, когда вы выбираете файл, поэтому может сказать, какую игру она
содержит, когда она сделана, где инстанция жила раньше и каких её инструментов
здесь не хватает, - ещё до того, как вы укажете ему папку.

Обе идут в рабочем потоке с индикатором выполнения, поэтому окно продолжает
отвечать, пока они работают, а по завершении индикатор превращается в отчёт.
Упаковка держит блокировку инстанции всё время работы: пока инстанцию читают,
трогать её больше ничто не может, - именно это и делает резервную копию снимком,
а не смазанным кадром.

### Что чинит распаковка

Простая копия папки оставила бы каждую кнопку инструмента указывающей на путь на
старой машине. `eidos unpack` переписывает значения, которые называют старый
корень инстанции, и только их: `exe`, `workdir` и нумерованные ключи `arg` в
`tools.ini`, а также `installationFile` в `meta.ini` каждого мода. Инструмент,
который никогда не лежал внутри инстанции (`/opt/xedit/SSEEdit.exe`), остаётся
ровно таким, каким был, и попадает в список того, что надо переустановить, -
гадать, куда чужой xEdit делся, это выдумка, а не починка. Она также исправляет,
называет ли инстанция себя центральной или портативной, чтобы последующие
команды искали её там, где она теперь есть.

Распаковка отказывается работать с непустой папкой (передайте `--force`, если вы
и правда собираетесь перезаписать), с диском, который меньше цифры из
собственного манифеста, с архивом, сделанным более новым Eidos, чем ваш, и с
любым архивом, где есть запись, которая была бы записана *вне* выбранной вами
папки.

После этого:

```sh
eidos prereqs /mnt/games/EidosSkyrim --install   # пересобрать Proton-префикс
eidos play /mnt/games/EidosSkyrim
```

## GUI

```sh
cargo run -p eidos-gui
```

Мастер первого запуска в стиле MO2, нарисованный в общих темах Colony:
приветствие -> тип инстанции (портативная / глобальная) -> игра -> имя и
расположение -> сводка -> создание -> главный экран. Экран приветствия также
перечисляет все известные существующие инстанции (глобальные и портативные,
последняя использованная первой) для открытия в один клик - он же служит
переключателем инстанций, - а если указать мастеру папку, в которой уже есть
инстанция, он ПЕРЕНИМАЕТ её как есть, вместо того чтобы создавать поверх (и
отказывается наотрез, если папка принадлежит другой игре).

Главное окно из двух панелей тоже готово: выбор профиля (переключиться или
создать новый копией текущего), список модов, который вы фильтруете, выделяете,
переупорядочиваете, группируете разделителями, сужаете по категории и по правому
клику получаете действия, плюс вкладки Data / Plugins / Conflicts / Overwrite /
Saves / Downloads / Diagnostics и кнопка Run с выбором цели запуска.

Переупорядочивание - это не только отправить наверх или вниз: точечные
перемещения MO2 тоже здесь - поставить выше первого конфликтующего мода, ниже
последнего, на явный приоритет или внутрь группы разделителя. Все они проходят
через один общий помощник перемещения, так что ошибка на единицу, возникающая
при удалении строк перед их повторной вставкой, живёт в одном месте, а не в пяти.

### Preferences

Нажмите **Eidos** в левом верхнем углу, чтобы открыть Preferences на месте двух
панелей, и нажмите ещё раз (или **Close**), чтобы вернуться. Сначала идут
General, Appearance и Accessibility, как в каждой программе Colony, затем Mod
list, Nexus и About. Каждое изменение применяется и сохраняется сразу; кнопки
Save нет.

- **General**: игра, которую открывает Eidos, размер окна, язык интерфейса,
  папка инструментов, способ запуска игры и то, сообщает ли уведомление
  рабочего стола о конце долгой задачи, пока окно в фоне. Окно говорит по-английски и
  по-французски; **System** следует `LC_ALL`, `LC_MESSAGES` или `LANG`, и
  изменение применяется сразу. Командная строка `eidos` всегда отвечает
  по-английски.
- **Appearance**: тема (25 семейств, 57 палитр, по умолчанию пергамент Eidos),
  акцентный цвет, размер текста, эффекты и живой предпросмотр.
- **Accessibility**: высокая контрастность, шрифт, удобный при дислексии,
  уменьшенная анимация и размер текста для чтения, который умножается на размер
  из Appearance.

Всё это хранится в `~/.config/Colony/Eidos/preferences.json`. Тема, которую
старый Eidos держал в `settings.ini`, переносится при первом запуске.

**About -> Version** содержит проверку выпусков, по умолчанию включённую. При запуске, не чаще раза в день, Eidos спрашивает у GitHub последний выпуск `Project-Colony/Eidos`. Если он новее запущенной копии, в строке меню после Help появляется `Eidos 1.24.0 is available: release notes`, а ссылка открывает страницу этого выпуска со списком изменений. Eidos никогда не скачивает и не заменяет сам себя. В офлайн-режиме проверка пропускается. Она выключена для копии, которую менеджер пакетов установил в `/usr`: обновляет её он; `/usr/local`, куда `install.sh --system` кладёт Eidos, считается вашей собственной установкой.

### Столбцы, сортировка и группировка

Из коробки список рисует четыре столбца, а предлагает восемь: Category, Content,
Version, Author, Installed, Nexus id, Game, Flags. Отмечайте их в меню View. По
умолчанию показаны не все восемь намеренно - в списке со всеми столбцами не
остаётся места для ИМЕНИ, а именно его вы и читаете.

Клик по любому заголовку сортирует по нему. Повторный клик разворачивает
порядок, а третий возвращает к **порядку загрузки**, и это важнее, чем звучит:
порядок загрузки - единственный порядок, в котором список можно перетаскивать,
потому что промежуток вставки адресует настоящий список, тогда как
отсортированная строка находится совсем в другом месте. Пока включена
сортировка, полосы вставки не рисуются, а перетаскивание отклоняется, вместо
того чтобы приземлиться туда, куда никто не целился, - то же самое делает MO2 и
по той же причине. Меню View сообщает об этом и предлагает путь назад.

Меню View может также **группировать** весь список: по категории или по
источнику (с Nexus или установлено вручную). Заголовки групп - не разделители:
за ними ничего нет, их нечего переименовывать, красить или двигать, они
сворачиваются, и счётчик остаётся на заголовке в свёрнутом виде. Разделители
покидают список при сортировке или группировке - разделитель возглавляет строки,
идущие за ним в порядке загрузки, а и то и другое их переставило.

### Мышь и клавиатура

Двойной клик по моду открывает Information, Ctrl+двойной клик - его папку,
Shift+двойной клик - его страницу на Nexus. Ctrl+F ставит курсор в поле фильтра.
Ввод буквы перепрыгивает к следующему моду, начинающемуся с неё, а повторное
нажатие идёт дальше по остальным, а не залипает на первом. Ни одно из этих
действий не может попасть на строку, скрытую фильтром, свёрнутым разделителем
или свёрнутой группой, - перемещение подсветки, которую вы не видите, и есть то,
из-за чего следующий Space переключит мод, на который вы не смотрели.

«Collapse others» в меню разделителя сворачивает все группы, кроме этой. Во
время перетаскивания задержка над свёрнутой группой открывает её, так что мод
можно бросить внутрь, не бросая перетаскивание, - именно задержка, а не
мимолётное движение мимо.

Ctrl+Z отменяет последнее изменение списка модов или порядка загрузки: галочку,
перемещение, массовое отключение, сортировку LOOT. Ctrl+Shift+Z возвращает его. Окно хранит 50 шагов и
забывает их по F5, по окончании запуска игры или инструмента, при смене профиля
и когда другой процесс Eidos меняет список. Установка, переименование или
удаление мода меняет папки на диске, поэтому отмена дальше такого шага
отклоняется.

### Фильтрация списка

Кнопка Filters открывает по строке на каждый критерий: активен, в конфликте,
есть обновление, без категории, одобрен на Nexus (endorsed), отслеживается
(tracked), есть id Nexus, есть скрытые файлы, нет пригодных игровых данных, для
другой игры, есть заметки, и по строке на каждый вид содержимого (плагины,
архивы BSA или BA2, текстуры, меши, скрипты, плагины script extender, файлы
интерфейса, звук, FaceGen). Клик переводит строку по кругу: выключено, «only»,
«except» и снова выключено. Верхняя строка переключает между модами, которые
удовлетворяют всем включённым критериям, и модами, которые удовлетворяют хотя
бы одному. Поле имени и список категорий всегда дополнительно сужают результат.
Строка скрытых файлов смотрит только на включённые моды.

### Что список сообщает о моде

Два рекомендательных флага, оба - глиф с пояснением при наведении. **No valid
game data** значит, что ничто в верхушке мода не похоже на то, что эта игра
загружает; возможно, его папки надо поднять на уровень выше, а возможно, это
вообще не мод для этой игры. **Another game** значит, что собственный `meta.ini`
мода называет другую. Ни то ни другое ничего не блокирует - мод всё равно
разворачивается, - а «Mark as valid» в меню строки заглушает любой из них через
собственный ключ MO2 `validated=`, так что мод, за который вы поручились в одном
менеджере, приходит тихим в другой.

Проверка раскладки намеренно снисходительна: дерево `Root/` засчитывается,
нечитаемая папка засчитывается, пустая засчитывается. Ложное предупреждение в
списке на пятьсот строк хуже, чем пропущенное.

### Отключение мода, которым пользуются ваши сохранения или другие моды

Прежде чем мод будет отключён или удалён, Eidos читает списки плагинов трёх
самых новых сохранений профиля. Если одно из них использует плагин из этого мода,
полоса над списком называет эти плагины и ждёт «Disable anyway» или «Cancel»
(Esc тоже отменяет). Remove добавляет те же имена в своё сообщение о повторном
щелчке. Читаются только сохранения Skyrim и Fallout 4; в остальных играх мод
отключается без вопроса.

Вкладка General в Information мода перечисляет моды, которые ему нужны, и моды, которым нужен он, по мастерам включённых плагинов. При отключении мода, который нужен другим, появляется та же полоса с кнопкой «Disable them too», которая отключает и каждый мод, которому он нужен, и моды, которым нужны те, или «Keep them enabled». У карточки отсутствующих мастеров на вкладке Health есть кнопка "Enable what provides them": она включает мод, содержащий каждый недостающий мастер, и отмечает мастер-плагин, который есть, но не отмечен.

### Резервная копия мода перед вмешательством

«Back up this mod» копирует его папку рядом как `<name>_backup` (затем
`_backup2` и так далее - копия никогда не заменяет предыдущую). Копия
**инертна**: это не мод, её чекбокс ничего не делает, и она ничего не вносит в
объединённый вид, потому что её включение развернуло бы две копии одного мода
друг поверх друга. «Restore this backup over the mod» возвращает её на место в
два клика; текущее содержимое сначала отодвигается в сторону и выбрасывается
только после того, как копирование удалось.

**Data** - настоящее дерево объединённого вида, разворачиваемое по одному уровню
за раз, так что открытие узла стоит одного чтения каталога на каждый слой, где
он есть, а не рекурсивного обхода всех включённых модов. Отвечает на него ТОТ ЖЕ
стек слоёв, из которого обслуживается монтирование, поэтому whiteout-ы и скрытые
файлы учитываются, и вкладка не может разойтись с тем, что увидит игра.
Фильтруйте по имени, сужайте до одних спорных файлов, разбирайтесь, что где
лежит, по столбцам Size и Modified, и открывайте любую строку в файловом
менеджере через Reveal. `meta.ini`, `readme.txt`, `fomod/` и `Root/` в корне
мода не попадают в Data, ни на этой вкладке, ни в монтировании: первые три нужны
менеджеру модов, а `Root/` уходит в папку игры. Файл, который игра или
инструмент запишет под одним из этих имён, оказывается в Overwrite и остаётся
видимым. **Plugins** - порядок загрузки ESP/ESM/ESL (включать,
переставлять вручную или отсортировать через LOOT и прочитать отчёт после
сортировки, ссылки из советов которого открываются в браузере). Его заголовок считает включённые плагины в каждом индексном пространстве относительно лимита игры, например `full 231/254, light 512/4096`, и становится оранжевым, когда одно из них заполнено. После сортировки LOOT полный плагин, все новые записи которого помещаются в диапазон light, сообщает об этом при наведении, а в меню его строки есть Flag as light. Eidos записывает копию с флагом light в новый мод `<plugin> (light)` внизу списка модов (наивысший приоритет) и не трогает оригинал, поэтому отключение этого мода отменяет изменение. Eidos отказывается, если одно из трёх самых новых сохранений профиля загружает плагин как полный. Читаются только сохранения Skyrim и Fallout 4, поэтому в Starfield сохранения не проверяются. LOOT проверяет только диапазоны записей: плагин, который добавляет ячейки или worldspace, перед пометкой просмотрите в xEdit. **Conflicts**
объясняет победителей и проигравших по каждому файлу. **Overwrite** превращает
записанное игрой в настоящий мод за один шаг. **Saves** разбирает заголовок
каждого сохранения - персонаж, уровень, место, время игры - и сравнивает
запечённый в него список плагинов с вашим текущим, с кнопкой, которая включает
нужные ему моды, потому что назвать их и оставить вас разбираться - это скучная
половина работы.

При наведении на плагин показываются его источник, автор, версии заголовка и формы, первые 300 символов описания, его мастера и, после сортировки LOOT, сообщения LOOT. В Skyrim, Skyrim SE, Skyrim VR и Enderal SE игра также читает INI с именем загруженного плагина; столбец INI отмечает такие плагины, а щелчок открывает этот файл только для чтения.

У строки `.exe` на вкладке Data есть кнопки Add tool, которая открывает редактор Executables с уже заполненным файлом (ничего не сохраняется, пока вы не нажмёте Save), и Run, которая запускает файл один раз через объединённое представление, как зарегистрированный инструмент. Save tree записывает всё объединённое дерево Data в текстовый файл: по строке на файл с указанием мода, который его предоставляет, без вашей домашней папки и имени пользователя, для отчёта об ошибке.

Сохранения, которые Steam Cloud скачивает с другого устройства или которые записывает запуск без Eidos, попадают в собственную папку сохранений игры, а её, пока игра запущена, перекрывают сохранения профиля. Вкладка Saves показывает их число в строке под заголовком, а Import копирует каждое вместе с его co-save в профиль. Сохранение, чьё имя в профиле уже занято, импортируется как `orphan-<time>-<name>`; в профиле ничего не заменяется.

«Information...» открывает диалог по моду: общее, конфликты, дерево файлов,
правки INI, заметки. Из дерева файлов (и из дерева Data) любой файл можно
**спрятать** - он переименовывается в `<name>.mohidden`, что выбрасывает его из
виртуального вида, не удаляя, так что три случайных меша одного мода можно
подавить, не трогая приоритеты. Дерево файлов делает и обычные файловые
операции: новая папка, переименование, удаление, открытие. Все они проходят
через один резолвер, который отвергает всё, что не является простым путём внутри
этого мода, - никаких `..`, никаких абсолютных путей и ни одного компонента,
являющегося симлинком, поскольку переход по нему вывел бы удаление за пределы
папки мода. Переименование заменяет только последний компонент, поэтому никогда
не может превратиться в перемещение, и оно отклоняет уже занятое имя, вместо
того чтобы молча заменить тот файл. Удаление требует двух кликов; это
единственное действие здесь, которое повторный клик не отменяет.

**View** на любой строке дерева файлов или дерева Data показывает предпросмотр
файла: изображения и текст. Не DDS и не NIF - им нужны блочный декодер и
рендерер, которых у этого дерева нет, - но они говорят об этом, а не показывают
пустое окно, и указывают на Reveal. Текст читается до 64 КБ и сообщает, где
остановился, потому что предпросмотр - это взгляд, а лог Papyrus может весить
сотню мегабайт. **INI Tweaks** перечисляет фрагменты, которые мод поставляет в
своей папке `INI Tweaks/`; включённые сливаются в игровой INI профиля при
запуске, в порядке приоритета, и снимаются обратно, когда INI после запуска
захватываются, - иначе правка молча стала бы настройкой, а её отключение ничего
бы не дало.

Загрузку можно **перетащить из списка Downloads на позицию в списке модов**,
чтобы установить её с этим приоритетом, а архивы или папки, брошенные в окно из
файлового менеджера, тоже устанавливаются (для этой половины нужна сессия X11
или XWayland - winit реализует перетаскивание файлов только для X11). Сами
загрузки можно ставить на паузу и возобновлять: пауза останавливает передачу и
сохраняет недокачанное, а Resume заново получает свежую ссылку и продолжает с
того места, где остановился.

Вкладка Downloads - это **библиотека** архивов, а не очередь передач. Фильтруйте
её по имени (в том числе по человеческому имени мода, так что «skyui» находит
`SkyUI_5_2_SE-12604-5-2SE.7z`), сортируйте по новизне, имени, размеру или
состоянию и **прячьте** архив, с которым закончили, - это сохраняет файл и
убирает только строку, потому что убрать книгу на полку - не то же самое, что
сжечь её. «Show hidden» возвращает их, и та же кнопка снимает скрытие. «Remove N
installed» удаляет архивы уже установленных модов, в два клика, и только те, что
**на экране**: фильтр - это и есть ваш способ сказать, какие вы имели в виду.

**Preferences -> Nexus -> Install downloads when they finish** по умолчанию выключено. Если включить, загрузка с Nexus, которая заканчивается при открытом окне, устанавливается сама, без захода на вкладку Downloads. Это обычная установка: FOMOD открывает свой установщик, а имя, которое уже есть в списке модов, спрашивает, что делать. Архивы, лежавшие в `downloads/` до открытия окна или до включения опции, не трогаются, как и загрузка, установку которой вы отменили. Участников коллекции, открытой на панели коллекций, и файл, которого ждёт отложенное обновление, устанавливают только эти сценарии. Пока игра или другой Eidos держит экземпляр, установка ждёт, пока он освободится.

### Обновления модов

Кнопка обновления в правом конце панели инструментов сравнивает каждый
установленный файл с файлом, который заменил его на Nexus. Авторы отмечают новую
загрузку как преемника более старой, и Eidos идёт по этой цепочке от
идентификатора файла, записанного в `meta.ini` мода. Если цепочка не называет
преемника, вместо этого сравнивается версия со страницы мода.

Track и Untrack в контекстном меню мода добавляют мод в ваши отслеживаемые моды
на Nexus или убирают его оттуда, так что уведомления сайта совпадают с тем, что
вы отслеживаете здесь. Каждая проверка обновлений также читает с Nexus ваши
одобрения (endorsements) и отслеживаемые моды (два запроса) и выставляет по ним
флаги Endorsed и Tracked каждого мода, на собственном домене Nexus этого мода.
Если они расходятся, побеждает Nexus. Если какой-то из списков прочитать не
удалось, проверка сообщает об этом и оставляет эти флаги как были.

Вкладка **Nexus files** в «Information...» перечисляет файлы мода на Nexus, от
самого нового, и отмечает установленный здесь и тот, что его заменяет. Во второй
из этих строк есть кнопка **Update**. С премиум-аккаунтом Eidos скачивает файл
сам. С бесплатным аккаунтом он открывает страницу файла, откуда Mod Manager
Download отправляет файл обратно, и установка начинается, когда архив появляется
в `downloads/`. Дальше это обычная установка: FOMOD открывается с ответами, с
которыми мод был установлен, затем запрос предлагает Replace с отмеченным «Keep
a backup of the existing mod», что бы вы ни выбрали в прошлый раз. Replace
сохраняет приоритет мода и то, включён ли он.

Папка, в которой лежит несколько файлов Nexus, например основной файл с влитым в
него необязательным, не обновляется: замена новым основным файлом потеряла бы
остальные. Обновите их вручную.

`eidos nexus update skyrimse --apply` выполняет ту же проверку, а затем с
премиум-аккаунтом скачивает каждый новый файл и устанавливает его поверх его
папки с `--replace --backup`. С бесплатным аккаунтом он вместо этого печатает
`OPEN <url>` для каждой страницы файла. Папки, объединяющие несколько файлов,
пропускаются с указанием причины. FOMOD-мод без сохранённых ответов, например
установленный до того, как Eidos начал их хранить, не переустанавливается с
настройками установщика по умолчанию: такое обновление завершается ошибкой с
просьбой один раз обновить мод из окна, которое сохранит ответы. FOMOD,
установщик которого ничего не предлагает выбрать, устанавливается как обычно.
Команда завершается с кодом 1, если какое-то обновление не удалось.

### Коллекции Nexus

Вставьте ссылку на коллекцию - или кликните её на сайте - и Eidos перечислит
участников ревизии, каждого сопоставив с этой инстанцией: установлен, скачан или
отсутствует. *Install this collection* затем прогоняет весь рецепт в рабочем
потоке, с тем же индикатором выполнения, что у упаковки и распаковки, и по
завершении индикатор превращается в отчёт. Всё сказанное выше о том, что
применяется, а что только называется, действует здесь слово в слово: окно и
`eidos collection` - это один движок с двумя интерфейсами.

Коллекцию можно прочитать только для **её собственной игры**. Откройте коллекцию
Skyrim с загруженной инстанцией Fallout 4 - и она откажется, назвав игру, вместо
того чтобы сопоставлять участников с неправильным списком модов, где каждое
«установлено» и каждое «отсутствует» было бы шумом в форме ответа.

Когда вы проверяете обновления, Eidos также спрашивает Nexus о последней ревизии каждой коллекции, установленной в этом экземпляре. Строка над списком модов называет каждую коллекцию с более новой ревизией и считает добавленные (+), обновлённые (~) и убранные (-) моды; имена видны при наведении курсора. Если рецепт установленной ревизии больше не лежит в кэше, чисел нет. **Обновить** открывает новую ревизию в панели коллекций, где её запускает *Install this collection*. Список строится заново при каждой проверке и не сохраняется.

### Офлайн-режим

**Preferences -> Nexus -> Offline** полностью прекращает обращения Eidos к Nexus и пропускает ежедневную проверку выпусков на GitHub.
Проверки обновлений, вход, загрузки и коллекции сообщают об этом, вместо того
чтобы падать с ошибкой соединения. Он выключен, пока вы его не включите - в
файле настроек, написанном старым Eidos, такого ключа нет, и чтение
отсутствующего как «включено» отрезало бы сеть всем, кто обновился.

**Preferred servers** ранжирует узлы CDN, которые предпочитает загрузка, лучший
первым. Больше одного зеркала на выбор получает только премиум-аккаунт, так что
для всех остальных выбирает Nexus и это ничего не меняет. Это порядок, а не
фильтр: если ничего из названного вами сегодня не предлагается, загрузка всё
равно происходит - с того узла, который Nexus предложил первым.

**Categories** можно редактировать, а не только смотреть: назначайте их одному
моду или целому выделению, правьте сам каталог из того же диалога и подтягивайте
официальный список категорий игры с Nexus. Оба файла каталога - собственные
файлы MO2 (`categories.dat` и `nexuscatmap.dat`), так что общая инстанция
сохраняет один каталог. Мод, скачанный с Nexus, получает категорию при установке, если «Получить с Nexus» уже сопоставил каталог.

**View -> INI editor** правит игровые INI профиля - ту копию, которая
сохраняется, а не ту, что зарыта в Proton-префиксе и переписывается при каждом
запуске. **View -> Log** читает логи сессий. **View -> Extensions** перечисляет
ваши собственные дополнения; см. [extensions.md](extensions.md).

Если при запуске главный INI игры (`Skyrim.ini`, `Fallout4.ini`, `Oblivion.ini`...) не найден ни в профиле, ни в префиксе, Eidos сначала копирует в профиль файл по умолчанию из папки игры (`Skyrim_Default.ini`, `Fallout4_Default.ini`...), как это делает MO2. Префикс и папка игры не изменяются.

Установка принимает всё: пути Simple и FOMOD, плюс пакеты **BAIN** от Wrye Bash
(отметьте подпакеты, которые сливаются по порядку) и **ручной** выбор, который
показывает дерево архива и позволяет указать корень данных, когда ни одна
эвристика не распознаёт раскладку. Ни один архив не отвергается.

Переустановка или обновление FOMOD-мода открывает мастер с отмеченными ответами
прошлой установки, на первом шаге, чьи варианты с тех пор изменились, и со
списком изменений. **Reinstall with new choices** вместо этого начинает с
настроек установщика по умолчанию. `eidos install --replace` или `--merge` снова
берёт сохранённые ответы, а если они больше не подходят, отказывается
устанавливать и перечисляет изменения.

**Diagnostics** выполняет живые проверки здоровья: прежде всего способность
запуститься, отсутствующие мастер-файлы (самый надёжный предсказатель
крашей), архивы, которые не загрузит ни один активный плагин, соответствие
списка модов папке модов и - после запуска - что собственный лог расширителя
скриптов говорит о каждой из его DLL-плагинов, что превращает «загрузились ли
мои плагины SKSE?» из догадки в доказательство.
Вкладка также сообщает об обновлении игры после последнего чистого запуска, об отсутствующем расширителе скриптов или о том, что он не подходит к версии игры (со страницей загрузки расширителя и кнопкой, которая устанавливает скачанный архив), о параметре запуска Steam, который не запускает Eidos с `%command%`, о NVAPI, оставленном выключенным для DLSS, об эксклюзивном полноэкранном режиме, который мешает генерации кадров, об `enblocal.ini` от ENB без `LinuxVersion=true`, об объявлениях плагинов F4SE и SFSE и о логе краша последней сессии с модами, которые он называет.
Проверка обновлений также читает требования каждого мода на Nexus. Diagnostics показывает требуемый мод, который отсутствует или отключён; кнопка Ignore скрывает требование, выполненное иначе.

Для Skyrim SE, Enderal SE и Fallout 4 в Diagnostics есть ещё карточка «Экран». Она показывает размер и режим окна, заданные в `SkyrimPrefs.ini` профиля (`EnderalPrefs.ini`, `Fallout4Prefs.ini`), или в копии в префиксе, пока у профиля своей нет. Если размер не задан ни там, ни там, поля заполняются по самому большому подключённому экрану из `/sys/class/drm`, так что на Steam Deck будет 1280x800. Apply записывает `iSize W`, `iSize H`, `bFull Screen` и `bBorderless` в копию профиля, а если у профиля её нет, сначала забирает копию из префикса. Когда окно задаёт SSE Display Tweaks, Apply записывает тот же размер и режим в его копию в Overwrite; собственный файл мода не меняется.

Чтобы запускать игру через GUI, задайте параметром запуска Steam для этой игры
абсолютный путь к исполняемому файлу (Steam не видит `~/.cargo/bin` в PATH):

```
~/.cargo/bin/eidos-gui %command%
```

Eidos открывается на инстанции этой игры - той, которой вы пользовались
последней, так что портативная инстанция находится снова точно так же, как
глобальная; нажмите Run, чтобы запустить её через объединённый вид.

Если включено **Start the game at once when a store opens Eidos** (Preferences, General, Running a game), Eidos обходится без этого щелчка: он проверяет Health и запускает игру, не показывая своё окно. Окно открывается как обычно, когда Health сообщает о проблеме, когда список модов требует внимания, когда у инструмента, настроенного на запуск перед игрой, устарел результат, или, для Skyrim SE, Enderal SE и Fallout 4, когда у профиля ещё нет размера окна (тогда окно открывается на Diagnostics). Чтобы получить окно на один запуск, поставьте `EIDOS_WINDOW=1` перед командой: `EIDOS_WINDOW=1 ~/.cargo/bin/eidos-gui %command%`.

Вне Steam Run не запускает игру сам через Proton или Wine. Он просит магазин,
которому принадлежит копия, запустить её, и магазин запускает Eidos:

- Steam выполняет `steam -applaunch <appid>`, когда параметр запуска выше задан.
  Если Steam закрыт, сначала запускается Steam.
- Heroic (копия GOG или Epic, нативный или Flatpak) получает ссылку
  `heroic://launch`, когда Eidos стоит обёрткой (wrapper) в настройках игры в
  Heroic, с абсолютным путём к `eidos-gui` в качестве исполняемого файла и без
  аргументов. Если Heroic закрыт, сначала запускается Heroic.
- Legendary сам по себе выполняет `legendary launch <app>`, когда в
  `~/.config/legendary/config.ini` есть `wrapper =` с абсолютным путём к
  `eidos-gui` в разделе игры `[<app>]` или в `[default]`.

Затем Eidos открывает второе окно на инстанции, которой вы пользовались
последней, и вы нажимаете Run там. Первое окно не следит за этим запуском,
поэтому после игры нажмите в нём F5, чтобы перечитать его списки. Если настройки
в магазине нет или загрузчик script extender не лежит рядом с исполняемым файлом
игры, Run ничего не запускает и показывает, что и где задать, с настоящим путём
работающего исполняемого файла.

### Переменные и обёртки для профиля

У профиля могут быть свои переменные окружения и команды-обёртки в `profiles/<имя>/launch-env.ini`, по одной записи в строке:

```ini
env=PROTON_ENABLE_NVAPI=1
env=DXVK_HUD=fps
wrapper=gamemoderun
wrapper=gamescope -W 1280 -H 800 -f -- %command%
```

Они действуют при каждом `eidos play` этого профиля (игра, запущенная через `%command%` в Steam или через Run в окне, которое открыл магазин) и при каждом запуске инструмента. `eidos shell` получает переменные, но не обёртки. Первая строка `wrapper=` самая внешняя. В строке `wrapper=` с `%command%` команда подставляется на это место, как в параметрах запуска Steam; в строке без него команда добавляется в конец. Обёртки работают внутри закрытого пространства имён Eidos, поэтому видят моды.

Переменная отсюда заменяет значение, которое Eidos задаёт для того же имени, а собственная строка `env=` инструмента в `tools.ini` заменяет оба. `WINEDLLOVERRIDES`, наоборот, добавляется после переопределений, которые Eidos задаёт для ENB, ReShade и встроенных DLL: DLL, указанная в обоих местах, получает настройку профиля, остальные сохраняют свою.

View -> INI editor открывает файл последней вкладкой, для любой игры. При сохранении Eidos перечисляет номера строк, которые игнорирует: те, что не являются ни `env=ИМЯ=значение`, ни `wrapper=команда`. `eidos play <экземпляр>` без команды выводит переменные, которые получит запуск, и обёртки. Copy report в Diagnostics называет переменные и программы-обёртки без их значений.

`%command%` в Steam для игр Bethesda обычно указывает на `<Game>Launcher.exe`.
Eidos никогда его не запускает: лаунчер - это отдельное приложение настроек,
которое заново сканирует `Data` и переписывает `plugins.txt`, отменяя только что
развёрнутый порядок загрузки. Он подставляет загрузчик расширителя скриптов,
если тот установлен, иначе бинарник игры, и сообщает, когда пришлось откатиться
к запасному варианту, - игра, которая стартует с инертными модами SKSE, хуже
той, которая не стартует.

Прежние инструкции здесь заставляли ставить
`WINEDLLOVERRIDES="d3dcompiler_47=n"`. Это больше не нужно и никогда не было
вполне верным: переопределение на *native* помогает, только если настоящая
`d3dcompiler_47.dll` уже есть в префиксе. Теперь Eidos сканирует импорты DLL
включённых модов, сам разворачивает настоящую DLL от Microsoft и только потом
выставляет переопределение.

## Инструменты

xEdit, BodySlide, DynDOLOD и прочие запускаются через объединённый вид внутри
Proton-префикса игры:

```sh
eidos tool skyrimse add BodySlide "<path>/CalienteTools/BodySlide/BodySlide.exe"
eidos tool skyrimse run BodySlide
eidos prereqs skyrimse            # что нужно зарегистрированным инструментам и в каком это состоянии
eidos prereqs skyrimse --install  # скачать всё недостающее
```

Одно, что надо знать до того, как называть инструмент: **название решает, какие
рантайм-DLL Eidos для него подготовит** - `BodySlide` получает свои библиотеки
DirectX, `BS` не получает ничего. В GUI диалог Executables показывает под полем
реальное состояние каждой зависимости, а недостающие оформлены кнопками.

Таблица, три уровня зависимостей, почему DynDOLOD нужен рантайм .NET, который
winetricks установить не может, и почему инструмент, установленный как мод,
запускается из объединённого пути, а не из своей папки, - в
[tools.md](tools.md).

Сборка из исходников и раскладка репозитория - в
[../internals/contributing.md](../../../../internals/contributing.md).

## Расширения

Eidos можно расширять без пересборки: манифест TOML в
`~/.config/Colony/Eidos/addons/` добавляет инструмент в список Extensions или
проверку на вкладку Health. Ничего не загружается внутрь Eidos - расширение это
программа, которую он запускает. См. [extensions.md](extensions.md).
