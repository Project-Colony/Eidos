# Расширения

Расширение добавляет в Eidos запись, не будучи частью Eidos. Это TOML-манифест,
называющий программу, плюс, самое большее, сама эта программа.

Манифесты лежат в `~/.config/Colony/Eidos/addons/`, по одному `.toml` на
расширение. Откройте папку через View -> Extensions -> Open folder и нажмите
Reload - перезапуск не нужен.

Поля `id`, `kind` и `exec` обязательны; `name` по умолчанию равно id. `exec`
называет программу. Имя без `/` ищется в `PATH`. Если программы нет, Eidos
пропускает расширение, а его строка в View -> Extensions объясняет причину
(`<exec> is not on PATH` или `<exec> is not there`). Поле `games` ограничивает
расширение указанными идентификаторами игр; без него расширение действует для
каждой игры, а в другой игре его строка говорит "not for this game".

Манифест, который Eidos отклонил, показывается первым, с причиной: файл не
читается, это не TOML или нет обязательного поля, пустой `id` или `id` с
пробелом, пустой `exec`, `id`, который уже занял более ранний манифест (файлы
читаются в порядке имён), неизвестный Eidos `kind`, либо установщик, предпросмотр
или сведения о сохранениях без `protocol = 1` и имени файла `extensions`.

## Почему в Eidos ничего не загружается

Mod Organizer 2 загружает плагины как разделяемые библиотеки, а питоновские
размещает через Qt. Ни то, ни другое сюда не переносится. У Rust нет стабильного
ABI, поэтому разделяемая библиотека, собранная другим компилятором, с другим
флагом оптимизации или с другим набором возможностей общей зависимости, - это
неопределённое поведение, и ничто не сообщит о нём как о несовпадении версий.
К тому же виджеты Eidos обобщены на этапе компиляции, так что библиотека не
смогла бы построить виджет для возврата, даже будь ABI стабильным.

Расширение - это программа, которую Eidos запускает с правами доступа вашей
учётной записи к файловой системе. Устанавливайте только вспомогательные
программы, которым доверяете. Изоляция процессов и проверка ответов не
заменяют песочницу операционной системы.

## Инструмент

```toml
id = "wrye-bash"
name = "Wrye Bash"
kind = "tool"
exec = "/opt/wrye/wrye-bash"
args = ["--data", "{data}"]
games = ["skyrimse"]        # опустить, чтобы для всех игр
description = "Bashed patch builder."
author = "you"
version = "1.0"
```

Он появляется в View -> Extensions с кнопкой Run и запускается отсоединённо:
Eidos его не ждёт, а строка состояния показывает его pid. Вывод отбрасывается.
Без `workdir` он стартует в папке, из которой запущен сам Eidos.

## Проверка

```toml
id = "esl-count"
name = "ESL budget"
kind = "diagnose"
exec = "/home/me/bin/esl-count.sh"
args = ["{profile_dir}/plugins.txt"]
```

Она выполняется при каждом обновлении, в корне инстанции, если `workdir` не
говорит иного, и печатает по одной находке на строку:

```
level<TAB>title<TAB>detail
```

где `level` - это `problem`, `advice` или `ok`. Деталь необязательна; строка без
заголовка отбрасывается. Всё, что не начинается с известного уровня,
игнорируется, так что вывод хода работы и случайные предупреждения не смогут
поднять строку, похожую на собственную проверку Eidos. Находки появляются во
вкладке Diagnostics как `<name> - <title>`, после карточек префикса и Nexus и
перед остальными карточками Health.

Проверке даётся три секунды. Превысившая срок останавливается и сообщается как
проблема против самой себя: она выполняется на том же обновлении, что следует за
каждым щелчком, поэтому зависшая заморозила бы окно. Отсчёт идёт, пока проверка
не завершится и её каналы вывода не закроются, так что фоновый дочерний процесс,
который их держит, засчитывается в эти три секунды. Проверка, которая завершилась
с ошибкой и ничего не напечатала, сообщается так же, с первой строкой её
вывода ошибок; так же сообщается и проверка, напечатавшая больше 1 MiB в любой
из двух потоков. В обоих случаях Eidos не запускает её снова, пока вы не нажмёте
Reload, а её строка говорит "It will not be retried until you press Reload."
Проверка ничего не читает со стандартного ввода.

## Подстановки

И `args`, и `workdir` раскрывают следующее:

| Подстановка     | Что это                                      |
| --------------- | -------------------------------------------- |
| `{instance}`    | корень инстанции                             |
| `{mods}`        | `<instance>/mods`                            |
| `{downloads}`   | `<instance>/downloads`                       |
| `{overwrite}`   | `<instance>/overwrite`                       |
| `{profile}`     | имя активного профиля                        |
| `{profile_dir}` | каталог активного профиля                    |
| `{game}`        | идентификатор игры, напр. `skyrimse`         |
| `{game_name}`   | отображаемое имя игры                        |
| `{install}`     | папка игры, с которой работает инстанция     |
| `{data}`        | каталог `Data` этой папки                    |

`{install}` - это установка из магазина или копия игры, если инстанция работает
с копией (замороженная `Stock Game` или собственная папка игры списка; см.
[usage.md](usage.md#файлы-игры-установка-из-магазина-или-копия)). `{data}` следует за
ней.

Проверка получает ещё `{addon_dir}`, папку с её манифестом; так же и
расширения протокола 1 ниже. Инструмент её не получает.

Неизвестная подстановка никогда не опустошается, иначе `--out {typo}` превратилось
бы в `--out --next-flag`. Eidos отказывается запускать инструмент или проверку,
у которых не все подстановки разрешаются, и говорит, каких не хватает: в строке
состояния для инструмента, в строке проверки во вкладке Diagnostics для проверки.

## Чего расширение не может

Расширение не может обращаться к Eidos через обратные вызовы, регистрировать себя из архива или рисовать собственные виджеты. Структурированные установщики протокола 1 могут возвращать проверенные планы файлов и вопросы с выбором; проверкой, подготовкой во временном каталоге и публикацией управляет Eidos. FOMOD и BAIN остаются нативными установщиками. Расширения предпросмотра и сведений о сохранениях используют тот же хост с ограничениями на ответы. Приоритет сопоставления, записанные ответы CLI, ограничения и проверки идентичности при повторном выполнении описаны в [спецификации протокола и исполняемых примерах](../../../../guide/examples/extensions/README.md).
