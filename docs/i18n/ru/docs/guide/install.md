# Установка Eidos

Четыре пути. Colony устанавливает один файл, `eidos-linux`, который и есть вся
программа. Набор релиза, пакет Arch и сборка из исходников дают `eidos` (командную
строку), `eidos-gui` и статическую вспомогательную программу предпросмотра NIF
`eidos-nif-preview` по отдельности. Пакет Arch и сборка из исходников
дополнительно ставят `eidos-fuse` и `eidos-launch`, два низкоуровневых CLI.
Любой путь может зарегистрировать обработчик `nxm://`, благодаря которому кнопка
«Mod Manager Download» на Nexus направляет загрузку в вашу инстанцию.

## Что нужно заранее

| Требование | Зачем |
|---|---|
| Linux с FUSE | `fusermount3` в PATH. Его поставляет любой современный дистрибутив. |
| Игра под Proton, запущенная хотя бы раз | Steam создаёт Wine-префикс игры только при первом запуске, а Eidos работает внутри него. Eidos также находит копии Skyrim Special Edition из GOG и Epic, копии Fallout 3 и Fallout: New Vegas из Epic и копию Stardew Valley из GOG. Они запускаются через Heroic или Legendary, где Eidos служит обёрткой игры: см. [usage.md](usage.md#запуск-игры). |
| Бинарный файл 7-Zip: `7z`, `7zz` или `7za` | Для установки архивов модов. `7zip` в Arch, `p7zip` в большинстве других дистрибутивов. |
| `par2` (необязательно) | Данные для восстановления PAR2 для резервных копий `eidos pack`. `par2cmdline` в Arch и Fedora, `par2` в Debian и Ubuntu. |

Ни root, ни демона, ни правки `/etc/fuse.conf`, ни добавления в группы. Eidos
монтирует в приватном пространстве имён, принадлежащем процессу игры.

Некоторые системные настройки проявляются только вылетами. Вкладка Diagnostics
проверяет `vm.max_map_count` (1048576 или больше), жёсткий лимит открытых файлов
(524288 или больше) и то, не лежат ли игра, её префикс или инстанция на NTFS,
exFAT или FAT; исправление для каждого случая есть в
[troubleshooting.md](troubleshooting.md#система).

## Через Colony

Найдите Eidos в [Colony](https://github.com/Project-Colony/Colony) и установите
его; обновления приходят через лаунчер. Colony держит один файл,
`~/.local/share/Colony/apps/Eidos/eidos-linux`. Запустите его, и откроется окно.
Вызванный через ссылку с именем `eidos`, тот же файл становится командной
строкой. Положите такую ссылку в свой `PATH` и зарегистрируйте обработчик
загрузок Nexus:

```bash
mkdir -p ~/.local/bin
ln -s ~/.local/share/Colony/apps/Eidos/eidos-linux ~/.local/bin/eidos
eidos nxm --register    # the site's Mod Manager Download button now reaches Eidos
```

Окну ссылка не нужна: всякий раз, когда оно запускает игру или инструмент, оно
запускает собственный файл как CLI. Предпросмотру моделей NIF нужен
`eidos-nif-preview`, который есть только в наборе релиза, пакете Arch и сборках из
исходников; без него предпросмотр сообщает об этом, и больше ничего не
затрагивается. В `eidos-linux` также нет ни одной из сред выполнения Microsoft,
которые поставляет набор релиза ([ниже](#среды-выполнения-microsoft-в-наборе)):
когда инструменту нужна такая среда, Eidos скачивает её с сайта Microsoft, как
только вы запускаете установку prerequisites. Указывайте Steam на сам файл, как
описано ниже.

## Набор релиза

Скачайте `eidos-linux-bundle.tar.gz` и его `.sig`, `.meta` и `.meta.sig` из
[последнего релиза](https://github.com/Project-Colony/Eidos/releases/latest)
и проверьте их, как показано в разделе README
[Политика подписи кода](../../README.md#политика-подписи-кода). В наборе лежат
`eidos`, `eidos-gui` и `eidos-nif-preview` на верхнем уровне, а также
`install.sh`, `README.md`, `LICENSE`, `SECURITY.md`, значки в `assets/brand/png`,
уведомления о сторонних компонентах в `licenses/` (nifly, omod, microsoft-directx,
microsoft-runtimes и крейты Rust) и папка `runtimes/`, описанная ниже. `eidos-fuse`
и `eidos-launch` в наборе нет. Затем:

```bash
tar xzf eidos-linux-bundle.tar.gz
cd eidos-linux-bundle
./install.sh
```

`install.sh` копирует бинарные файлы в `~/.local/bin` или в `$XDG_BIN_HOME`, если
он задан. `--system` кладёт их в `/usr/local/bin` через sudo, `--bindir DIR` -
куда угодно, а `--from DIR` берёт бинарные файлы из другого каталога. Скрипт
также:

- регистрирует обработчик `nxm://`, запуская `eidos nxm --register`, так что шаг
  регистрации из раздела про Colony не нужен;
- пишет `~/.local/share/applications/eidos.desktop` и значки Eidos в
  `~/.local/share/icons/hicolor`;
- копирует уведомления о лицензиях в `~/.local/share/licenses/eidos`
  (`/usr/local/share/licenses/eidos` с `--system`);
- копирует `runtimes/` в `~/.local/share/Colony/Eidos/runtimes`, в том числе с
  `--system`, так что среды принадлежат пользователю, который запустил скрипт;
- в конце печатает параметр запуска Steam с абсолютным путём к `eidos-gui`,
  который он установил.

`--cap` просит sudo выдать `CAP_SYS_ADMIN` установленному `eidos` (см. FUSE
passthrough ниже). `--no-cap` действует по умолчанию и оставляет работу без
root. Повторный запуск скрипта - штатный способ обновления. Набору и
`eidos-linux` нужен Linux x86_64 с glibc 2.39 или новее.

### Среды выполнения Microsoft в наборе

В папке `runtimes/` набора лежат файлы Microsoft, которые просят инструменты:
`VC_redist.x86.exe` и `VC_redist.x64.exe` (Visual C++ 2015-2022, prerequisite
`vcrun2022`), `windowsdesktop-runtime-8.0.12-win-x64.exe` (среда .NET 8 Desktop
Runtime, для `dotnet8` и `dotnetdesktop8`) и `dotnet-runtime-10.0.10-win-x64.zip`
(среда .NET 10, для `dotnet10`). Eidos сам запускает установщики Visual C++ и
.NET 8 в префиксе игры, без winetricks, а zip с .NET 10 распаковывает один раз в
`~/.local/share/Colony/Eidos/runtimes`, где его делят все инстанции (78 МБ в
распакованном виде). Каждый файл используется только тогда, когда его SHA-256
совпадает с зафиксированным в Eidos. .NET 10 SDK, нужный Synthesis (`dotnetsdk10`,
около 300 МБ), в набор не входит и всегда скачивается.

Распакованный набор также работает на месте: после папки данных выше Eidos ищет
`runtimes/` рядом со своим бинарным файлом.

## Arch

```bash
cd packaging && makepkg -si
```

PKGBUILD собирает текущую ветку `main` из исходников. Он ставит `eidos`,
`eidos-gui`, `eidos-nif-preview`, `eidos-fuse` и `eidos-launch` в `/usr/bin`, с
общесистемным обработчиком `nxm://`, записью рабочего стола и значками. Он зависит
от `fuse3`, `7zip` и `xdg-utils`. Папки `runtimes/` в нём нет, поэтому среды
Microsoft скачиваются, когда они нужны инструменту. `winetricks` необязателен:
Eidos по-прежнему использует его для prerequisites, которые не ставит сам,
например `dotnet48` и `xact`.

## Из исходников

```bash
git clone https://github.com/Project-Colony/Eidos && cd Eidos
just build
just install
```

Для сборки из исходников нужны Rust 1.92 или новее, `just`, CMake 3.20+,
компилятор C++17 и Python 3 для тестов нативной вспомогательной программы.
`just build` собирает весь workspace, так что `eidos-fuse` и `eidos-launch`
собираются тоже, а `just install` запускает `packaging/install.sh` на результате
сборки и копирует их вместе с остальным. Команды без `just` приведены в
[инструкции для нативной вспомогательной программы](../../../../../crates/eidos-nif-preview/README.md):
соберите Rust командой `cargo build --release --locked`, скопируйте
вспомогательную программу в `target/release`, затем запустите
`packaging/install.sh --from target/release`. В сборке из исходников тоже нет
папки `runtimes/`, поэтому среды Microsoft скачиваются, когда они нужны
инструменту.

Профиль release использует один codegen unit, fat LTO и вырезанные символы. С
rustc 1.99.1 и 3 задачами сборки холодная сборка `eidos` и `eidos-gui` заняла
334 с против 243 с с thin LTO и дала `eidos` в 20,9 МБ и `eidos-gui` в 49,7 МБ.
Каждый бинарный файл встраивает восемь DLL DirectX, хранящихся в сжатом gzip виде:
7,9 МБ вместо 17,9 МБ. `just profile=dev build` собирает без оптимизации.

## Затем: указать на него Steam

Eidos запускается *как* команда запуска вашей игры - именно так он успевает
смонтировать вид до её старта. В Steam: правый клик по игре -> Свойства ->
Параметры запуска, и введите абсолютный путь к окну Eidos, а за ним `%command%`:

```
~/.local/bin/eidos-gui %command%
```

Используйте абсолютный путь - Steam не читает `PATH` вашей оболочки. Путь зависит
от способа установки Eidos, а `install.sh` печатает строку для каталога, который
он использовал:

| Установка | Параметр запуска |
|---|---|
| Набор релиза или `just install` | `~/.local/bin/eidos-gui %command%` |
| `install.sh --system` | `/usr/local/bin/eidos-gui %command%` |
| Пакет Arch | `/usr/bin/eidos-gui %command%` |
| Colony | `~/.local/share/Colony/apps/Eidos/eidos-linux %command%` |

Нажмите «Играть». Eidos откроется на инстанции этой игры; ставьте моды,
сортируйте через LOOT, жмите Run. При выходе монтирование исчезает вместе с
игрой, а установка остаётся ровно такой, какой была.

Игра всегда запускается через свой магазин. В окне, которое вы открыли сами, Run
выполняет `steam -applaunch <appid>`, Steam запускает Eidos через параметр
запуска, и открывается второе окно Eidos, где вы нажимаете Run. Пока параметр
запуска не запускает Eidos, Run ничего не стартует, а строка состояния показывает
строку, которую нужно задать. При включённом Start the game at once when a store
opens Eidos (Preferences, General, Running a game; по умолчанию выключено) Play в
Steam запускает игру без окна, если Health не показывает проблем. Heroic и
Legendary работают так же через свою настройку обёртки; подробности в
[usage.md](usage.md#запуск-игры).

Вкладка Diagnostics проверяет эту строку. Карточка Health показывает строку,
которую нужно задать, когда параметр запуска пуст, не называет бинарный файл
Eidos, указывает на несуществующий файл, не содержит `%command%` после Eidos или
запускает другую копию Eidos, не ту, что работает.

### Если вы предпочитаете терминал

```sh
eidos init skyrimse               # создать инстанцию (укажите папку, чтобы сделать её портативной)
eidos install skyrimse mod.7z     # моды Simple / FOMOD / BAIN / root
eidos sort skyrimse               # отсортировать порядок загрузки через LOOT
eidos check skyrimse              # проверки Health, не требующие окна
eidos play skyrimse -- %command%  # запустить что угодно через объединённый вид
eidos shell skyrimse              # оболочка в объединённом виде, записи попадают в Overwrite
```

Любая команда, принимающая идентификатор игры, принимает и папку портативной
инстанции - см. [usage.md](usage.md#инстанции-глобальные-и-портативные). Полная
экскурсия в [usage.md](usage.md).

## Обновление

Colony обновляет `eidos-linux` через свой лаунчер. Для набора релиза запустите
`install.sh` нового набора; для пакета Arch снова выполните `makepkg -si`; для
сборки из исходников сделайте pull и запустите `just install`. Окно при старте
спрашивает у GitHub последний релиз, не чаще раза в сутки, и когда вышел более
новый, показывает ссылку на его заметки о выпуске после Help в строке меню. Оно
никогда не скачивает и не заменяет себя. Preferences, About, Version отключает
проверку, автономный режим её пропускает, а копия, установленная в `/usr` (пакет
Arch), никогда не спрашивает, потому что её обновляет менеджер пакетов.

## Необязательно: FUSE passthrough

`sudo setcap cap_sys_admin+ep "$(command -v eidos)"` предоставляет необязательную
возможность; passthrough она не включает. `./install.sh --cap` и `just setcap`
выдают её тому `eidos`, который они устанавливают или собирают. На `nosuid`-монтировании
ядро игнорирует файловые возможности, поэтому `install.sh` пропускает выдачу с
предупреждением, а `just setcap` останавливается с ошибкой. Возможность ставится на
отдельный бинарный файл `eidos` из набора релиза, пакета Arch или сборки из
исходников и никогда не ставится на `eidos-linux`, который также является окном
([SECURITY.md](../../../../../SECURITY.md)). Пересобранный или переустановленный
бинарный файл - это новый файл без возможности, так что если вы ею пользуетесь,
выдавайте её заново после каждого обновления.

`EIDOS_FUSE_PASSTHROUGH=1` - отдельный переключатель времени выполнения, и по
умолчанию он выключен. При включённом passthrough прежняя версия демона мешала
Skyrim SE загружать содержимое любых модов. Наиболее вероятная причина в том, что
она регистрировала новый файл-основу при каждом открытии, а ядро принимает только
один на inode. Теперь демон делит один между всеми открытиями файла через
passthrough, но в игре это ещё не измерено заново. До тех пор включайте
passthrough только для проверки. Измерения и причина описаны в
[troubleshooting.md](troubleshooting.md).
