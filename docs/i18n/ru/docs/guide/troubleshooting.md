# Диагностика и устранение неполадок

Переключатели окружения, чтение счётчиков операций, карточки Health во вкладке
Diagnostics, поиск мода, из-за которого игра падает, что приложить к отчёту об
ошибке и известные проблемы с их историей.

## Диагностика VFS

Две переменные окружения закрывают большинство случаев, когда игра видит нечто, с
чем файловая система не согласна:

```sh
EIDOS_FUSE_STATS=1                  # счётчики операций, выводятся при размонтировании
EIDOS_FUSE_NO_CACHE=1               # все кеши со стороны ядра выключены
EIDOS_FUSE_NO_CACHE=attr,neg,keep,dir   # или назвать их поимённо
```

Именно поимённая форма нашла вылет из-за `FOPEN_KEEP_CACHE` в разделе «Известные
проблемы»: выключить все четыре - это ответ на вопрос «дело в кешировании?», а
назвать их поимённо - ответ на вопрос «в каком именно». Счётчики отвечают на
другую половину. При включённом passthrough (по умолчанию он выключен) загрузка,
показывающая `read 0`, - это загрузка, где `FUSE_PASSTHROUGH` отдал каждый байт в
ядре, а значит всё, что вы собирались настраивать на пути чтения, уже бесплатно.

Ещё несколько переключателей сужают поиск дальше:

```sh
EIDOS_FUSE_TRACE=open,opendir       # писать в журнал каждый open / opendir (1 = все каналы)
EIDOS_FUSE_THREADS=1                # один поток демона (по умолчанию: число ядер CPU, но не больше 4)
EIDOS_FUSE_OPENDIR=1                # держать дескрипторы opendir, даже когда ядро может их пропустить
EIDOS_NO_INDEX=1                    # обходить слои вместо индекса слоёв
EIDOS_NO_OW_INDEX=1                 # то же для индекса состава Overwrite
EIDOS_FUSE_KEEP_CACHE=1             # FOPEN_KEEP_CACHE снова включён, см. Известные проблемы
```

Для запуска через Steam поставьте их перед командой в параметре запуска,
например `EIDOS_FUSE_STATS=1 ~/.local/bin/eidos-gui %command%`. Вывод идёт в
журнал запуска: в `logs/run-*.log` инстанции при запуске из окна, в консоль Steam
при запуске через Steam.

Чтобы посмотреть на сам объединённый вид, `eidos shell <instance>` открывает
оболочку в папке игры так, как её видит игра, а
`eidos shell <instance> -- ls Data/meshes` выполняет там одну команду; всё
записанное попадает в Overwrite
([usage.md](usage.md#оболочка-в-объединённом-виде)). Кнопка Save tree во
вкладке Data записывает всё дерево объединённой `Data` в текстовый файл, по файлу
на строку, с указанием мода, из которого он взят; домашняя папка при этом скрыта.

## Смонтировать объединение вручную

`eidos-fuse` входит в пакет Arch и в сборки из исходников: его собирает
`just build`, а `just install` или `install.sh` копируют его, когда он есть. В
набор релиза и в `eidos-linux` он не входит. Строка использования:

```
eidos-fuse --layer <dir> [--layer <dir> ...] [--overwrite <dir>] <mountpoint>
```

Первый `--layer` побеждает в конфликте; последний - ваши нетронутые данные игры.
Монтированию нужны только `/dev/fuse` и `fusermount3` (ни overlayfs, ни Wine):

```sh
eidos-fuse --layer mod_b --layer mod_a --layer game_data /mnt/point
# ... читайте и пишите через /mnt/point ...
fusermount3 -u /mnt/point
```

Записи попадают в `--overwrite <dir>` (временный каталог, если не указано), так что
сами слои остаются нетронутыми даже здесь.

## Почему passthrough выключен по умолчанию

Passthrough передаёт ядру настоящий файл-основу, так что чтения полностью минуют
этот демон. Измерение A/B ниже сделано с прежней версией демона, до изменения,
описанного дальше в известной проблеме «FUSE passthrough не даёт игре загрузить
содержимое модов». Это изменение обходит наиболее вероятную причину, но в игре
ещё не измерено заново, поэтому passthrough по умолчанию остаётся выключенным,
пока этого не сделают. Измерено A/B на Skyrim SE 1.6.1170, proton-cachyos 11.0,
ядро 7.1.4, один и тот же порядок загрузки из 82 плагинов; единственная
переменная - несёт ли двоичный файл эту возможность:

| passthrough | отказы `NtCreateFile` со `STATUS_ACCESS_VIOLATION` |
|-------------|-----------------------------------------------------|
| включён     | 152 - 75 `.bsa`, 65 `.esl`, 10 `.esm`, 2 `.esp`    |
| выключен    | 0                                                   |

С включённым игра не открывала ни одного своего архива и плагина, что
проявлялось в игре как моды, которых нет: ни ошибки, ни строчки в журнале. С
выключенным тот же порядок загрузки доходил до игрового процесса с живыми
плагинами, архивами и скриптами Papyrus.

Отказ был невидим изнутри демона: собственный `open` демона был успешен каждый
раз, и ядро ни разу не отказало в файле-основе (проверено на целой провальной
сессии с `EIDOS_FUSE_TRACE=open`: ноль `open FAILED`, ноль `passthrough refused`).
Ошибка возникала после того, как демон ответил `opened_passthrough`, поэтому
никакое журналирование со стороны демона не могло её увидеть. Она и не зависела
от расширения - била одинаково по архивам и плагинам, то есть по файлам, которые
игра держит открытыми весь свой запуск.

`EIDOS_FUSE_PASSTHROUGH=1` включает его обратно, чтобы измерить выгоду или
перепроверить механизм. Предупреждения о возможности в лаунчере и во вкладке
Diagnostics появляются только тогда, когда вы её запросили.

## Действительно ли используется индекс слоёв?

`LayerStack::new` строит либо полную карту слоёв только для чтения, либо
никакой. Без карты каждый запрос обходит слои, как прежде: ответы те же,
загрузка сохранения идёт примерно в три раза дольше, а больше ничего не меняется
внешне.

Когда индекс выключен, монтирование один раз при старте сообщает причину:

```
eidos-fuse: layer index off (<reason>); every lookup walks all layers
```

Причина называет нечитаемый каталог, слой глубже 64 каталогов, больше 4 000 000
записей или `EIDOS_NO_INDEX`. Строка попадает в журнал запуска: в
`logs/run-*.log` инстанции при запуске из окна, в консоль Steam при запуске через
Steam. С `EIDOS_FUSE_STATS=1` в отчёте при размонтировании есть и строка
`layer index:`, а ненулевой счётчик `unindexed` при обычном монтировании значит,
что индекс был выключен.

Примеры ниже проверяют то же самое офлайн, на папках инстанции, без
монтирования:

```sh
cargo run --release -p eidos-core --example index_health -- <mods-dir> <overwrite-dir>
cargo run --release -p eidos-core --example index_agrees -- <mods-dir> <overwrite-dir>
cargo run --release -p eidos-core --example listing_cost -- <mods-dir> <overwrite-dir>
```

`index_health` разрешает настоящие пути с индексом и без и сравнивает обходы
каталогов. `index_agrees` проверяет, что оба отвечают ОДНО И ТО ЖЕ, на каждом пути и
каждом листинге реальной инстанции. `listing_cost` измеряет, что карта объединённых
потомков экономит на `readdir`.

`EIDOS_NO_INDEX=1` принудительно включает обход - на случай, когда отлаживается
именно разница между двумя ответами.

## Запуск игры через CLI

Чтобы запускать игру через CLI `eidos`, а не через окно, задайте в её параметре
запуска Steam абсолютный путь к `eidos`, например:

```
~/.local/bin/eidos play skyrimse -- %command%
```

Префикс `WINEDLLOVERRIDES` не нужен. Когда включённый мод импортирует
`d3dcompiler_47`, Eidos разворачивает в префиксе свою встроенную копию,
принудительно делает её родной (native) и сливает это с любыми переопределениями
DLL, которые поставляет мод (загрузчики ENB/ReShade/`.asi`).

Eidos никогда не запускает игру через Proton сам.
`eidos tool <instance> run <title>` с записью, которая запускает игру (загрузчик
расширителя скриптов, лаунчер или бинарный файл игры), просит магазин, которому
принадлежит копия, запустить её, как это делает Run в окне, которое не открывал
магазин, и печатает, что нужно задать, если настройка магазина не запускает
Eidos. `--print` печатает команду магазина вместо её выполнения.

## Игра или инструмент, которые не закрываются

Пока игра или инструмент работает, кнопка Run становится кнопкой Stop, и на
карточке блокировки тоже есть кнопка Stop. Нажмите её дважды. Второе нажатие
завершает все программы, запущенные этим запуском: сначала SIGTERM, затем через
10 секунд SIGKILL для всего, что осталось. Всё, что игра не сохранила, теряется.
Затем Eidos делает то же, что после любого выхода: изменения INI и плагинов
возвращаются в профиль, вывод инструментов записывается, а моды отмонтируются.
Запуск записывается с кодом выхода 143, что бы ни вернула программа, поэтому
`eidos sessions <instance> diff` никогда не принимает его за последний удачный.
Unlock работает иначе: он возвращает окно и оставляет программу запущенной. Из
терминала `kill <pid>` для процесса `eidos` (pid указан на карточке блокировки)
делает то же, что Stop.

## Что сломалось

Чтобы найти, какое изменение сломало игру:

- `eidos sessions <instance> diff` перечисляет, что изменилось с последнего
  запуска игры, завершившегося с кодом 0: моды, версии, порядок плагинов, INI и
  исполняемый файл игры
  ([usage.md](usage.md#что-изменилось-с-последнего-удачного-запуска)).
- Test run рядом с Run играет с модами профиля, без модов или с выбранными модами
  и нужными им мастерами и направляет всё, что игра пишет, в
  `<instance>/test-run/`. После запуска вы оставляете или выбрасываете каждую
  группу файлов: сохранения, изменения INI, состояние плагинов, вывод в
  Overwrite и журналы ([usage.md](usage.md#тестовые-запуски)).
- Find the mod behind a problem во вкладке Diagnostics выполняет тестовые запуски,
  каждый раз с половиной оставшихся подозреваемых, и спрашивает, случилась ли
  проблема. 200 подозреваемых требуют примерно 8 запусков, а поиск переживает
  закрытие Eidos
  ([usage.md](usage.md#поиск-мода-вызывающего-проблему)).

Остановленный запуск никогда не подставляет в этом поиске ответ Yes заранее,
потому что он записан с кодом выхода 143 (см. выше).

## Карточки Health

Вкладка Diagnostics показывает карточку Health для каждой найденной проблемы, с её
причиной и, у некоторых, кнопкой, которая её исправляет. Карточки параметра
запуска описаны в [install.md](install.md), карточки NVAPI, полноэкранного режима
и ENB - в [graphics.md](graphics.md), а карточки Proton и префикса - в следующем
разделе. `eidos check <instance>` печатает находки, которым окно не нужно
([usage.md](usage.md#проверки-health-из-терминала) перечисляет их), среди них
карточки префикса, реестра и диска `S:`. Только окно показывает карточку Proton с
её вариантами для Flatpak, неизвестной и более старой сборки, порядок патчей,
скрипты расширителя, архивы, которые не загружает ни один плагин, требования
Nexus, устаревшие копии плагинов и карточку Display.

### Система

- «vm.max_map_count is <value>» появляется при значении ниже 1048576, которое
  стоит по умолчанию в Arch Linux, Fedora 39 и новее и Ubuntu 24.04 и новее.
  Некоторые игры под Proton отображают больше областей памяти и тогда падают без
  ошибки. Запишите `vm.max_map_count = 1048576` в файл в `/etc/sysctl.d`,
  например `80-gamecompatibility.conf`, затем выполните `sudo sysctl --system`.
- «The open files limit is <value>» появляется, когда жёсткий лимит ниже 524288,
  который нужен esync в Proton; ниже него игры могут не запускаться или падать.
  systemd 240 и новее задают его. В более старой системе задайте
  `DefaultLimitNOFILE=524288` в `/etc/systemd/system.conf` и
  `/etc/systemd/user.conf`, затем войдите заново.
- «Game files on a Windows file system» называет папку игры, префикс или корень
  инстанции, когда они лежат на `ntfs`, `ntfs3`, `fuseblk` (ntfs-3g, exfat-fuse),
  `exfat` или `vfat`. Proton нужны символические ссылки, права Unix и имена с
  учётом регистра. Перенесите игру, её префикс и инстанцию на файловую систему
  Linux, например ext4, btrfs или xfs.

### Файлы игры

Карточка Game files вверху вкладки показывает, запускает ли инстанция установку
из магазина или копию игры внутри инстанции
([usage.md](usage.md#файлы-игры-установка-из-магазина-или-копия)). Запуски
отклоняются, с карточкой, объясняющей причину, в трёх случаях:

- «The game copy '<folder>' is missing»: инстанция работает с копией, которой
  больше нет. Верните её на место или вернитесь к версии из магазина.
- «'<folder>' has no <binary>»: в папке, с которой работает инстанция, нет
  исполняемого файла игры, значит это не копия игры.
- «<game> cannot run from a copy yet»: Morrowind и Oblivion с
  `bUseMyGamesDirectory=0` хранят список плагинов в папке игры.

«ModOrganizer.ini points tools at another game folder» появляется, когда в
собственном `ModOrganizer.ini` списка, не записанном Eidos, есть `gamePath`,
отличный от файлов игры, с которыми работает инстанция. Инструменты в режиме
Mod Organizer 2, такие как PGPatcher, читают игру оттуда. Измените `gamePath` в
этом файле или удалите файл, чтобы Eidos записал свой.

### Порядок загрузки

- «sTestFile lines make the game ignore plugins.txt» появляется для Fallout 4,
  Fallout 4 VR и Starfield, когда в `Fallout4Custom.ini` или `StarfieldCustom.ini`
  профиля есть строки `sTestFile1` - `sTestFile10` в `[General]`. Пока одна из них
  задана, игра загружает эти плагины, а порядок загрузки, который пишет Eidos, не
  действует. Fix удаляет строки из копии профиля и сохраняет прежний файл как
  `<ini>.pre-fix`.
- Starfield: включённые плагины `.esp` без флага мастера получают карточку,
  потому что Starfield не может отсортировать их среди `.esm` и плагинов с флагом
  мастера и держит часть их записей загруженными всю сессию. Релиз автора в виде
  `.esm` избавляет от обоих проблем.
- Starfield: «Invalid blueprint plugins» перечисляет плагины, у которых есть
  часть флагов blueprint, но не все, имя, начинающееся с `BlueprintShips-`, и
  расширение `.esm`. «Blueprint plugins without their main plugin» перечисляет те,
  чей главный плагин не включён: `BlueprintShips-Example.esm` нужен `Example.esm`,
  `.esp` или `.esl`.
- «<patch> loses <n> file(s) to <master>» появляется, когда плагину из одного
  мода нужен мастер из другого мода, а у того другого мода приоритет выше, так что
  выигрывают его копии файлов, которые есть у обоих. Патч обычно ставят ниже мода,
  который он патчит, и кнопка Move на карточке ставит его туда. Оставьте порядок,
  если патч должен проигрывать эти файлы.
- «Out-of-date copy of <plugin>» появляется, когда мод содержит очищенную или
  помеченную как лёгкая копию плагина, чей оригинал с тех пор изменился
  (обновление мода или игры). Игра загружает старую копию. Скройте её, затем
  очистите или пометьте новый плагин заново.

### Список модов

- «Order rules of the collection <name> that no longer hold» появляется, когда
  моды установленной коллекции больше не стоят в порядке, которого требуют её
  правила. Restore collection order возвращает на место только моды этой
  коллекции, а Ctrl+Z отменяет это.
- «<mod> requires <mod>, which is not installed» (или «which is disabled»)
  берётся из требований Nexus, которые читает Check for updates. Open on Nexus
  открывает страницу требуемого мода, Download main file скачивает его на премиум-
  аккаунте, а Ignore скрывает требование, которое другой мод уже выполняет.
  Требование DLC - только совет: Eidos ищет плагин с именем DLC.
- «fontconfig.txt names a font library that is missing» (движки Skyrim) называет
  шрифты, которых нет ни в одном слое и ни в одном архиве, и мод, чей
  `Interface/fontconfig.txt` побеждает. Текст в меню может отображаться
  квадратами, пока шрифт не установлен или строка не удалена.
- «BA2 archive stores audio compressed» (Fallout 4 и Fallout 4 VR) считает файлы
  `.wav` и `.xwm`, которые BA2 мода хранит сжатыми. Игра может упасть, когда
  проигрывает их. Перепакуйте архив с несжатым звуком.

### Расширитель скриптов и обновления игры

- «<loader> is not installed» появляется, когда плагины расширителя скриптов
  установлены (в `SKSE/Plugins`, `F4SE/Plugins` и так далее), но загрузчика нет ни
  в одном включённом моде и нет в папке игры. Игра запускается без них.
- «The script extender does not match game version <version>» появляется, когда
  загрузчик установлен, а DLL времени выполнения для запущенной версии игры нет,
  например `skse64_1_6_1170.dll`. Загрузчик останавливается с ошибкой. Обычно это
  следует за обновлением игры. У этой карточки и предыдущей есть кнопка Open the
  download page для сайта расширителя и кнопка Install the downloaded archive,
  которая кладёт загрузчик в папку `Root/` мода.
- «<game> changed since the last clean launch» появляется, когда исполняемый файл
  игры или, для копии Steam, её build id изменились с последнего запуска через
  Eidos, завершившегося без ошибки. Обновление Steam, не менявшее исполняемый
  файл, её не вызывает. Плагины расширителя скриптов, собранные под старую версию,
  могут перестать загружаться, а карточки ниже называют те, что это объявляют.
  Чтобы сохранить версию игры, на которой собран список, заморозьте её в
  инстанции кнопкой Freeze this version на карточке Game files или командой
  `eidos stock-game <instance> freeze --yes` после того, как одна `freeze`
  показала размер: последующие обновления магазина меняют установку из магазина,
  а не копию.
- «<mod> replaces <n> <extender> script(s)» появляется, когда у мода с более
  высоким приоритетом, чем у расширителя скриптов, есть свободные копии `.pex`
  собственных скриптов расширителя. Старая копия ломает объявленные в ней
  функции, а игра не показывает ошибки. Переместите расширитель ниже этого мода
  (кнопка Move на карточке делает это, когда оба - моды) или скройте эти файлы в
  моде. Когда скрипты расширителя лежат свободно в `Data` игры, установите
  расширитель как мод, чтобы его можно было упорядочить. Архивы не проверяются,
  только свободные файлы.

### Вывод инструментов

- «Overwrite/Root holds meshes» (или textures) означает, что инструмент, у
  которого путь к данным указывал на папку игры, записал эти папки туда, где игра
  их никогда не читает. Исправьте путь инструмента, удалите папки и запустите
  инструмент снова. Кнопка Open folder открывает `Overwrite/Root`.
- «BodySlide's GameDataPath is not the game's Data folder» (или
  `OutputDataPath`): см.
  [Инструменты](tools.md#собственные-настройки-инструмента-остаются-его-собственными).

### Крах в последней сессии

«The game crashed in the last session» появляется, когда crash logger записал лог
при последнем запуске. Карточка называет исключение, а также DLL и плагины из
лога, которые устанавливают ваши моды или Overwrite. Считайте их зацепками: мод,
названный в логе краха, часто лишь место, где крах проявился, а не его причина.
Если в логе нет ни одного файла из ваших модов, карточка так и говорит. Open the
log открывает лог, а Copy the log (home path hidden) копирует его со скрытой
домашней папкой.

### Размер окна

Для Skyrim SE, Enderal SE и Fallout 4 карточка Display показывает размер и режим
окна, с которыми профиль запускает игру, и говорит «No window size set for this
profile», когда ни Prefs INI профиля, ни префикс его не задают. Apply записывает
размер и режим в копию профиля и в копию INI SSE Display Tweaks в Overwrite, когда
окно задаёт этот мод ([usage.md](usage.md#диагностика)).

## Какой Proton запускает игру, и сломанный префикс

На вкладке Diagnostics есть карточка Proton: сборка, которую Eidos и Steam
используют для игры, собственная настройка Steam и сборка, которая последней
запускала префикс. Если префикс последним подготовил более новый Proton, чем
выбранный, карточка становится советом, потому что более старый Proton на более
новом префиксе может сбросить его файлы Wine или не запуститься. Выберите в
Steam сборку не старее (Свойства игры, Совместимость) или пересоздайте префикс.

Остальные карточки Proton и префикса:

- «Proton comes from the Flatpak Steam install»: этот Proton держит свою среду
  выполнения и библиотеки steamclient внутри песочницы Flatpak, поэтому запуск
  с хоста может не сработать. Eidos не запускает его через `flatpak run`, что
  поместило бы игру в песочницу, вне объединённого вида. Установите Proton в
  `~/.steam/root/compatibilitytools.d/` и выберите его для игры.
- «Eidos cannot tell which Proton runs this game»: `config.vdf` Steam не называет
  для неё инструмент совместимости, а префикс не записывает ни одной
  установленной сборки. Инструменты не запускаются, пока в Steam не выбран один
  (Свойства игры, Совместимость).
- «<game> has no Proton prefix yet»: запустите игру один раз через Steam, затем
  нажмите F5. Если Steam не создаёт префикс, проверьте, что папка игры в
  `steamapps/compatdata` доступна на запись; пустая папка, принадлежащая root,
  блокирует создание без сообщения.
- «Windows tools cannot find <game>»: запись префикса о пути установки неверна или
  отсутствует, а xEdit, DynDOLOD, Wrye Bash и Creation Kit её читают. Eidos
  запишет верный путь при следующем запуске инструмента.
- «The prefix's S: drive points outside the Steam library»: `S:` не совпадает ни
  с корнем библиотеки, куда Eidos направляет его для инструмента, ни с
  `<library>/steamapps`, куда Steam направляет его для игры. Скорее всего,
  библиотека переехала или префикс пришёл с другой машины. Каждый путь,
  хранящийся в префиксе относительно `S:`, никуда не ведёт, пока следующий запуск
  через Eidos или Steam не направит его снова.
- «<store> installation: started through its store» - карточка копии из GOG или
  Epic. Run просит Heroic или Legendary запустить игру, когда Eidos служит там
  обёрткой игры, а инструменты запускаются со сборкой Wine или Proton, которую
  Heroic записал для этой копии.

Меню File запускает winecfg, regedit, файловый проводник Wine и деинсталлятор в
префиксе игры, с тем Proton, который запускает инструменты игры
([tools.md](tools.md#собственные-программы-wine-в-префиксе-игры)). Их строки
остаются серыми, пока в префиксе нет этих программ.

Кнопка Rebuild prefix на карточке Proton нужна для префикса, который больше не
работает. Нажмите её дважды. Eidos ничего не удаляет: он переименовывает
`steamapps/compatdata/<appid>` в `<appid>.eidos-backup-<date>-<time>` в той же
папке, и Steam создаёт новый префикс при следующем запуске игры из Steam. Он
отказывается, пока префикс использует игра, инструмент или любая программа Wine.
Пока нового префикса нет, Run в окне не может передать игру Steam и вместо этого
показывает параметр запуска, так что нажмите Play в Steam. Сохранения и
настройки, которые есть только в старом префиксе, остаются в переименованной
папке: скопируйте обратно то, что нужно, и удалите эту папку сами, когда она
станет не нужна.

## Что приложить к отчёту об ошибке

- Copy report во вкладке Diagnostics копирует версию Eidos, игру, сборку Proton,
  является ли Steam Flatpak, состояние passthrough, тип сессии, дистрибутив, ядро,
  `vm.max_map_count`, лимит открытых файлов, есть ли `/dev/fuse` и `fusermount3`,
  имена переменных запуска и программ-обёрток профиля и каждую карточку Health.
  Ваша домашняя папка показана как `~`, а имя для входа как `<user>`.
  `eidos check <instance>` печатает тот же заголовок в терминале, а `--json`
  выдаёт его как JSON.
- Журнал запуска, `<instance>/logs/run-*.log`, начинается с точной команды,
  которую выполнил Eidos. File, Eidos logs открывает папку собственных журналов
  Eidos, `~/.local/share/Colony/Eidos/logs`.
- Copy the log (home path hidden) на карточке краха копирует лог краха.
- Save tree во вкладке Data сохраняет объединённое дерево `Data` с источником
  каждого файла.

## Известные проблемы

### DLSS или генерация кадров молча ничего не делает

Три отдельные причины, каждая без единого сообщения об ошибке: NVAPI не включён в
параметрах запуска, эксклюзивный полноэкранный режим или устаревший лимит FPS у
Reflex. Полный список - в [graphics.md](graphics.md).

### Run ничего не делает с Flatpak Steam

В окне, которое не открывал магазин, Run просит Steam запустить игру командой
`steam -applaunch <appid>`. Flatpak Steam не кладёт `steam` в `PATH` хоста,
поэтому строка состояния говорит «Could not start Steam» с текстом ошибки.
Нажмите вместо этого Play в Steam.

### Сохранение с другого устройства не появляется

Сохранение, которое попадает в префикс, минуя Eidos, например загрузка Steam Cloud
с Steam Deck, остаётся скрытым, пока сохранения профиля смонтированы. Ничто его не
удаляет. Вкладка Saves считает такие сохранения под своим заголовком, а Import
копирует их в профиль, не заменяя сохранение профиля
([usage.md](usage.md#сохранения-принадлежат-профилю)).

### Мод, который пишет один каталог двумя способами, терял всё под вторым

Исправлено. ext4 различает `meshes/` и `Meshes/`; объединённый вид не должен, а
реальные моды поставляют оба: у XP32 Maximum Skeleton анимации и файл поведения
FNIS лежат под написанием с большой буквы, а `character assets` - под другим.

Резолвер брал точное совпадение по регистру для каждого компонента пути и держался
за него: он входил в `meshes/`, не находил там остаток пути и бросал ВЕСЬ СЛОЙ.
Каждый файл под другим написанием был невидим для игры - ни ошибки, ни журнала,
ничего ни в одной диагностике. На реальной инстанции из 50 слоёв это было 74 файла.

Совпавший компонент теперь кандидат, а не решение; точный регистр по-прежнему
пробуется первым, и лишь когда остаток под ним не находится, обход ищет соседей,
равных с точностью до регистра. У листингов был тот же изъян каталогом выше, и
теперь они читают каждый такой каталог в каждом слое.

Индекс путей этой ошибки никогда не имел, потому что обходит каждый найденный
каталог. Поэтому какое-то время индекс возвращал файлы, которых не находил запасной
путь, хотя именно запасной путь должен быть ответом, который никогда не ошибается.

### LODGen от DynDOLOD умирает, оставляя пустой журнал

Исправлено с помощью `dotnet10`; см. [tools.md](tools.md). `LODGen_SSE_<world>_log.txt`
каждого мира содержит баннер версии, строку `.NET Version:` и больше ничего, а
диалог говорит лишь «failed to generate object LOD for one or more worlds».
Причина - Mono из Wine, отвечающий вместо .NET Framework, и никакая установка
.NET Framework этого не лечит: Proton заменяет `mscoree.dll` символической ссылкой
в собственное дерево при каждом обновлении префикса. Набор релиза поставляет среду
выполнения .NET 10; в остальных установках её скачивают один раз.

### Wine не мог понять, что монтирование сворачивает регистр

Исправлено.

`get_dir_case_sensitivity` в Wine сначала спрашивает каталог через
`FS_IOC_GETFLAGS`, затем вынюхивает маркер, который CIOPFS оставляет в
обслуживаемых им каталогах. Если нет ни того, ни другого, Wine считает файловую
систему регистроЗАВИСИМОЙ, и каждый поиск, чьё написание не совпадает побайтно,
откатывается к чтению ЦЕЛОГО каталога ради регистронезависимого совпадения. Игры
Bethesda запрашивают `data/ccbgssse001-fish.bsa`, тогда как файл называется
`ccBGSSSE001-Fish.bsa`, так что это срабатывало почти на каждом ресурсе: 4471
проба маркера и 2236 полных перечитываний каталога за восемь секунд и 195796
перечислений `Data` за девяносто. Skyrim SE так и не доходил до главного меню -
он сидел на 240 МБ резидентной памяти, пока демон сжигал 92 % ядра.

Eidos сворачивал регистр в `resolve_read` с самого начала. Вся цена была в том,
что он никогда об этом не говорил. Теперь `lookup` отвечает `.ciopfs`; `readdir`
по-прежнему его не перечисляет. `ioctl` также отвечает на `FS_IOC_GETFLAGS` для
каталогов флагом casefold, который нынешний Wine запрашивает до поиска маркера.

Две вещи сделали это смертельным, а не просто медленным. Цена растёт с размером
каталога, так что установка контента Anniversary (`Data` с 37 файлов до 177)
перевесила чашу. И `opendir` жадно строил объединённый листинг, что чистая трата,
когда Wine открывает каталог лишь ради `stat` того маркера внутри: теперь снимок
делается при первом `readdir`.

После: главное меню, 2,1 ГБ резидентной памяти, демон на 0 % CPU.

`EIDOS_FUSE_TRACE=opendir` - это то, что его нашло, и оно поставляется. Счётчики
операций говорят «сколько»; 195796 перечислений одного каталога в общей сумме
невидимы.

### Игра переписала `plugins.txt` пустым

Очень похоже, что причина та же, что с регистром выше: `Data`, который игра не
могла перечислить за разумное время, откуда вывод, что там ничего нет, и
сохранение этого вывода. Не доказано и стоит перепроверки. В любом случае защита
захвата (захват, полностью очищающий активный набор, отклоняется при любом
размере) означает, что повредить профиль это больше не может.

### `FOPEN_KEEP_CACHE` выключен

Исправлено. Он ронял Skyrim SE на разыменовании нуля через считаные секунды после
главного меню, детерминированно, без единого установленного мода; остальные три
кеша со стороны ядра были отсечены по одному, и значение имел только этот. Эти
замеры шли с включённым `FUSE_PASSTHROUGH`, а ядро завершает с EIO открытие через
passthrough, которое несёт `FOPEN_KEEP_CACHE`, так что с этим флагом каждое
открытие через passthrough проваливалось. Возможно, именно эти неудачные
открытия и роняли игру, а сам флаг при выключенном passthrough ни разу не
проверяли. Ответы через passthrough его больше не несут. Его потерю тогда
измерили как бесплатную, но при включённом passthrough демон обслуживает *ноль*
чтений (`EIDOS_FUSE_STATS` сообщал `read 0` за полную загрузку), так что при
passthrough, выключенном по умолчанию, настоящая цена не измерена. Включите
`EIDOS_FUSE_KEEP_CACHE=1`, чтобы проверить его отдельно.

### FUSE passthrough не даёт игре загрузить содержимое модов

Демон теперь обходит наиболее вероятную причину (ниже), но в игре это ещё не
измерено заново, поэтому passthrough по умолчанию остаётся выключенным;
`EIDOS_FUSE_PASSTHROUGH=1` включает его. До этого изменения при включённом
passthrough Skyrim SE не мог открыть 152 своих файла со
`STATUS_ACCESS_VIOLATION`, так что содержимое модов не загружалось, молча.
Измерение и причина, по которой собственные журналы демона показывали чистый
прогон, описаны выше в разделе «Почему passthrough выключен по умолчанию».

Ядро привязывает к каждому inode один файл-основу (`fs/fuse/iomode.c`).
Открытие, которое приносит второй идентификатор файла-основы для inode, у
которого он уже есть, завершается с EIO, как и обычное открытие (без
`FOPEN_PASSTHROUGH`) inode, у которого есть файл-основа. Открытие через
passthrough, которое несёт `FOPEN_KEEP_CACHE`, тоже завершается с EIO. Демон
раньше регистрировал новый идентификатор при каждом открытии, поэтому второе
открытие файла, который игра уже держала открытым, проваливалось. Wine сообщает
EIO как `STATUS_ACCESS_VIOLATION`; это та самая ошибка 152 неудачных открытий.
Это правило взято из исходного кода ядра и совпадает с этими 152 отказами,
поэтому оно и есть наиболее вероятная причина.

Теперь демон регистрирует один файл-основу на inode, общий для всех его открытий
через passthrough, и никогда не ставит `FOPEN_KEEP_CACHE` на открытие через
passthrough. Passthrough касается только открытий только для чтения у файлов из
слоёв игры и модов размером от 1 MiB или с окончанием `.dll`, `.exe` или `.asi`.
Когда у файла уже есть файл-основа, его использует каждое открытие файла только
для чтения, а пока у файла есть обычные открытия, новые читатели тоже получают
обычные открытия. Файл из Overwrite никогда не идёт через passthrough, а
монтирование, которое проецирует временные метки плагинов, вообще его не
использует. Открытие на запись файла, который держат читатели через passthrough,
получает ETXTBSY (в Wine: `STATUS_SHARING_VIOLATION`) до любого copy-up, так что
открытие с `O_TRUNC` не может оставить в Overwrite пустую копию, которая скрыла
бы файл мода.

### Кнопка Mod Manager Download ничего не делает

Preferences, Nexus, Downloads показывает, какая программа получает ссылки
`nxm://`. Карточка Health появляется, когда это не Eidos, программа отсутствует
или не задана никакая. Кнопка Register записывает `eidos-nxm.desktop` и делает его
обработчиком по умолчанию для `x-scheme-handler/nxm`. В терминале то же делает
`eidos nxm --register`.

Если в статусе уже указан Eidos, а кнопка по-прежнему ничего не делает, браузер
мог сохранить прежний выбор. Сотрите сохранённый выбор для ссылок nxm в настройках
браузера, чтобы он спросил снова. Браузер из Flatpak не может запускать программы
хоста сам и передаёт ссылку через портал рабочего стола, который читает
обработчик, зарегистрированный на хосте.
