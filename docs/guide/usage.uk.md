# Користування Eidos

Практичний посібник: CLI, GUI, параметр запуску Steam, збирання з джерельних
кодів і скрипт-доказ концепції. Що робити, коли щось виглядає не так, - див.
[troubleshooting.uk.md](troubleshooting.uk.md).

## Користування (CLI)

```sh
eidos games                       # підтримувані ігри, встановлені тут (як список MO2)
eidos init skyrimse               # створити екземпляр для модів
# ...кидайте кожен мод текою до <instance>/mods/ (глобальний екземпляр лежить
#    у ~/.local/share/eidos/skyrimse; `eidos init` покаже ваш)...
eidos install skyrimse mod.7z     # або встановити завантажений архів (Simple / FOMOD)
eidos import skyrimse <mo2-profile>  # перейняти порядок і стан плагінів наявного профілю MO2
eidos sort skyrimse               # відсортувати порядок завантаження плагінів через LOOT
eidos play skyrimse               # показати, що було б змонтовано
eidos play skyrimse -- <command>  # запустити <command> з модами, змонтованими поверх гри
```

`eidos tool`, `eidos prereqs`, `eidos nexus`, `eidos nxm` і `eidos export`
доповнюють набір; запустіть `eidos` без аргументів, щоб побачити повний список.

### Екземпляри: глобальні та портативні

Кожна команда вище звертається до екземпляра. `skyrimse` називає **глобальний** -
той, що зберігається централізовано в `~/.local/share/eidos/skyrimse` і яким
керує Eidos. Другий різновид - **портативний**: самодостатня тека там, де вам
зручно (другий диск, розділ з іграми), переносна та ізольована, точно як
портативні екземпляри MO2. Скрізь, де команда приймає ідентифікатор гри, вона
приймає й теку портативного екземпляра:

```sh
eidos init skyrimse /mnt/games/EidosSkyrim   # створити там портативний екземпляр
eidos install /mnt/games/EidosSkyrim mod.7z  # кожна команда приймає теку
eidos play /mnt/games/EidosSkyrim -- %command%
```

Тека описує себе сама (її `eidos-instance.ini` називає гру), тож більше нічого не
потрібно - а `EIDOS_INSTANCE=<folder>` у середовищі перенаправляє ідентифікатор
гри на цю теку, що зручно в параметрах запуску Steam. Портативні екземпляри, які
ви створили або відкрили, запам'ятовуються (найновіші першими) у
`~/.config/Colony/Eidos/instances.ini`; вітальний екран GUI перелічує їх для
відкриття одним кліком, запуск зі Steam потрапляє на той, у який ви грали
востаннє, а обробник `nxm://` завантажує саме в нього. Два застереження, які
варто знати: переміщення портативної теки зберігає все, крім записів
інструментів, які ви зареєстрували абсолютними шляхами до старого розташування
(додайте їх наново), а спільний кеш runtime
(`~/.local/share/Colony/Eidos/runtimes/`) навмисно лишається глобальним для
машини - хост .NET на 78 МБ не буває окремим для кожного екземпляра.

Eidos тримає власні файли під `Colony/Eidos` - за розкладкою, якою користується
кожна програма родини Colony: `~/.config/Colony/Eidos/` для того, що ви обрали
(налаштування, ваш сеанс Nexus, ваш список екземплярів, написані вами означення
ігор і додатків), `~/.local/state/Colony/Eidos/logs/` для логів сеансів і
`~/.local/share/Colony/Eidos/` для того, що Eidos завантажив. Старіший Eidos
тримав це в `~/.config/eidos/` і `~/.local/state/eidos/`; перший запуск після
оновлення **копіює** їх туди й повідомляє про це в лозі. Старі каталоги
лишаються точно такими, якими були - нічого не видаляється, тож невдале оновлення
не може коштувати вам входу в акаунт, - і ви можете прибрати їх самі, коли
переконаєтеся, що все гаразд.

Ваші моди до цього не належать. Глобальний екземпляр і далі живе в
`~/.local/share/eidos/<game>/`, а портативний - там, де ви його поклали, бо ці
шляхи вписані у ваш список екземплярів і, можливо, у параметр запуску Steam:
переміщення зламало б зв'язок, обома кінцями якого Eidos не володіє.

Одне місце відхиляється навідріз: **усередині теки встановлення гри** (рефлекс
ветерана MO2). Цим деревом володіє Steam - оновлення, «перевірка цілісності» чи
видалення можуть переписати або стерти його разом з усім вашим налаштуванням, - а
Eidos монтує поверх кореня гри, тож екземпляр там опинився б усередині власної
цілі монтування. Майстер, `eidos init` і `eidos play` однаково кажуть ні; кладіть
теку ПОРУЧ із грою (сусідка на тому самому диску дає ту саму зручність).

`play` монтує моди екземпляра поверх власного каталогу `Data` гри (через
bind-stash, тож демон і далі читає незаймані файли) всередині приватного простору
імен, а тоді запускає команду через цей вигляд. Записи (збереження, перегенеровані
конфіги) потрапляють у шар `overwrite/` екземпляра; інсталяція гри й кожне
джерело мода лишаються незайманими до байта.

### Жодних привілейованих кроків

Eidos працює повністю без root. Він монтує у приватному просторі імен користувача
й монтувань, тож жодного setuid-помічника, жодного демона й нічого, що треба
надавати.

`sudo setcap cap_sys_admin+ep "$(command -v eidos)"` є **необов'язковим** і керує
рівно однією річчю: passthrough FUSE на рівні ядра, який вимкнений типово, бо він
ламає гру (див. нижче). З цією можливістю Eidos бере звичайний простір імен
монтувань замість простору імен користувача; моди розгортаються однаково в обох
випадках.


Чому зникла давня порада про `setcap` - і чому passthrough FUSE постачається
вимкненим - пояснено в
[troubleshooting.uk.md](troubleshooting.uk.md#чому-passthrough-вимкнений-типово).

## GUI

```sh
cargo run -p eidos-gui
```

Майстер першого запуску в стилі MO2 та в пергаментно-бордовому вигляді Colony:
вітання -> тип екземпляра (портативний / глобальний) -> гра -> назва й
розташування -> підсумок -> створення -> головний екран. Вітальний екран також
перелічує кожен відомий наявний екземпляр (глобальні та портативні, останні
використані першими) для відкриття одним кліком - він же й перемикач
екземплярів, - а якщо навести майстра на теку, у якій екземпляр уже є, він
ПЕРЕЙМЕ його як є замість створювати поверх (і відмовиться навідріз, якщо тека
належить іншій грі).

Головне вікно з двома панелями теж збудоване: вибір профілю (перемкнути або
створити новий копіюванням поточного), список модів, який ви фільтруєте,
виділяєте, переставляєте, групуєте роздільниками, звужуєте за категорією та
викликаєте на ньому дії правим клацом, плюс вкладки Data / Plugins / Conflicts /
Overwrite / Saves / Downloads / Diagnostics і кнопка Run із вибором цілі запуску.

Перестановка - це не лише «на самий верх / у самий низ»: точні переміщення MO2
теж тут - відправити вище першого конфліктного мода, нижче останнього, на явний
пріоритет або в групу роздільника. Усі вони проходять через один спільний
помічник переміщення, тож помилка на одиницю, що виникає, коли рядки видаляють
перед повторною вставкою, живе в одному місці, а не в п'яти.

### Стовпці, сортування та групування

Список типово малює чотири стовпці, а пропонує вісім: Category, Content, Version,
Author, Installed, Nexus id, Game, Flags. Позначайте їх у меню View. Типово
ввімкнено не всі вісім, і це навмисно: у списку, де показано кожен стовпець, не
лишається місця для NAME, а саме його ви насправді читаєте.

Клац на будь-якому заголовку сортує за ним. Повторний клац міняє напрям, а третій
повертає до **порядку завантаження**, і це важливіше, ніж звучить: порядок
завантаження - єдиний порядок, у якому список можна перетягувати, бо проміжок для
вставки адресує справжній список, тоді як відсортований рядок перебуває зовсім
деінде. Поки сортування ввімкнене, смуги вставки не малюються, а перетягування
відхиляється замість приземлитися там, куди ніхто не цілився, - так само робить
MO2 і з тієї самої причини. Меню View про це повідомляє й пропонує шлях назад.

Меню View також уміє **групувати** весь список - за категорією або за джерелом (з
Nexus чи встановлено вручну). Заголовки груп - не роздільники: за ними немає
нічого, що можна перейменувати, розфарбувати чи перемістити, вони згортаються, а
лічильник лишається на заголовку у згорнутому стані. Роздільники зникають зі
списку під сортуванням або групуванням - роздільник очолює рядки, що йдуть за ним
у порядку завантаження, а і те, і те їх перемістило.

### Миша й клавіатура

Подвійний клац на моді відкриває Information, Ctrl+подвійний клац - його теку,
Shift+подвійний клац - його сторінку на Nexus. Ctrl+F ставить курсор у поле
фільтра. Набрана літера перестрибує до наступного мода, що з неї починається, а
повторне натискання йде рештою, а не застрягає на першому. Жодне з них не може
приземлитися на рядок, який ховає фільтр, згорнутий роздільник чи згорнута
група, - переміщення підсвітки, якої ви не бачите, і є тим, як наступний Space
перемикає мод, на який ви не дивилися.

«Collapse others» у меню роздільника згортає всі групи, крім цієї. Під час
перетягування затримка над згорнутою групою розгортає її, тож мод можна кинути
всередину, не перериваючи перетягування спершу, - саме затримка, а не побіжний
рух повз.

### Що список каже про мод

Два дорадчі позначники, кожен - гліф із поясненням при наведенні. **No valid game
data** означає, що ніщо у верхівці мода не схоже на те, що ця гра завантажує;
можливо, його теки треба підняти на рівень вище, а можливо, це взагалі не мод для
цієї гри. **Another game** означає, що власний `meta.ini` мода називає іншу.
Жоден із них нічого не блокує - мод усе одно розгортається - а «Mark as valid» у
меню рядка вимикає будь-який із них через власний ключ MO2 `validated=`, тож мод,
за який ви поручилися в одному менеджері, приходить тихим і в інший.

Перевірка розкладки навмисно поблажлива: дерево `Root/` зараховується, нечитабельна
тека зараховується, порожня теж. Хибне попередження у списку з п'ятисот рядків
гірше за пропущене.

### Резервна копія мода, перш ніж його чіпати

«Back up this mod» копіює його теку поруч як `<name>_backup` (потім `_backup2` і
так далі - резервна копія ніколи не заміняє попередню). Копія **інертна**: це не
мод, її прапорець нічого не робить і вона нічого не додає до об'єднаного вигляду,
бо позначити її означало б розгорнути дві копії одного мода одна поверх одної.
«Restore this backup over the mod» повертає її на місце у два кліки; поточний
вміст спершу відсувається вбік і відкидається лише після того, як копіювання
вдалося.

**Data** - це справжнє дерево об'єднаного вигляду, що розгортається на один
рівень за раз, тож відкриття вузла коштує одного читання каталогу на кожен шар,
який його має, а не рекурсивного обходу кожного ввімкненого мода. Його
обслуговує ТОЙ САМИЙ стек шарів, з якого читає монтування, тож whiteout-и та
приховані файли враховуються, і вкладка не може розійтися з тим, що побачить гра.
Фільтруйте за назвою, звужуйте до самих лише спірних файлів, розбирайтеся, що де
лежить, за стовпцями Size і Modified, і показуйте будь-який рядок у файловому
менеджері через Reveal. **Plugins** - це порядок завантаження ESP/ESM/ESL
(перемикайте, переставляйте вручну або сортуйте через LOOT і читайте звіт після
сортування, посилання з порад у якому відкриваються у вашому браузері).
**Conflicts** пояснює переможців і переможених для кожного файлу. **Overwrite**
одним кроком перетворює написане грою на справжній мод. **Saves** розбирає
заголовок кожного збереження - персонаж, рівень, місце, час гри - і порівнює
вбудований у нього список плагінів із вашим поточним, з кнопкою, що вмикає
потрібні йому моди, бо назвати їх і лишити вас із цим наодинці - нудна половина
справи.

«Information...» відкриває діалог для окремого мода: загальне, конфлікти, дерево
файлів, налаштування INI, нотатки. З дерева файлів (і з дерева Data) будь-який
файл можна **приховати** - його буде перейменовано на `<name>.mohidden`, що
прибирає його з віртуального вигляду, не видаляючи, тож три випадкові меші одного
мода можна придушити, не чіпаючи пріоритетів. Дерево файлів робить і звичайні
файлові операції: нова тека, перейменування, видалення, відкриття. Усі вони
проходять через один резолвер, що відхиляє все, що не є простим шляхом усередині
цього мода, - жодних `..`, жодного абсолютного шляху й жодного компонента, який є
симлінком, бо перехід за ним виніс би видалення взагалі за межі теки мода.
Перейменування замінює лише останній компонент, тож ніколи не може стати
переміщенням, і воно відхиляє вже зайняте ім'я замість мовчки замінити той файл.
Видалення потребує двох кліків; це єдина дія тут, яку повторний клац не скасує.

**View** на будь-якому рядку в дереві файлів або в дереві Data показує
попередній перегляд файлу: зображення й текст. Не DDS чи NIF - для них потрібні
блоковий декодер і рендерер, яких у цього дерева немає, - але про це так і
сказано замість порожнього віконця, з підказкою про Reveal. Текст читається до
64 КБ і повідомляє, де зупинився, бо перегляд - це побіжний погляд, а лог Papyrus
може важити сто мегабайтів. **INI Tweaks** перелічує фрагменти, які мод постачає
у своїй теці `INI Tweaks/`; увімкнені зливаються в ігровий INI профілю під час
запуску, у порядку пріоритету, і знімаються, коли INI цього запуску захоплюються,
- інакше твік мовчки став би параметром, а його вимкнення нічого б не змінило.

Завантаження можна **перетягнути зі списку Downloads на позицію в списку модів**,
щоб встановити його з цим пріоритетом; архіви або теки, кинуті на вікно з
файлового менеджера, теж встановлюються (для цієї половини потрібен сеанс X11 або
XWayland - winit реалізує кидання файлів лише для X11). Самі завантаження можна
ставити на паузу й відновлювати: пауза зупиняє передавання й зберігає часткове, а
Resume наново отримує свіже посилання і продовжує з місця зупинки.

Вкладка Downloads - це **бібліотека** архівів, а не черга передавань. Фільтруйте
за назвою (зокрема за дружньою назвою мода, тож «skyui» знайде
`SkyUI_5_2_SE-12604-5-2SE.7z`), сортуйте за новизною, назвою, розміром чи станом
і **ховайте** архів, з яким ви закінчили, - файл лишається, зникає лише рядок,
тож відкласти книжку не означає спалити її. «Show hidden» повертає їх, і та сама
кнопка знімає приховування. «Remove N installed» видаляє архіви модів, які ви вже
встановили, у два кліки, і лише ті, що **на екрані**: фільтр - це і є ваша заява
про те, які саме ви мали на увазі.

### Колекції Nexus

Вставте посилання на колекцію - або клацніть його на сайті - і Eidos перелічить
учасників ревізії, кожного зіставленого з цим екземпляром: встановлено,
завантажено чи бракує. Він **читає** колекцію; він її не встановлює, і панель про
це каже. Чотири речі роблять інсталятор тут не просто складним, а нечесним:
учасники - це звичайні файли Nexus, яким потрібен окремий ключ на файл, що його
поза власною кнопкою сайту може викарбувати лише преміум-акаунт; повне
встановлення - це три виклики API на учасника проти бюджету, який цей клієнт
відмовляється перевитрачати; фази, правила та відтворені відповіді FOMOD із
маніфесту не вдалося перевірити на справжній опублікованій колекції Bethesda, а
вгадування дає порядок завантаження, який виглядає правильним і таким не є.
Читання коштує одного запиту й точне.

Колекцію можна прочитати лише щодо **її власної гри**. Відкрийте колекцію для
Skyrim із завантаженим екземпляром Fallout 4 - і вона відмовиться, назвавши
причину, замість зіставляти учасників із чужим списком модів, де кожне
«встановлено» й кожне «бракує» були б шумом у формі відповіді.

### Автономний режим

**Settings -> Nexus -> Offline** повністю припиняє звертання Eidos до Nexus.
Перевірки оновлень, вхід, завантаження та колекції про це кажуть, замість падати з
помилкою з'єднання. Він вимкнений, доки ви його не ввімкнете, - у файлі
налаштувань, написаному старішим Eidos, такого ключа немає, а прочитати
відсутній як «увімкнено» означало б відрізати мережу всім, хто оновився.

**Preferred servers** ранжує вузли CDN, яким віддає перевагу завантаження, кращі
першими. Більше ніж одне дзеркало на вибір коли-небудь отримує лише
преміум-акаунт, тож для всіх інших обирає Nexus і це нічого не змінює. Це
впорядкування, а не фільтр: якщо сьогодні жодного з названих вами немає в
пропозиції, завантаження все одно відбудеться - з того вузла, який Nexus
запропонував першим.

**Categories** можна редагувати, а не лише переглядати: призначайте їх одному
моду чи цілому виділенню, редагуйте сам каталог із того самого діалогу і тягніть
офіційний список категорій гри з Nexus. Обидва файли каталогу - власні файли MO2
(`categories.dat` і `nexuscatmap.dat`), тож спільний екземпляр має один каталог.

**View -> INI editor** редагує ігрові INI профілю - ту копію, що зберігається, а
не поховану в префіксі Proton, яку переписує кожен запуск. **View -> Log** читає
логи сеансу. **View -> Extensions** перелічує ваші власні додатки; див.
[extensions.uk.md](extensions.uk.md).

Встановлення приймає все: шляхи Simple і FOMOD, плюс пакунки **BAIN** Wrye Bash
(позначайте підпакунки, які зливаються по черзі) і **ручний** вибір, що показує
дерево архіву й дає вказати корінь даних, коли жодна евристика не впізнає
розкладку. Жоден архів не відхиляється.

**Diagnostics** виконує живі перевірки стану: передусім спроможність запуску,
відсутні майстер-файли (найнадійніший провісник вильотів), архіви, яких не
завантажить жоден активний плагін, чи список модів досі відповідає теці модів, і
- після запуску - що власний лог розширювача скриптів каже про кожну з його
DLL-плагінів, а це перетворює «чи завантажилися мої плагіни SKSE?» з припущення
на доказ.

Щоб запускати гру через GUI, вкажіть у параметрі запуску Steam для цієї гри
абсолютний шлях до виконуваного файлу (Steam не бачить `~/.cargo/bin` у PATH):

```
~/.cargo/bin/eidos-gui %command%
```

Eidos відкривається на екземплярі цієї гри - на тому, яким ви користувалися
востаннє, тож портативний екземпляр знаходиться знову так само, як глобальний;
тисніть Run, щоб запустити гру через об'єднаний вигляд. (Кнопка Run показує саме
цей рядок, зі справжнім шляхом до запущеного виконуваного файлу, якщо натиснути
її поза Steam.)

`%command%` від Steam для ігор Bethesda зазвичай указує на `<Game>Launcher.exe`.
Eidos ніколи його не запускає: лаунчер - це окремий застосунок налаштувань, який
перескановує `Data` і переписує `plugins.txt`, скасовуючи щойно розгорнутий
порядок завантаження. Він підставляє завантажувач розширювача скриптів, якщо той
встановлений, інакше - виконуваний файл гри, і повідомляє, коли доводиться
відступати: гра, що стартує з усіма модами SKSE інертними, гірша за ту, що не
стартує.

Давніші інструкції тут нав'язували `WINEDLLOVERRIDES="d3dcompiler_47=n"`. Це
більше не потрібно і ніколи не було цілком правильним: перевизначення на *native*
допомагає лише тоді, коли справжня `d3dcompiler_47.dll` уже є в префіксі. Тепер
Eidos сканує імпорти DLL увімкнених модів, сам розгортає справжню DLL від
Microsoft і лише тоді встановлює перевизначення.

## Спробувати доказ концепції

Гра не потрібна. Він доводить об'єднання + copy-on-write + невтручання + область
дії в межах простору імен, використовуючи лише непривілейований OverlayFS у
просторі імен користувача (Linux >= 5.11):

```sh
./scripts/poc-overlay.sh
```

## Інструменти

xEdit, BodySlide, DynDOLOD і подібні працюють через об'єднаний вигляд усередині
префікса Proton гри:

```sh
eidos tool skyrimse add BodySlide "<path>/CalienteTools/BodySlide/BodySlide.exe"
eidos tool skyrimse run BodySlide
eidos prereqs skyrimse            # що потрібно зареєстрованим інструментам і в якому воно стані
eidos prereqs skyrimse --install  # дістати те, чого бракує
```

Одне варто знати, перш ніж називати інструмент: **назва вирішує, які runtime-DLL
Eidos для нього забезпечить** - `BodySlide` отримає свої бібліотеки DirectX, `BS`
не отримає нічого. У GUI діалог Executables показує справжній стан кожної
передумови під полем, а ті, яких бракує, є кнопками.

Таблиця, три рівні передумов, чому DynDOLOD потребує runtime .NET, який
winetricks не вміє встановити, і чому інструмент, встановлений як мод,
запускається з об'єднаного шляху, а не з власної теки, - у
[tools.uk.md](tools.uk.md).

Збирання з джерельних кодів і розкладка репозиторію - у
[../internals/contributing.md](../internals/contributing.md).

## Розширення

Eidos можна розширювати без перезбирання: маніфест TOML у
`~/.config/Colony/Eidos/addons/` додає інструмент до списку Extensions або
перевірку на вкладку Health. Нічого не завантажується в Eidos - розширення це
програма, яку він запускає. Див. [extensions.uk.md](extensions.uk.md).
