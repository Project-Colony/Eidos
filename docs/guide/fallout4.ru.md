# Fallout 4 через Eidos

Fallout 4 не нужен ни особый параметр запуска, ни переименованный исполняемый файл,
ни скрипт-обёртка. Это стоит сказать прямо, потому что все прочие руководства по
F4SE под Linux утверждают обратное - и их советы ломаются на следующем обновлении
Steam.

## Параметр запуска

```
~/.local/bin/eidos-gui %command%
```

Цель запуска Steam для Fallout 4 - это `Fallout4Launcher.exe`, никогда
`Fallout4.exe`, так что заставить script extender вообще запуститься - на деле
вопрос «как заставить Steam стартовать другую программу». Обычные ответы
переписывают `%command%` на bash:

```
bash -c 'exec "${@/Fallout4Launcher.exe/f4se_loader.exe}"' -- %command%
```

или копируют `f4se_loader.exe` поверх `Fallout4Launcher.exe`, который Steam тихо
восстанавливает при каждом обновлении игры - после чего вы играете без F4SE, и
ничто об этом не сообщает.

Eidos делает подмену сам, исходя из описания игры: он заменяет лаунчер на
`f4se_loader.exe`, когда тот установлен, откатывается на `Fallout4.exe`, когда его
нет, и **говорит вам**, когда пришлось откатиться. Игра, которая стартует со всеми
модами F4SE мёртвыми, хуже игры, которая не стартует вовсе.

Есть и вторая причина никогда не запускать лаунчер: он пересканирует `Data` и
переписывает `plugins.txt`, отменяя только что развёрнутый порядок загрузки. Eidos
его не выполняет никогда.

## Что Eidos берёт на себя

| | |
|---|---|
| Инвалидация архивов | В `Fallout4Custom.ini` попадают `[Archive]` `bInvalidateOlderFiles=1` и пустой `sResourceDataDirsFinal=` - два ключа, без которых свободные файлы вне `Data` вообще не видны. Пишется в профиль, а не в папку игры. |
| Порядок загрузки | `plugins.txt` в формате со звёздочками, который использует Fallout 4 (`*` отмечает активный), с учётом `Fallout4.ccc` для неявных плагинов Creation Club |
| LOOT | Сортировка работает так же, как для Skyrim - `eidos sort <instance>` забирает masterlist `fallout4` |
| Сохранения | Сохранения `.fos` и их косейвы `.f4se` перечисляются, копируются и хранятся по профилям; панель подробностей читает собственную таблицу плагинов сохранения, поэтому сохранение, которому нужен отключённый вами плагин, скажет об этом до загрузки |
| Root-моды | Всё, что мод кладёт рядом с исполняемым файлом (сам F4SE, ENB, `dxvk.conf`), попадает туда через тот же механизм `Root/`, что и в Skyrim |

## Вопрос версий

Fallout 4 уже не та замороженная игра, какой была с 2019 по 2024 год. На август
2026 живых веток три, и DLL мода, собранная под одну, не загрузится на другой:

| Ветка | Версия | F4SE |
|---|---|---|
| Классическая («old-gen») | 1.10.163 | 0.6.23 |
| Next-gen | 1.10.984 | 0.7.2 |
| Anniversary / Creations | 1.11.137 → 1.11.240 | 0.7.4 → 0.7.9 |

Два следствия, которые стоит знать до сборки списка модов:

- **Проверьте, что у вас на самом деле.** Папки `Creations/` и `Mods/` в корне игры
  означают линию 1.11.x. Панель подробностей сохранения в Eidos также показывает
  сборку, которой оно записано - Fallout пишет её в сохранение, а Eidos выводит как
  «Game build».
- **Свежий патч - плохой день для старта.** F4SE обычно выходит через день-два
  после обновления Bethesda, но *Address Library for F4SE Plugins* - через которую
  большинство DLL-модов разрешают свои смещения - идёт по собственному расписанию.
  В промежутке DLL-половина экосистемы лежит. Моды без DLL (текстуры, меши,
  плагины) не затронуты.

Как только сборка заработала, отключите автообновление Steam для Fallout 4
(Свойства → Обновления → «Обновлять эту игру только при запуске»), иначе следующий
патч сломает каждую установленную DLL.

## Замечание по железу: вылеты на обломках оружия у NVIDIA

Эффект обломков оружия в Fallout 4 работает на NVIDIA FleX, производной PhysX,
поддержку которой NVIDIA прекратила после поколения Pascal. На любой карте Turing и
новее - GTX 16, RTX 20 по RTX 50 - он роняет игру. Это баг игры, никак не связанный
с Linux, Proton или Eidos.

Два исправления, годится любое: выключите «Weapon Debris» в настройках игры или
поставьте *Weapon Debris Crash Fix* (Nexus 48078), который отключает столкновения
осколков, а не сам эффект.

## Если что-то выглядит неправильно

Общий список проверок - в [troubleshooting.ru.md](troubleshooting.ru.md); первый
вопрос, специфичный для Fallout, всегда *какой исполняемый файл реально
запустился*. Eidos пишет полную команду запуска в журнал запуска инстанции, поэтому:

```sh
grep '# command:' <instance>/logs/run-*.log | tail -1
```

Если там `f4se_loader.exe`, подмена состоялась. Если там `Fallout4Launcher.exe`,
значит F4SE не установлен там, где Eidos может его найти - его место рядом с
исполняемым файлом игры, что при управляемой сборке означает каталог `Root/`
какого-нибудь мода (или саму папку игры, установленную вручную).
